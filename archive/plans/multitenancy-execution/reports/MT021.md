## 1. 设计要点（新文件 `server/src/enterprise/tenancy/conversations-list.ts`，纯新增）

- **可见性规则 = 个人会话**（父 Spec §5.1「团队成员资格不开放个人文件、会话、连接账号和凭据」）：行必须同时满足 RLS 租户臂（受限 `ob_ent_data` + `app.tenant_id` 先行隐藏跨公司行）→ 行 `workspace_id === scope.workspaceId`（scope 钉死当前团队）→ 行 `principal_id === scope.principalId`（同团队他人会话不可见）→ 事务内重验调用者公司成员资格（active 且 `epoch === scope.memberEpoch`）与团队成员关系 active（MT005 scope-gate 事务等价物切片，MT016 `readMembershipFacts` 同款）。任一不成立 → 不可见。
- **列表/计数/游标只从可见项派生**：候选行按 `(created_at, id)` 全序读取（**不可变键**——`updated_at` 随消息追加前进，不入游标键，中途改名不引起跳过/重复）；keyset 游标 `{v:1, at, id}` 只钉在最后一个可见项上，`LIMIT limit+1` 的第 limit+1 行只用来判断「还有下一页」。隐藏条目不消耗页位、不偏移游标、键大于全部可见项时不制造末页游标（`nextCursor=null`）。
- **详情 = canonical 不可见**（票注：复用 MT011，不自造错误码）：`readVisibleConversation` 的一切拒绝（不存在/跨公司/跨团队/他人会话/被撤权）返回 `notFoundVerdict()` 冻结实例——逐字节同形，测试钉死五类拒绝构成单元素字节集。
- **切团队立即变化**：服务按入参受信 scope 过滤，无进程级「当前团队」状态、无跨调用缓存（MT014 验收 4 同纪律）——同一 actor 的每个新 scope（真实 resolver 按请求选择器铸造）立即得到该团队的事实。
- **事务纪律**与 MT008/MT011/MT016 判定入口完全一致：`assertScopeContext` → `assertTrustedScope` → read committed + lock/statement timeout → `set_config('app.*', …, true)` 事务本地 → advisory 共享锁（键序 tenant → principal → membership → workspace-membership）。读路径全部经受限 data 角色与真实 RLS。
- **输入校验响亮**（错误只含代码，绝不回显值）：`CONVERSATIONS_LIMIT_INVALID`（1..200，缺省 50）、`CONVERSATIONS_CURSOR_INVALID`（opaque 令牌形状）、`CONVERSATION_ID_INVALID`（UUID 形状）——输入形状拒绝，不是存在性信号；不可见语义只有 canonical `RESOURCE_NOT_FOUND` 一种。
- **无迁移**：`enterprise_conversations` 的归属字段（tenant_id + workspace_id + principal_id）与 RLS（`enterprise_conversations_data_scope`，0057 基线）已存在且满足票面 Scope boundary「相关表 RLS」；本票交付的是作用域读面，migrate-test/migration-tool/schema barrel 因此零改动。

## 5. 披露 D1–D6

- **D1 无迁移任务（决策而非遗漏）**：票面 Scope boundary 四项中「归属字段」「相关表 RLS」由 0057 基线满足（tenant/workspace/principal 归属列 + `ob_ent_data` 租户臂 RLS + 列级授权已存在）；「列表与计数查询」「游标稳定性」是纯读面语义，本票以服务模块交付。注册空迁移任务只会徒增迁移链长度，违反最小改动。若后续票需要把个人会话可见性下推为更细 RLS 策略（如 workspace 臂进 RLS），属独立存储票的 schema 变更。
- **D2 夹具种子与两个变异助手的数据通道**：会话行经**受限 data 角色** INSERT（真实 0057 授权 + RLS `withCheck` 租户策略，非 superuser 旁路——每条种子都被 withCheck 验过租户上下文）；仅两个翻页中途变异助手例外：`hardDeleteConversationViaSetup` 走 setup 通道（data 角色无 DELETE 授权——MT011 softDelete 先例），`renameConversationAsData` 走 data 角色（title 在列级授权内）。**判定侧从不使用 setup 通道**：list/count/detail 全部经真实 `verifyDataDatabase` 验证的受限通道。套件收尾 `current_user` 不变量覆盖每条受限查询。
- **D3 变异靶行追加（c10/c11）**：验收 4 describe 的 beforeAll 追加两行到 a1-member 可见集（14→16 行），使交错/中途变异断言拥有专属靶行；追加经同一受限 data 角色种子通道，验收 1 的精确集合断言在其之前运行（bun 文件序），计数语义按「当前作用域全部可见事实」口径（MT016 D3 先例）在验收 4 内重断言（5→删后 4）。
- **D4 epoch 独立可捕获性（预置而非补测）**：suspend 同时改 status 与 epoch，仅移除 epoch 比对无法被暂停态捕获（MT016 MUT2 同形态）——本票在 GREEN 阶段即内置「暂停→恢复（真实 MT007 restore：status 回 active 且 epoch+1）后旧 scope 仍被拒、新 scope 正常」用例，使 MUT4 首轮即被捕获（无先存活后补测环节）。
- **D5 边界（诚实声明）**：(a) 列表/计数候选读取一次扫过 scope 团队内本人的候选行——个人会话可见性是纯归属谓词，已完整下推 SQL WHERE（与 MT011 注册表求值不同，无应用层二次过滤流）；团队规模超出此模型属后续分页架构票。(b) 详情读不持逐会话 advisory 锁——本模块为只读面，无对应的本模块写者，锁族不预支；写路径仍归既有 conversations 服务。(c) 会话详情按会话 UUID 主键定位（票面「会话 ID」）；按 threadId 的既有详情路径（conversations service `authorizedConversation`）不在本票改动面。(d) 本票不接路由：服务面供下游接线票复用（与 MT009/MT011/MT016 装配同例）；列表展示排序（如 updated_at 倒序）属路由/前端职责，视图已携带 created_at/updated_at。(e) 撤权后 resolver 层拒绝码未钉死单一值（真实资格门的既有契约，测试按已知拒绝码集合断言）。
