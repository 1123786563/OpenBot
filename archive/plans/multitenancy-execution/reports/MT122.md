## 2. 测试（21 例，真实 PostgreSQL + RLS，零授权 mock；缺专用库 env 显式 skip）

- AC1：双选择头签发受信 scope；缺 tenant/缺 workspace → `TENANT_REQUIRED`/`WORKSPACE_REQUIRED`；
  跨公司 → `TENANT_FORBIDDEN`；A 选 B 团队 → `WORKSPACE_FORBIDDEN`；中间件显式选择失败 → 拒绝
  （403 + canonical 码）且业务 handler 不达；无上下文消费 `requireEntryBusiness` →
  `ENTRY_CONTEXT_REQUIRED`（中间件放行的无选择头请求消费接缝同样被拒）。
- AC2：A/a1（公司默认模型 gpt-4o）vs A/a2（团队覆盖 gpt-4o-mini）→ 不同 runtimeConfig；同 scope
  两次请求 → 新实例（scope 对象身份亦不同）；无配置行（公司 B）→ `RUNTIME_CONFIG_NOT_FOUND`；
  资格翻转（active→suspended）→ 下一次 `business.transaction` 即 `WORKSPACE_REVOKED`，恢复后重验通过。
- AC3：工厂 scope 过企业入口同一 `assertTrustedScope`；克隆 scope `UNVERIFIED_SCOPE`；企业入口
  resolver 与工厂对同一批坏请求拒绝码**逐字相同**；中间件状态映射 401/400/403 同族。
- 内部入口：持久化身份建立（entrypoint=schedule，配置随上下文）；机器身份无成员资格 →
  `TENANT_FORBIDDEN`；越权选 B 公司 → `TENANT_FORBIDDEN`；机器请求走 HTTP fromRequest →
  `AUTH_REQUIRED`。
- AC4：`business.transaction`/`runtimeConfig()` 执行期间包装 `globalThis.fetch` 计数 = 0。
