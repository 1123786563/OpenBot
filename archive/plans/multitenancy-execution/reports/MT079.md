## 1. 设计要点

### 1.1 分类 seam（新文件 `server/src/enterprise/tenancy/preferences.ts`，纯新增）

- **全局个人偏好（封闭穷举清单）**：`GLOBAL_PERSONAL_PREFERENCES` —— `messageListEmphasis`（enum: agent/thread）+ `selfHostBannerDismissed`（boolean），恰为 `shared/user-preferences.ts` 的 `UserPreferences` 全部键（测试钉死结构性同步：清单与 shared 类型不可能漂移）。纯 UI 偏好按用户保存（`users.preferences`，表上没有任何范围列），跨公司/团队切换保持。issue 点名的语言、主题等**尚未存在的** UI 键在入清单之前同样被拒（fail-closed 优先于猜测）——新增偏好必须先入清单，这正是「清单可核对」的机制含义。
- **范围业务配置（封闭类别表）**：`SCOPED_BUSINESS_PREFERENCES` 六类，每类绑定真实权威存储（封闭集 `runtime-config | governance-policy | bot-configuration`）：model-selection（业务模型选择 → MT014 `model.*`，company 写 + team 收窄覆盖）、prompts（提示词 → Bot 配置业务对象 `coworker.configuration.systemPrompt`，实测核实）、default-resources（默认资源 → MT014 `botDefaults.*`）、policy（策略 → MT077 governance-policy `network/capabilities/modelRouting`）、credential-references（凭据引用 → MT014 `credentials`，票面验收 3 点名）、billing-plan-mapping（套餐映射 → MT014 `planMapping`）。业务配置的读写只走各自归属面，偏好机制对它没有任何入口。
- **清单摘要**：`PREFERENCE_CLASSIFICATION_DIGEST` = 对规范序列化（两段清单逐项展开定长数组）的 SHA-256，精确 hex `0f5d77ab…` 由测试钉死——清单任何一项增删改都同时改变摘要与钉死值（有意的摩擦，改动永远是有意识动作）。测试独立重算验证推导 + 两段缺席自证覆盖面。
- **写入口 fail-closed（全有或全无）**：`parseGlobalPreferencePatch(patch)` 只接受清单内键 + 封闭值形（enum 精确成员 / boolean）；空补丁、非对象、任一未分类键、任一坏值让**整个补丁**被拒（绝不部分生效）。拒绝码 `PREFERENCE_PATCH_INVALID` / `PREFERENCE_KEY_UNCLASSIFIED` / `PREFERENCE_VALUE_INVALID`；**拒绝消息零回显**（被拒的键与值都不回显，同 MT015 纪律，canary 钉死）。值形封闭 = 全局偏好文档结构上装不进公司业务数据或凭据引用（票面验收 3 的实现面）。
- **读入口过滤**：`readGlobalPreferences(stored)` 遍历**分类清单**而非存储键——存储文档里的任何其他内容（遗留脏键、业务形键、投毒数据、`__proto__` 陷阱）结构上不可能出现在输出里；清单内键坏值/缺失落回默认；输出恒为完整 `UserPreferences`，深冻结、确定性。读取永不合并任何范围业务条目（票面验收 4 的实现面）。
- **纯函数 seam**：只依赖入参，绝不读取任何进程环境（源码级断言钉死），无进程级可变状态；输出深冻结（与 runtime-config 同一契约）。

### 1.2 与既有机制的关系（零既有文件改动的依据）

- `users.preferences` 的既有读取/合并（`createUserPreferencesStore`）与路由层 zod 严格模式**保持原样**：路由 schema 键与本清单的同步由测试钉死（源码级提取 `strictObject` 键 ⊆ 清单），遗留入口不可能接受清单不承认的键。本模块是多租户侧的分类权威与读写门；生产装配接线由后续消费方按冻结签名接入（同 MT015 D1 判例，见 D1）。
- **无迁移**：分类是代码事实 + 既有表（`users`、MT014 两张 runtime-config 表）；migrate-test.ts / migration-tool.test.ts / index.ts / schema barrel 全部零触碰（before/after 哈希 + prereq 67 项收尾复扫为证）。

## 6. 诚实披露

- **D1（遗留偏好入口的装配接线不在本票）**：本票交付分类权威与读写门 seam；把 `parseGlobalPreferencePatch`/`readGlobalPreferences` 接进 `user-preferences-routes.ts`/`createUserPreferencesStore` 的生产装配属后续消费方动作——brief Ownership 只授权新文件 + 三个具名扩展点（无迁移可用、无装配段需求），改动遗留入口文件既未授权也会与并行票抢文件。现状风险已由既有防线（路由 zod strictObject 未知键拒绝）+ 测试钉死的键集同步覆盖；接口已冻结，接线按签名即可。
- **D2（issue 点名的语言/主题键未入清单，决策而非遗漏）**：票面以语言、主题举例说明「纯 UI 偏好**可以**继续是全局个人偏好」，当前代码不存在这两个键；fail-closed 分类下未入清单的键一律拒绝，未来新增 UI 偏好时按清单加项 + 摘要 hex 同步更新（有意的摩擦），而不是现在替未来声明词汇。
- **D3（prompts 类别的存储绑定）**：`bot-configuration:coworker.configuration.systemPrompt` 经代码实测核实（profile-store 读取 bot 配置的 systemPrompt 字段）；Bot 配置的租户化存储由 Spec §8 Bot 闭环交付，本票只钉死「提示词属业务配置、绝不进偏好机制」这条边界——绑定字段回答的是权威归属，不是新存储。
- **D4（GREEN 一次成绿的取舍）**：首跑即 23/0（唯一修复是测试的 shared 导入深度笔误，属 RED 期修正）；风险由 4/4 变异捕获 + 投毒/零回显/canary 断言对冲——测试不是只验证实现快乐路径的摆设。
- **D5（端口与容器命名）**：专用容器复用票号前缀 `mt079-impl-pg`、端口 55484（预检空闲）；assigned 库 `openbot_enterprise_mt079_assigned` 仅供 migration-tool 的 MT003_ASSIGNED 真实 apply 用例（全量回归依赖），与 MT015 同款。
- **D6（基线 9639 vs 全量 9865 expect 差异）**：基线 9639（22 文件）+ 聚焦首跑 225 + digest 钉死 +1 = 9865（23 文件），账目吻合。
