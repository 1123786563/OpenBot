## 1. 设计要点

### 1.1 分享事实表（新文件 `server/src/db/schema/personal-shares.ts` + migrate-test 的 MT010 任务）

Brief 存储条款的两分支中，「复用 grants 表扩展有效期/撤销属性」需要改 `enterprise-tenancy.ts` schema（本票 不得改 清单明列），故按预授权的第二分支落新表 `enterprise_resource_shares`（MT012 模板：复合 FK 内嵌 tenant_id + FORCE RLS + 最小列授权），迁移经 migrate-test **MT010 任务** 真实执行（brief 预授权的窄例外）：

- 复合主键 `(tenant_id, resource_id, principal_id, action)`；`action` CHECK 只允许 `'read'`——被分享方永远拿不到管理动作，**转授在结构上不可能**；`validity` CHECK 要求 `expires_at > created_at`（行自身的有效期不变量）。
- 三条复合外键内嵌 tenant_id：`(tenant_id, resource_id) → enterprise_resources`；`(tenant_id, principal_id)` 与 `(tenant_id, granted_by) → enterprise_memberships`——**跨公司分享行在结构上不可能存在**（测试以 23503 钉死）。
- **撤销语义 = 删除行**：无可达中间态，「过期或撤销后立即失效」由判定现场核对保证；行永不部分改写（无 UPDATE 授权）。活跃分享不可重复（服务层 `SHARE_ALREADY_ACTIVE`，主键兜底），撤销后可开新窗口。
- RLS：data 只读本人行（tenant+principal），operator 租户范围 SELECT/INSERT/DELETE（DELETE 另要求行内 `granted_by = 操作者`）；无 directory、无 identity_operator、无 UPDATE。FORCE RLS 经 pg_class 断言钉死。

### 1.2 服务（新文件 `server/src/enterprise/tenancy/personal-share-rules.ts`）

- **属主判定**：个人资源授权面 = `enterprise_resource_grants` 里恰有一行 `'read'` 且 principal 即操作者。0 行（含资源不存在/跨公司 id）与「不是你的」对外同为 `NOT_RESOURCE_OWNER`（不泄露存在性）；多行属不变量破坏，`PERSONAL_RESOURCE_OWNERSHIP_AMBIGUOUS` 响亮拒绝。分享目标必须显式 `visibility='private'`（`SHARE_TARGET_NOT_PERSONAL`），资源已删除拒 `SHARE_TARGET_INACTIVE`。
- **分享感知判定**（新判定门，不触碰 resource-policy）：受信 Scope（`assertTrustedScope`）→ 受限 data 事务（read committed + 超时 + 事务本地 `set_config` + advisory 共享锁，键序/键形与 resource-policy 判定入口完全一致）→ 真实 RLS 下读事实 → 公司成员资格 active 且 epoch 与 scope 一致 → 团队成员资格 active → 资源 active 且 revision/aclEpoch 完整 → 两扇门：**属主门**（本人 grants 行，restrictive RLS 保证只见本人行）∪ **分享门**（本人分享行存在且 `expires_at > now()`）。deny 只有一种形状 `{ outcome: "deny", code: "RESOURCE_NOT_FOUND" }`。
- **两个刻意的语义决定**（模块头注释已声明）：(a) 有效期按**数据库时钟** `now()` 现场核对，应用时钟永不参与安全判定；(b) 判定**不要求** resource.workspace == scope.workspace——个人权限跟随人（R4），跨团队分享的合法路径正是「同公司、不同团队」，这是 GREEN 阶段抓出并修正的第一版过严校验。
- 分享写路径与判定读路径同键族 advisory 锁（写排他/读共享，键序 tenant→principal→membership→resource），与可见性迁移、既有判定入口串行化。

### 1.3 装配（index.ts 纯追加）与迁移注册

- `personalShareRules`（decisions + admin）在 multitenancy 开关下装配：判定走已验证的 data 通道；admin 走 operator 通道，验证失败保持 null——**fail-closed**（无通道即无法创建/撤销任何分享）。分享令牌/分享页入口属 MT058/MT092，本票不接路由。
