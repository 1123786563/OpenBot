## 2. 交付内容

**表 `enterprise_workspace_memberships`**（drizzle 导出 `enterpriseWorkspaceMemberships`，schema 文件纯追加 70 行 / 0 删除）：

- 列：`tenant_id`、`workspace_id`、`principal_id`、`status`（默认 `active`）、`epoch`（默认 1）、`created_at`。
- 唯一成员关系 = 复合主键 `(tenant_id, workspace_id, principal_id)`；另有 principal 侧唯一索引 `enterprise_workspace_membership_principal_tenant (principal_id, tenant_id, workspace_id)`（沿用 `enterprise_memberships` 的反序查询索引先例）。
- 复合外键（同时证明两个归属事实）：
  - `(tenant_id, workspace_id) → enterprise_workspaces(tenant_id, id)` ON DELETE cascade——workspace 属于该公司；
  - `(tenant_id, principal_id) → enterprise_memberships(tenant_id, principal_id)` ON DELETE cascade——principal 是该公司成员（沿用 `enterprise_resource_grants` 的复合 FK 先例）。
- CHECK：`enterprise_workspace_member_status in ('active','suspended')`、`enterprise_workspace_member_epoch > 0`（正整数由 DB 兜底；**单调递增由应用写入路径 read-then-increase 保证**，测试实测 1→2→3→4）。
- RLS 最小新增（`0002_mt004_rls_policies.sql`）：REVOKE PUBLIC → ENABLE RLS → 5 条策略，逐条对照同文件既有模式：`_self_read`（directory，EXISTS principals.user_id=app.user_id）、`_data_read`（data，tenant+principal）、`_operator_read/_insert/_update`（operator，tenant；update 另加 operator_principal_id），及配套最小 GRANT（SELECT、operator INSERT、operator `UPDATE ("status","epoch")`——与 0056 对 `enterprise_memberships` 的授权形状一致）。未改动任何既有表策略（全面 RLS 属 MT012）。

**TASKS 注册条目 `MT004`**（migrate-test.ts 纯追加 74 行 / 0 删除）：两个步骤 `0001_mt004_create_table.sql`、`0002_mt004_rls_policies.sql`，编号续接工具「每任务从 0001 起」约定；SQL 逐字对照 `server/drizzle/0055/0056` 的 drizzle 生成风格（约束名、`--> statement-breakpoint` 语义由工具拼装）；**不含任何业务数据写入**。
