## 3. 交付内容

**新建 `server/src/enterprise/tenancy/admin-separation.ts`**（分类 + 判定 + 显式授权 + 审计，四段）：

1. **管理面分类（封闭规则表）**：`MANAGEMENT_PLANE_RULES` 四条——`/api/admin/**` → platform（部署管理面：企业控制、身份/凭据/人员、全局审计读、部署计费/模板；挂载点下新路由自动保守归平台面）；`/api/enterprise/workspace-scope/admin/**` → company（MT006 公司/团队管理动作）；`/api/auth/scim/**` 的 PUT/PATCH/DELETE → platform（SCIM 供应写动词是部署管理员身份管理，GET/POST 不分类）；`/api/auth/sso/{register,update-provider,delete-provider}`（POST）→ platform（SSO 登记是 ADMIN_ONLY 的部署配置决定，better-auth 面不在 Hono 路由表，按精确路径登记）。`classifyManagementPlane()` 首条命中生效；业务/自服务入口返回 null（不是管理入口）。`assertClassifiedCompanyEntrance()` 是公司面路由的 fail-closed 载荷守卫。
2. **平台面判定** `authorizePlatformManagementAction`：入口未分类 → deny `MANAGEMENT_ENTRANCE_UNCLASSIFIED`（fail-closed）；`deployment_admin` 与 `platform_operator` 放行（平台机器身份执行平台任务——如全局身份审计——是其登记用途）；**`company_admin` → deny `PLATFORM_ADMIN_REQUIRED`**（AC1 前半的判定点：tenant_admin 身份不携带任何平台管理权，平台策略只能由平台面修改）。
3. **公司面判定** `authorizeCompanyManagementAction`：入口未分类 → fail-closed；`company_admin` 携带的上下文必须过 `assertTrustedAdminContext` 信任边界（workspace-admin 签发半边的 WeakSet 机制，本文件只读消费）且 `context.tenantId` 与目标公司一致，否则 deny `COMPANY_ADMIN_CONTEXT_REQUIRED`；放行不留跨面审计（动作留痕由管理服务的撤权审计写）；**平台身份（`deployment_admin`/`platform_operator`）必须命中显式跨面授权**（subject × tenantId × entrance 三维精确绑定，无通配），命中 → 放行并产生审计事件；未命中 → deny `MANAGEMENT_CROSS_AUTHORIZATION_REQUIRED`（AC1 后半：部署管理员同样不是公司管理员，两面互不隐含）。
4. **显式授权登记 + 审计**：`createManagementCrossGrantRegistry` 构造时逐条校验（字段完整 + 入口确实分类为公司面，登记错误装配期响亮失败）；`ManagementAuditEvent`（类型 `management_action.cross_plane`，本模块自己的封闭事件类型，**不改 revocation.ts** 的封闭撤权类型集）；`recordManagementAuditEvent` 经受限 operator 事务写入 `enterprise_security_events`——与撤权审计同表同一条 RLS INSERT 策略（`app.tenant_id` 调用方 pin + `app.operation_id` 本函数 pin），写入失败原样上抛。判定结果不携带任何 PlatformScope/principal/workspace 句柄（用例钉死）。

## 4. 验收逐条证据映射（Issue #118 四条）

1. **公司管理员调用平台级管理入口被拒绝；平台身份调用公司管理入口需显式授权并留审计**：判定层——`authorizePlatformManagementAction(company_admin) → PLATFORM_ADMIN_REQUIRED`（部署守卫 `requireAdmin` 对照：tenant_admin 的部署角色是 user → 403）；跨面无登记 → `MANAGEMENT_CROSS_AUTHORIZATION_REQUIRED`（部署管理员与机器身份同样拒绝）；精确登记（异主体/异公司/异入口均不命中）→ allow + 审计事件；**真实库**：审计事件经受限 operator 角色 + 真实 RLS 落 `enterprise_security_events`，operation-pin 读回恰好一条（entrance/grant_id/granted_by/cross_plane_from 全在 details），无 pin 不可见；真实表面正控：company-admin 建团 201，平台机器身份无会话 → 401/403。
2. **每个管理入口都被分类（清单可核对）**：封闭规则表 × **真实装配清单**交叉核对——`/api/admin/**` 全部 46 条 + SCIM 写动词分类 platform（0 漏）、workspace-scope admin 4 条分类 company（0 漏）、每条前缀规则在清单至少命中 1 条（防拼错）；真实路由表（Hono routes 枚举）× 分类规则一致性钉死（新增管理路由未登记 → 用例失败 + 运行时守卫 fail-closed）。
3. **管理动作不隐含业务内容读取权（专门越权测试）**：公司管理员完成 `suspendTeamMember`（管理权真实）后经业务读通道（真实 resolver + reader）读被管理成员私有资源 → 拒绝；有资格成员读团队共享资源 200（正控：拒绝是授权语义非通道损坏）；平台机器身份 `requestAs` → 401（连业务范围都无法签发）；目录证据：`ob_ent_identity_operator` 表级授权 = 0（对照 `ob_ent_operator` > 0）、运行时登录 URL 恰好三个业务角色（`ROLE_DATABASE_VARIABLES`）；跨面 allow 决策 JSON 不含 principalId/workspaceId/memberEpoch。
4. **分类结果回写 MT001 清单**：`summary.managementPlanes` 由同一函数在真实装配上计算（结构保证一致）；清单携带 workspace-scope 面（5 入口，closure=workspace-admin，未分类 0）；`inventory-after.json` / `gap-report-after.md` 入库检查点。
