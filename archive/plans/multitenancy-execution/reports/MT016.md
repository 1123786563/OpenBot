## 2. 设计要点（承接第 1 任模块结构 + 本任补强）

- **归属即行**：`enterprise_bot_ownership` 一行 = 一个 Bot 在一家公司一个团队的归属（tenant_id + workspace_id + owner_principal_id + 状态/版本号），默认配置文档 `default_config` 在归属行内——配置与 Bot 结构上不可分离（brief 验收 4）。`agent_id` 全局唯一索引：旧工作台 agents 表主键全局（Spec §4.2），两家公司不得认领同一底层 Bot；同公司重复与跨公司占用同一代码 `BOT_ID_UNAVAILABLE`（23505 映射，不泄露占用发生在哪家）。
- **偏好复合 FK 同归属**：`enterprise_bot_preferences` (tenant_id, agent_id, principal_id) 复合外键钉到归属行与公司成员关系，均 cascade——偏好行无法在 Bot 之外的公司存在；硬删归属行时偏好经级联消失（级联不经过逐行 RLS——PostgreSQL 语义）。
- **可见性门（四重）**：行存在（RLS 租户过滤后）+ `status='active'` + 行 workspace 与受信 scope 同团队 + 调用者公司成员（active + epoch 匹配签发时版本）与团队成员关系 active。任一不成立 → MT011 canonical `{outcome:"deny", code:"RESOURCE_NOT_FOUND"}`（复用冻结实例，逐字节同形）。
- **编辑门 = 可见性门内 owner 判定**：update/delete 仅限 `owner_principal_id === scope.principalId`；同团队非 owner = `BOT_EDIT_FORBIDDEN`（已过可见性门，不新增信息）；管理身份不隐式继承内容编辑权（Spec §4.1）。
- **列表/计数/游标只从可见项派生**：非成员/被撤权者列表为空、计数 0、游标不偏移；keyset 游标 `(created_at, agent_id)` 全序。
- **公司作用域清理**：`enumeratePrincipalBots`/`hardDeleteOwnedBots` 按 (tenant, owner, ids) 三重钉死；仅凭用户 id 在错公司上下文删不掉任何行；幂等重放删 0 行。
- **归属不可客户端声明**：文档顶层携带 tenant/workspace/owner 归属键（两种拼写）一律 `ATTRIBUTION_NOT_CLIENT_DECLARABLE`——归属只来自服务端受信 scope 与事务内事实。
- **事务纪律**：assertTrustedScope → read committed + lock/statement timeout → `set_config('app.*', …, true)` → advisory 锁（tenant → principal → membership → workspace-membership → bot；读共享/归属写排他）；读走受限 data 角色、写走受限 operator 角色，事实读取全部经真实 RLS。
