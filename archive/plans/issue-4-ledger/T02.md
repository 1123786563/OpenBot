## 八状态语义（不混用）

`disabled` / `empty` / `forbidden` / `basic` / `omitted` / `truncated` / `syncing` / `unavailable`
每个命名空间在 `availability.*` 下各有一套 title+description（en/zh 双语）。
核心区分：**空**（没数据）、**省略**（有数据但不安全不能展示）、**不可用**（存储没应答，是故障不是空）。
两处有意的命名空间差异：evaluations 的第四槽位是 `unscored`（样本无评分，缺失不是 0 分，Spec §8）而非 `basic`——`basic` 一词只保留能力等级语义（仅 OpenBot 自身观察）；runs 额外携带 `tokenUnavailable`（Spec §9「token 不可用」，不可用不是 0，不按 0 token 计）。
后续页面渲染状态文案时用 `t("availability.<state>.title")`，禁止跨状态借用文案（测试断言标题互不相同）。

## 路由约定（后续页面直接复用）

| 维度 | 路由 | 落点文件 |
| --- | --- | --- |
| Bot → 运行列表 | `/bots/$agentId/runs` | `app/src/routes/_authed/_app/bots.$agentId.runs.tsx` |
| Bot → 运行详情 | `/bots/$agentId/runs/$bindingId` | `app/src/routes/_authed/_app/bots.$agentId.runs.$bindingId.tsx` |
| Bot → 评测（数据集+实验） | `/bots/$agentId/evaluations` | `app/src/routes/_authed/_app/bots.$agentId.evaluations.tsx` |
| 管理后台 → AI 可观测性 | `/admin/ai-observability` | `app/src/routes/_authed/admin/ai-observability.tsx` |

- 四条路由目前是最小占位：`ObservabilityPlaceholder` 渲染一句诚实的"尚未接入"文案。后续 Ticket 替换组件实现，不新增路由地址。
- datasets 命名空间首期没有独立路由：#27 在 `/bots/$agentId/evaluations` 页面（evaluations 链）内构建 section，因此无占位路由、也无 placeholder 文案。
- **权限校验靠布局继承，直接输入 URL 同样生效**：`/_authed` 的 `beforeLoad` 强制登录；`/_authed/admin` 的 `beforeLoad` 额外要求 `role === "admin"`。页面隐藏入口不是权限控制，服务端仍执行同样授权（Spec §9）。
- `app/tests/ai-observability-routes.test.tsx` 断言四条路由在生成的 `routeTree.gen.ts` 中、且 id 链挂在 `/_authed`（admin 页挂在 `/_authed/admin`）之下。
- 新增/改动路由文件后必须重新生成 `routeTree.gen.ts`（vite dev/build 启动时由 `@tanstack/router-plugin` 自动生成）并一并提交。

## 已知坑（本仓库测试约定）

- `@testing-library` 的全局 `screen` 在模块导入期（早于 happy-dom 注册）就固化了无 document 的回退形态，任何查询都会抛错；查询一律用 `render()` 返回值上的方法。
- 路由实例的 `fullPath`/`options.id` 都不含祖先链，测试里用 `flatten()` 递归拼接（见 `ai-observability-routes.test.tsx`）。
- 根目录 `bun run generate:app-config` 先于 `bun test` / `typecheck` 运行（pretest/pretypecheck 已挂）。
