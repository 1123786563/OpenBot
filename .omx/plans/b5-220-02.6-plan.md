## 设计决策

1. **新增 `Credits.personalBalance(payer)`**（服务层新方法，additive，不改 02.4 交付的既有签名 —— 遵守"禁止静默改别人的接口"）：
   - `readCapacity(db, payerKey(payer), at)` → available=spendableUnits（与写入侧准入同一标准，audit A1）、held=Σ held。
   - 过期侧一条 SQL：Σ used、Σ greatest(total-used,0) where expiresAt <= at（同一 `at` 时钟）。
   - consumed = Σ used（全部 grant，含过期）；expired = 过期未用；grants = 全部 grant（含 plan source）经 `grantOf` 派生状态。
   - `pendingSettlement` = `pendingSettlementPlaceholder()`：`{ enabled: false, available: 0, consumed: 0, expired: 0 }`（类型字面量钉死恒 0，组 06 接入时改类型即破契约可感知）。
2. **路由改造**：三个 credit 读路由从 `context.var.actor`（requireUser 之后的认证身份）经 `resolvePayerForPersonalUser` 解析 PayerRef —— 不读任何查询/body 账户参数；`/credits/summary` 返回 PersonalCreditBalance 新结构；02.4 中间件与错误结构原样保留。
3. **不产生写入**：解析走纯函数（不落 payer_accounts 行），路径只有 SELECT；测试用记录型 database 代理断言 insert/update/delete/transaction 零调用。
4. `summary()/grants()/consumption()` 服务签名与其部署键回退保持原样（非路由调用方与 02.1/02.2 测试不受影响）；路由层不再触达回退。
