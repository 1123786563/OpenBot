# 实施、派发与上下文

编写实施计划、实现、修复、派发或恢复时读取；关联 Issue 先做[只读摄取](issue-delivery.md)。仅分析、计划或 Review 不启动实施；提交、推送、合并、发布及 GitHub 写入以当前授权为准。

## 先分档

开工说明范围、风险和最高适用档位；事实足够即执行，不为分档增加确认。按实际影响分档，不按文件数或行数降低风险。

| 档位 | 条件 | 最低流程与记录 |
| --- | --- | --- |
| 轻量 | 明确、单模块、可逆的局部修复/小改动，沿用已确认行为，不改公开接口、跨模块合同或高风险边界；纯文档排版/错字 | 实施 → 最小相关验证 → diff 自查 → 结果/限制；无需另建 Issue、方案文件、DAG、Run、Worktree 或子 Agent |
| 标准 | 其余一般功能、跨文件行为修改或接口调整 | 简要计划 → 实施/相关验证 → 一次独立 Spec/质量 Review；计划可在消息或已有 Ticket 写步骤、文件、验收，跨会话/多人接力才持久化 |
| 完整 | 身份权限、租户/沙箱隔离、计费支付、持久化写入/事务/迁移/事实所有权、部署发布、关键运行链路/运行依赖；授权/验证/审核/交付门禁的规则配置；Orca 多 Agent | 完整计划与必要隔离 → 实施 → 独立行为验证及 Review → 集成验收/适用 OCR；计划存 `docs/plans/` |

完整计划采用 `writing-plans` 或等价步骤，列事实源/约束、编号 Task、依赖/接口、文件所有权、验收和失败处理。风险不明先定向核验，触及更高边界即升级并补缺项。

各档均保留授权、他人改动、测试隔离、真实验收及用户/批准 Spec/ADR 的额外门禁。关联 Issue 不升档；[Orca](orchestration.md)、[关闭票审计](closed-issue-audit.md)、[每日自动化](closed-issue-daily-run.md)执行专用强约束。规则更新不自动改写活跃 Run 契约，恢复须核政策影响。

## 工作区、技能与计划

1. 核 Git 基线、已有改动和相关事实源；领域/架构按实际改动加载。复用合适工作区，多写入者、跨分支集成或用户要求隔离时才建 Worktree；Orca 按 [worktrees.md](worktrees.md)。
2. 仅检查当前路径需要的技能/工具，遵守系统、开发者和用户明确要求。仓库默认技能缺失时记录缺口并走等价步骤；不能编造调用回执。
3. 等价流程保留上表完整档步骤、可还原检查点及保全后收尾；自查不替代独立验证/Review/OCR。能力缺失仅阻塞受影响阶段。
4. 默认当前 Agent 串行实施；多任务按当前可用 SDD 派发，Orca 使用监督 Task/Dispatch，每阶段一个派发器。主控可直接修复已授权局部 finding，无须另起完整方案；专用编排走其修复路径。

已获实施授权时展示必要计划后继续，不重复索取许可。

## 验证与审核

实现者执行适用的 RED → GREEN → REFACTOR、[相关验证](testing.md)和自查。[review.md](review.md)统一规定范围、finding、轮次、证据承接、终审和 OCR。

标准任务一次独立会话审查 Spec/质量；完整任务增加独立行为验收，可由同一独立 reviewer 兼任，报告分列行为、Spec、质量结论，不按角色名另开会话。多任务验证实际组合结果。

独立会话不同于被审内容的实现会话，以必要事实源和冻结范围启动，不参与该范围实现；验证者只读业务代码/测试源，可写指定缓存/报告。平台支持时用实际专业角色，否则在 Brief 定职责；记录真实会话身份与可核实配置，不猜 agent_type/模型。模型遵从当前能力与已有授权；自测不冒充独立验证。

## 派发与恢复（仅需多 Agent 或跨会话时）

- Worker 接收一个自足 Brief：目标/验收、必要事实源、工作区/前置检查点、owned_files、接口、提交策略、验证/报告路径。干净会话启动；Worker 不再派发，主控安排审核。
- 并行实施须明确用户授权，并满足接口、文件写权、资源隔离和集成顺序；工具并发上限不授予并行权。
- [共享协调](coordination-state.md)仅用于跨 Run、共享资源或专用自动化；独占本地临时目录及已证明隔离资源无需每日协议，归属不明先核验。
- 按 [artifacts.md](artifacts.md)保留唯一活动 Ledger 和证据；消息仅传新结果/阻碍/入口。恢复先核 Ledger、Git、在途工作，避免重派。
- 固定审查版本、转移或恢复内容时再读 [checkpoints.md](checkpoints.md)。未提交范围须完整覆盖，下游取得全部前置内容，不用空 BASE..HEAD 冒充审查。
