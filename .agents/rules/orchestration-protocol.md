# Orca 编排协议：执行权、资源与恢复

在 [Orca 编排](orchestration.md)中准备派发、处理消息、集成、失败或恢复时读取。Agent 候选及身份规则见 [Agent 选择](orchestration-agents.md)；具体 Orca argv 与回执字段始终核对当前版本的 `orchestration` 和 `orca-cli` 指南；本文件定义放行证据，不缓存工具参数。

## 权威状态与事件

- 区分业务 Task、内部阶段和 Orca Task/Dispatch：业务依赖只等待前置 Task 的已集成 `verified`；阶段完成只推进该阶段。每次产物整改生成新的 attempt 和检查点；阶段重试有独立 Dispatch。仅当前权威 Dispatch 的结果可以推进状态，旧结果保留为历史并完成其生命周期结算。
- 派发前记录工作区、任务/阶段身份、授权范围、资源占用、预期 Agent 与启动意图；启动回执记录实际身份。响应丢失时先查询 Orca 和 Ledger。未知写入者、资源或副作用为 `unverifiable`，取得正面退出或结算证据前不重新启动同范围写入者。
- Worker 将完整结果写入 Run 报告；消息仅报告 Delivery/Task/Dispatch、状态、检查点哈希、报告/回执路径及需要的裁决。编排者按 Delivery ID 去重，核对权威 Dispatch，先持久化结果并完成资源/会话处置，再 ack。重复消息重放已记录结论，不重复整改、Git 写入或集成。
- 成功、失败及未知尝试分别记录；每个已结算 Worker 有复用、保留或释放决定。空等待只是检查点，按技能要求枚举 Worker 并对账，不据列表缺席推断退出。

## 资源与并发

- 调度只在 DAG 前置 verified 且已集成、[编排入口](orchestration.md)规定的任务 Worktree 名额未满、owned_files 不冲突、接口稳定、所需资源可用时派发。开发、整改和独立审核期间的任务 Worktree 均占名额；只读审核不增加 Worktree，但其 Agent 占实际 Worker 槽位。
- 数据库、端口、测试环境、缓存、迁移和产物目录按真实共享范围声明；集成目标工作区独占。资源预留先于启动或集成副作用；跨 Run 的同一资源不得以不同 Run 名称规避冲突。无法证明共享资源安全时延迟派发并记录原因。
- 并行任务可从同一已验证集成 HEAD 派生；集成必须串行。每次合入前核对前置检查点和目标树，集成后在实际组合树上跑任务声明的检查及受影响回归；冲突解决或超出已审查增量的内容形成新检查点并由选定的独立审核 Agent 复审。失败时锁定目标树并保留现场，不能放行下游。

## 失败、变化与恢复

- 先分类并写持久 RecoveryDecision：环境或已确认结束的阶段故障重试阶段；有效代码 finding 返回该 Task 原实施 Agent 整改；需求变化且代码可复用时重新验证；集成回归以失败组合树为基线修复；身份/副作用不明先对账。每轮整改绑定新的代码哈希和相关验证、独立审核；Agent 改选按 [Agent 选择](orchestration-agents.md)记录交接；连续无进展及轮次上限按 [Review 规范](review.md)升级。
- rescan 保存范围修订和 Issue 变更，计算受影响 Task 及后继闭包。验收、接口、依赖或批准事实源变化使相关证据失效；未受影响结果只有在需求、前置检查点、所有权和代码哈希一致并记录承接依据后保留。移出范围的在途工作先安全结算，既有代码记录处置裁决。
- 恢复先读当前授权、scope revision、集成分支 HEAD 与 Git 状态、DAG、Ledger、活动 Dispatch、资源/Issue 声明、启动与集成意图、待处理 Delivery 和回执。状态投影不替代原始事件及代码证据；损坏或不一致时从事件和 Git 重建、核验。未知状态保持 blocked/unverifiable，不凭超时、进程列表缺席或旧聊天摘要重派。
- 任务增量记录 staged、unstaged、新增、删除文件与 SHA-256；验证和所选独立审核绑定同一检查点。集成记录前后树、授权文件清单与合入结果；回执不明时先按树和文件哈希对账，再决定继续。跨 Worktree 转移显式核对内容与哈希，不用共享 stash 协调。
