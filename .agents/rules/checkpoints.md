# 检查点与内容转移

固定交付内容、生成 Review Package、派生下游/修复工作区、转移改动或修改子模块时读取。检查点同时标识代码和前置内容，不能只用 HEAD 代替未提交工作树。

## 完整内容与范围

1. 记录检查点 ID、Run/Task/attempt、仓库与绝对工作区、HEAD、前置检查点、授权文件清单，以及任务前后的 staged/unstaged diff、授权范围内所有 untracked/ignored 文件的前后完整内容（含任务前已存在且本轮修改者）、新增文件及删除记录。清单包含相对路径、类型、模式、SHA-256、符号链接目标和增量归属；无关用户改动单独列为只读基线。对任务范围外的新增/修改做清单核对，发现意外写入先裁决，不把它默认为授权增量。
2. 按实际进入交付的每个 Git 仓库分别记录 BASE/HEAD、tracked、untracked 及子模块状态。子模块的 gitlink 或 `-dirty` 标记不代表内部内容已审查；子模块内按同一规则固定检查点、验证和独立 Review/OCR，父仓库再核对已交付 gitlink。递归未初始化或不可读的受影响子模块记为不完整。目标 gitlink 的提交须从接收方有权限的持久远端可获取：记录规范远程、承载提交的 ref 和 SHA，在无源仓库 object cache/alternates 的隔离接收目录以接收权限 fetch 并递归 checkout，核对各层 gitlink、内容和适用检查。仅本机对象、临时 ref 或实现者权限不证明接收方可还原；未发布/不可取回保持 integration_pending，保留源工作区，不擅自推送。父仓库推送/合并及清理前均核对此门禁。
3. 敏感内容优先于全文快照要求：凭据、客户数据和完整环境变量不进入普通归档、diff、消息或外部 Review 输入。敏感文件只存路径、变更类型、必要的脱敏证据及受控指纹；低熵秘密不保存可离线猜测的裸哈希。确需原文才能恢复时，仅使用已有授权的受保护存储，记录引用与访问范围；没有安全保留方式时保留原工作区并标记 `protected/unverifiable`，不得宣称完整快照或清理它。脱敏副本不能冒充逐字节检查点。
4. 在 `.archive/runs/<run-key>/checkpoints/` 保存前后快照、增量和 manifest；manifest 本身计算哈希。验证与 Review 绑定同一 manifest 及其所需前置树。字节、模式、链接、gitlink 或前置树变化后补做受影响验证与 Review。

## 派生与转移

| 模式 | 下游及终审/OCR 修复工作区的起点 |
| --- | --- |
| 已授权提交，前置成果均已提交 | 正常业务从已验证的精确 HEAD 派生；限定修复可按下节失败检查点派生，核对 HEAD 与前置提交 |
| 未提交或混合交付 | 从已记录的集成 HEAD 派生，再显式应用完整前置增量（正常业务为已审查树，限定修复可为 frozen_failed），包括 staged/unstaged、新增、删除、模式、链接及受影响子模块内容；不能只创建分支后启动 Worker |

转移前核对接收工作区及用户基线，按前置检查点顺序应用；敏感部分经受保护渠道，禁止共享 stash。核对最终文件清单、内容/模式/链接、各仓库状态与预期 manifest，并记录目标检查点。冲突或任何额外修改形成新检查点，先审查并验证；环境相关生成物按声明重建，不以源工作区的运行服务代替目标环境。

只有接收树包含全部前置内容且组合验证通过，才允许业务下游派发；限定修复任务适用下节失败检查点例外。无提交授权时称“已集成工作树检查点”，不声称分支已合并；无法安全还原前置内容时保持 blocked。

## 冻结失败检查点

检查点类型分 `deliverable_verified`（验证/审核通过，可释放业务下游）和 `frozen_failed`（已停止写入、内容完整可还原，但验证/Review/OCR 尚有失败）。集成回归及终审/OCR finding 的修复允许从 frozen_failed 派生；失败不是缺少完整前置内容的豁免。

固定失败树的 HEAD、全部增量/子模块 manifest、失败命令与环境/复现结果、finding ID、受影响节点及允许修复的 owned_files，写 RecoveryDecision 和修复 Brief。只向限定修复任务开放该检查点，不将其标 verified；业务后继继续 blocked。接收工作区还原并核对失败 manifest、确认同一失败可复现或明确环境阻塞后启动修复。独立验证/审核通过、串行集成且组合回归成功后，建立新的 deliverable_verified 检查点，再释放业务后继；最终仍需完整终审/OCR。禁止以“先通过组合验证”为修复任务的启动前置。

## 安全还原

增量包、Worker 清单及历史归档均按不可信输入处理。写入前逐项拒绝绝对路径、驱动器/UNC 路径、空段、`.`/`..`、NUL、不同平台分隔符变体和大小写/Unicode 规范化碰撞；包内路径只允许规范 POSIX 相对路径，并核对授权清单。归档解包、删除和 patch 同样适用。逐级以不跟随链接的目录句柄核对接收根与父目录，防止 symlink/junction 或检查后的目录替换逃逸；仅 realpath 字符串前缀比较不够。声明为符号链接的叶子按链接本身恢复，不追随其目标；越出授权根的链接须裁决，不自动创建。

`.git` 文件/目录及其大小写变体、Git common dir/config/hooks/objects 等元数据不允许由内容包写入；gitlink 通过受控 Git/子模块操作处理。授权恢复工具须具备上述防护并在写前完成全包验证；不具备时 blocked，不尝试有副作用的部分恢复。权限、模式、文件类型与已有用户基线不符先裁决；禁用可能执行不可信 hook/filter 的自动恢复路径。

## 审查镜像

最终审查仅含本轮授权增量。工作区有无关用户改动或敏感文件时，优先在独立、干净且版本一致的镜像中还原交付树；逐仓库核对 manifest 后运行 workspace OCR，已提交部分按下述授权提交映射覆盖。镜像排除的是已登记的无关基线，不得漏掉交付文件；报告保存源/镜像映射、范围和哈希。无法安全隔离时记录审查阻塞，不修复无关用户改动，也不把混入内容当本轮交付。

混入无关已提交内容时，保留原始 BASE/HEAD 和全部提交清单，逐提交/逐 hunk 标识授权归属。在干净且内容一致的镜像中还原本轮授权增量，保存 `source commit/path/hunk → mirror commit/path/hunk`、前置基线、最终 manifest 和哈希；与无关提交耦合到无法无损隔离时阻塞外发并澄清范围，不能默默归为本轮。已提交 OCR 使用镜像真实 BASE/HEAD，未提交用 workspace；记录原始到镜像的完整覆盖映射。原始 BASE..HEAD 仍为溯源范围，不强制将无关提交或秘密发给 provider。
