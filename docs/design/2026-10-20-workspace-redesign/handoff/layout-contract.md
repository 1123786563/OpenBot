## 2. 评审工具与产品的明确边界

以下元素只属于视觉方案索引，正式应用不得新增：

- “OpenBot 全站视觉方案”标题、设计说明和示例数据声明。
- “查找页面 / 页面空间 / 布局示意 / 状态示意”的评审控件。
- P01/P02 等 76 页编号导航、模板标记、源码路径、改造说明、验收报告。
- 外层索引与内层产品导航并存的双应用导航结构。

产品原本具有的主题偏好入口仍保留在设置中。评审控件的主题选择器不是新增产品全局工具栏。

## 3. 布局实施必须落实的六个方面

1. **空间分配**：对话主区有足够宽度，导航和辅助区服从当前任务；不能只改色值。
2. **垂直结构**：顶栏、可滚动内容和输入/表单操作彼此明确，输入区不随消息一起滚走。
3. **信息优先级**：Bot 待处理事项先于配置；主体文档/消息先于辅助元数据。
4. **组件密度**：真实字号/行高/命中区来自规范，不按缩略图比例缩小文字。
5. **层次与样式**：表面、边界、圆角、间距、图标与状态共同统一；保持 HeroUI 交互语义。
6. **响应式**：辅助面板转 Sheet/Tab；长代码或表格局部滚动，页面主体不横向溢出。

## 4. 首批布局的可执行目标

这是建议收敛到批准 Spec 的目标，不是随图自由发挥。

### 应用/设置/后台外壳

- 保留三套外壳与路由门禁；桌面应用侧栏目标 280px，设置/后台 256px，紧凑轨目标 64px；实际值以审阅后的 Spec 为准。
- 主区 `min-width:0`、内部滚动容器 `min-height:0`，外壳不因内容增加额外页面滚动。
- 侧栏手动展开/折叠和当前偏好持久化继续有效。自动响应式收起只影响当前显示，不写坏用户偏好。
- 行为回归包括隐藏侧栏后再次打开、刷新保持偏好、键盘快捷键和窄屏 Drawer。

### 聊天

- 会话顶栏固定在主区上方；消息滚动，输入区保持可达；消息阅读列建议上限 720px。
- 辅助区沿用互斥 settings/watch/workshop 搜索参数；返回键可以关闭，关闭后主区恢复。
- 可用容器小于“右栏宽度 + 主区最低 480px”时转 Sheet。此为建议统一阈值，相比现有 DetailPanel 的 400px 主区下限属于需明确的布局变化。
- 群聊保留成员身份与消息顺序，不加只适用于单 Bot 的详情入口。

### Bots / Bot 详情

- 行列表保留需要你、置顶、自己的、共享和隐藏的语义与分组算法。
- 列表行头像 28–32px，名称与职责/状态两层，数量/操作右对齐；长名称不挤出操作。
- 详情页按身份、待处理事项、活动、配置和管理操作分层；原启用、通知、建议、审批与管理能力完整保留。
- 任何内容折叠必须定义默认展开与键盘可达；不把“折叠配置”误做成隐藏功能。

### Craft

- 桌面呈现会话列表/对话/输出；预览/文件/产物沿用原组件及隔离。
- ≥1440px 在足够空间展示多列；1280–1439px 优先压缩全局导航；768–1279px 输出/会话按需打开；<768px 对话/输出切换。
- 对话最低约 480px，输出初始目标沿用约 420px，会话列表可收至 224px；按容器实际空间切换，而非强制同时摆放。
- 移动视图切换保留草稿、消息、选中会话和正在进行的执行；不得通过反复卸载重建来丢失状态。

### 设置与知识库

- 配置阅读宽度约 672–720px；数据/文档管理约 1024px；亮暗层次一致。
- 设置行“标签/解释/控件”对齐；窄屏标签在前、控件在后，保持关联和错误信息。
- 知识库窄屏按上传、文档列表、检索测试顺序；宽屏可以采用文档主区+检索辅助区。
- 文档上传中、索引处理中、失败、无文档与检索无结果分别呈现，使用已有接口字段。

## 5. 视觉验收方法

- 使用真实生产页面/受控测试数据截图，评审索引的截图不算生产验收。
- 首批至少覆盖聊天、Bots、Bot 详情、Craft、设置、知识库六种结构中的实施范围。
- 390/768/1280/1440px × 明暗主题；中英文长标题、200% 缩放、焦点与 reduced-motion。
- 截图记录 URL/状态/数据来源/主题/视口/代码检查点；同时核对布局比例、区域顺序、间距和文字层次。
- 交付差异表：参考要求 → 实际实现 → 已测证据 → 仍有限制；不能用“视觉接近”替代行为验收。
