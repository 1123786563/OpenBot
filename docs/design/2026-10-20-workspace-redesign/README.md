## 1. 设计依据与边界

### 已知事实

OpenBot 是可自托管的 AI 同事工作台，现有前端同时包含聊天、电脑、Craft、Bot 运行/评估、个人设置和管理后台。
现有 HeroUI v3.2.6 已接入；主题通过 `tokens.css`、HeroUI 变量和旧名称桥接分层。
页面事实来自当前工作区代码，不把概念图中的功能当成现有功能。
87 个文件路由声明分为 76 个页面、4 个无独立内容的布局、7 个兼容跳转；76 个页面中包含两个共享可观测性组件的地址。

### 本方案的默认决定

1. 采用“克制的现代科技工作台”：冷调石墨表面、清晰信息层级、少量蓝色操作与状态。
2. 明暗双主题同等覆盖，保留用户当前主题偏好与唯一存储，不因新配色强制暗色。
3. 保留路由、权限、领域归属和主要任务路径。所有新增布局变化显式标为 L；导航变化单列为 I，不悄悄混入换肤。
4. 聊天重阅读，配置重理解，记录重扫描，Craft 重工作空间；共用语法但不强制同一密度。
5. 保留现有头像与品牌资产；概念图里生成的新 Logo、人物照片、Bot 头像不是要求替换的正式资产。
6. 新增筛选、排序、搜索、导出或批处理必须有现有接口/行为依据；只有设计需要时在后续需求中单独立项。

### 与既有视觉事实的关系

`app/DESIGN.md` 目前记录 HeroUI 默认主题。本文件提出新的视觉候选，不把候选写成已批准事实；实施获准后再统一更新 DESIGN.md 和 Token。
原迁移中的权限、付款、聊天和可访问性验收继续成立。
领域词汇以 [CONTEXT.md](../../../CONTEXT.md) 为准；公司积分、个人积分、用户模型访问授权不可因视觉简化合并。

## 2. 全站视觉规范

### 2.1 色彩与表面

| 语义 | 暗色候选 | 亮色候选 | 用途 |
| --- | --- | --- | --- |
| canvas | `#111318` | `#F5F7FA` | 页面底面 |
| sidebar | `#0D1015` | `#EEF1F6` | 导航背景 |
| surface | `#191D26` | `#FFFFFF` | 主要容器/配置内容 |
| raised | `#242B38` | `#FFFFFF` | 浮层与明确升起的输入/选择区域 |
| foreground | `#EBEFF7` | `#192131` | 正文与标题 |
| muted text | `#A2ACBE` | `#526079` | 说明、时间、占位文字；不得进一步透明到不可读 |
| subtle boundary | `#303949` | `#D8DFE9` | 装饰性分组边界，不独自承担识别控件的责任 |
| control boundary | `#68788F` | `#7A879B` | 确需边界识别的输入和交互区域 |
| action fill | `#3D6BDA` | `#315FCF` | 主要按钮，配白色文字 |
| accent text / focus | `#8DB4FF` | `#315FCF` | 交互文字与焦点 |
| success text | `#69D5AC` | `#16704D` | 完成/可用，配图标与文字 |
| warning text | `#F0BE69` | `#8B570B` | 等待决策/需要注意 |
| danger text | `#FF9EA7` | `#B32745` | 错误/危险说明，配低饱和浅底 |

原先样例图的亮蓝仅作为视觉参考；最终按钮候选加深以容纳白色小字。主色不铺满消息正文。
状态淡底与 focus ring 的最终组合需在真实 DOM 上再次测量；自查报告只验证本表中的指定配对。
装饰边界可以弱，输入控件如依赖边界识别则必须使用 control boundary，而非随意复用低对比 hairline。

### 2.2 字体、密度与形状

- 正文延用 Inter Variable + 项目已有中文回退字体；不在全站换成等宽字体。
- 聊天正文建议 15–16px / 1.65–1.75；配置和列表 14px / 1.5–1.6；辅助标签 12–13px / 1.5。
- 页面标题 24px / 600，分组标题 14–16px / 600；对话顶栏 14px / 500。避免每页巨大标题。
- 技术 ID、路径、模型标识、时间与金额使用等宽数字或局部等宽字体，普通文案保持正文体。
- 控件高度常规 36–40px；触屏主要操作命中区至少 44px。列表行按内容 52–64px；设置行 64–80px。
- 控件圆角 8px，内容容器 12px，弹窗 16px，小状态标签允许胶囊形；列表中间行仍方角。
- 间距以 4px 为基准：8/12/16/24/32/48；页面边距桌面 24–32px，窄屏 16px。
- Tabler 图标延用同一线性风格，常规 16px，重要操作 18px。图标不代替操作标签或可访问名称。
- 暗色以表面明度区分层次；亮色浮层使用轻阴影。静态内容不叠加阴影和明显边框制造重复轮廓。

### 2.3 交互与状态

主要动作每个任务区域最多一个；查看详情、复制、取消等为次级。危险操作用文字/淡底与明确确认内容。
焦点使用独立可见轮廓，不只变化背景；选择态、焦点态与 hover 是三个状态。
切换/展开约 150–200ms，状态变化只在必要区域出现；尊重 reduced-motion，内容默认可见。
运行中、等待用户、暂停、失败、同步中、未知数据分别表达；不把 null 当 0、不把上游故障当空结果。
保存失败保留输入，背景刷新失败保留已有数据并说明时效；成功消息不让页面跳动。

## 3. 全站布局与导航

### 3.1 三套外壳（L-01）

| 区域 | 当前 | 建议 |
| --- | --- | --- |
| 应用侧栏 | 340px | 280px 起步；保留两行会话摘要，超长内容截断；有效性通过真实双语长标题验证 |
| 设置/后台侧栏 | 300px | 256px；分组、当前页与返回应用位置一致 |
| 图标轨 | 可折叠 | 64px 设计目标；保留原有折叠记忆，不在响应式切换中覆盖用户存储 |
| 配置正文 | 默认约 672px | 维持 672–720px 阅读宽度 |
| 数据/资源正文 | wide 约 1024px | 维持约 1024px；运行比较/复杂预览可使用更宽专用布局 |
| 右侧详情 | 通用 400px，可自定义 | 常规 400px，电脑/工作坊按内容配置，不把截图固定宽度强加所有场景 |

宽度与密度变化属于布局提案，不宣称现有 CSS 已实现。

### 3.2 响应式规则（L-02）

- ≥1440px：可容纳完整导航与辅助区；主阅读列仍有上限。
- 1280–1439px：多面板工作台优先收起全局导航，避免压缩聊天；尊重用户主动展开。
- 768–1279px：普通列表/配置保持导航可收起；Craft 的输出按需展示，会话列表可转面板。
- <768px：全局导航 Drawer；聊天与右栏切换；Craft 对话/输出切换；配置单列；复杂表格在具名容器内横滚。
- 判断是否并排时同时检查容器空间：主工作区至少约 480px，辅助区不够时转 Sheet；不只依据浏览器宽度。
- 移动端输入区适应安全区和软键盘；不把 fixed 底栏盖在可提交表单上。
- 横向滚动只允许代码、预览、确需保持列关系的数据容器；文档页面不整体横滚。

### 3.3 导航建议与变更分界

**基础方案：** 保留现有三套导航、分组和兼容地址。不新增“全局审批中心”、不将后台知识库直接暴露给普通用户。

| 编号 | 可独立评审的导航建议 | 默认处理 |
| --- | --- | --- |
| I-01 | 在可访问 Bot 详情中增加清楚的运行/评估/导出入口组，避免路由存在但难以发现 | 作为独立增强，不计入纯换肤的强制项；入口仍按现有权限能力判断 |
| I-02 | 为 enterprise/observability 明确后台入口归组，与管理首页一致 | 暂保留既有入口；确认目标用户和门禁后再实施 |
| I-03 | 全局会话导航与 Craft 会话列表能否合并 | 本轮不合并，使用收起/切换解决空间问题 |

## 4. HeroUI 与现有组件分工

| 领域 | 设计处理 |
| --- | --- |
| 操作/输入/选择 | HeroUI Button、Input、TextArea、Label、Checkbox、Switch、Select、ComboBox；应用包装保持既有事件和 ref 合同 |
| 菜单/浮层 | HeroUI Dropdown/Menu、Popover、Tooltip、Modal、Drawer；不重建焦点与键盘处理 |
| 卡片与设置行 | 原 PageShell / PageSection / PageRows / Item 继续承担组合，统一 Token 与密度 |
| 聊天/滚动/附件 | 保留现有专用组件，仅调整外观与布局；重点回归 IME、流式、停止/重试、附件与滚动锚点 |
| 数据表 | 保留语义 table 和业务列表；不为外观一致强制引入未验证的库组件 |
| Craft/电脑/预览 | 保留隔离、连接和执行协议，只调整容器及状态层次 |
| 状态标签 | 统一语义、文案、颜色和图标；使用当前可用包装，避免另开互相矛盾的状态映射 |

主题实施须同时验证 `--ob-*` 与 HeroUI 原生变量。当前 heroui-theme.css 多数映射为空，单改 tokens.css 不会自动改变所有原生 HeroUI 控件。
`--accent` 是 HeroUI 强调色，`--muted` 是弱化文字；应用 hover/muted surface 保留自己的命名。
Dialog/Drawer 等 portal 必须读到相同主题，预绘制脚本、`.dark`、`data-theme` 与用户偏好继续一致。

## 5. 页面模板

### `home` · A · 对话协作 / 首次行动

主内容居中，输入区获得最高权重，探索同事退为次要内容。

组件处理：Composer、Button、ComboBox；保留现有富文本/附件行为。

### `chat` · A · 对话协作

紧凑标题栏 → 可读消息列 → 固定输入区；上下文右栏按需出现。

组件处理：现有 Message/Composer + HeroUI Button、Tooltip、Drawer/Modal。

### `list` · B · 对象列表

标题与单一主动作 → 作用范围/已有筛选 → 成组行列表；状态在同一对齐列。

组件处理：应用 Item/PageRows + HeroUI Button、Menu、Modal。

### `profile` · C · Bot 工作详情

身份摘要 → 待处理事项 → 当前活动 → 配置 → 管理操作；不把设置堆到首屏。

组件处理：PageSection/Item + HeroUI Button、Switch、Select、Modal。

### `config` · C · 配置详情

返回与标题 → 状态/范围说明 → 按主题分组的设置行；长文本另开明确编辑区域。

组件处理：PageShell/PageRows + HeroUI Label、Input、TextArea、Switch、Select、Modal。

### `records` · D · 数据记录

标题 → 可用性/范围 → 已有筛选 → 记录列表或表格 → 分页/详情。

组件处理：PageRows 或语义 table + HeroUI Button、Select、Popover；表格不强制换库。

### `run` · D · 运行详情

运行身份与状态 → 紧凑事实摘要 → 引用/元数据 → 执行步骤；技术明细层级展开。

组件处理：PageSection + HeroUI Button、Disclosure 类语义；原步骤数据组件保留。

### `compare` · D · 比较分析

对象选择 → 两侧身份 → 兼容性 → 同单位差值 → 退化样本；先判断能否比较。

组件处理：HeroUI Input、Select、Button + 原比较组件与语义表格。

### `editor` · B/C · 列表与编辑

列表作为主背景，右侧编辑；保存与取消在编辑区底部，长字段内部滚动。

组件处理：HeroUI Drawer/Modal、Input、TextArea、Button + 原编辑器。

### `craft-home` · E · 创作工作台入口

Craft 会话列表 → 聚焦的选择/创建提示；维持无默认会话行为。

组件处理：SessionSidebar + HeroUI Button、Menu。

### `craft` · E · 创作工作台

全局导航可收起 → Craft 会话列表 → 对话与执行 → 输出预览；工作区宽度优先。

组件处理：原 ChatPanel/OutputPanel + HeroUI Button、Tooltip、Menu；预览隔离不变。

### `playground` · E · 编辑与预览

字段/代码编辑与输出并列；窄屏在两者间切换，输入和输出状态各自可读。

组件处理：原代码与预览组件 + HeroUI Input、TextArea、Button。

### `knowledge` · B/D · 资源管理

文档添加与上传反馈 → 文档管理主区 → 检索验证辅助区；不让测试表单压过文档。

组件处理：HeroUI Input、Select、Button、Modal + 原 UploadTasksPanel/DocumentList。

### `gallery` · F · 发现与预览

分类/Tab → 资源预览与名称 → 详情；预览本身比外层装饰更突出。

组件处理：HeroUI Button、Modal/Drawer + 原资源预览。

### `preview` · F · 单项预览

返回与身份 → 大预览区 → 元信息 → 管理配置（有权限时）。

组件处理：原 ComponentPreview + HeroUI Drawer、Switch、Input、Button。

### `billing` · D · 账户与用量

账户归属与订阅 → 余额与来源 → 现有购买动作 → 消费明细；数字使用等宽排列。

组件处理：原 PlanCard/CreditGrantList/ConsumptionTable + HeroUI Button、Select、Modal。

### `directory` · C · 配置入口目录

分组目录、简短描述与状态；入口保持与侧栏一致，不引入无来源聚合数据。

组件处理：PageRows/Item + HeroUI Button/链接。

### `flow` · G · 聚焦流程

品牌与目标 → 当前步骤/表单 → 明确主动作 → 结果/恢复；无日常会话侧栏。

组件处理：HeroUI Label、Input、Select、Button + 原认证/引导流程。

### `share` · G · 公开只读

来源与标题 → 分享内容 → 现有公共操作；不显示内部应用导航。

组件处理：原分享预览 + HeroUI Button。

## 6. 共通状态与内容规范

所有页面至少考虑首次加载、有效数据、空内容、异常、无权限、长内容；不适用的状态要按页面说明，不强行加空卡片。
列表骨架匹配实际行高；空列表给出事实与现有可用动作；筛选为空与从未有数据分开。
只读权限隐藏或禁用管理操作并解释原因，不出现可点击后必失败的假入口。
表单关联 label/说明/错误，必填和校验不靠颜色；键盘顺序与视觉一致。
异常说明采用“发生了什么 + 哪部分受影响 + 已有恢复操作”；禁止用整屏报错覆盖仍可用的区域。
长中文、英文长词、长模型名、100+ 列表项、最大金额/币种、缺失字段与过期授权都作为设计边界样例。
日期带必要时区，数值带单位；比较指标注明基线、候选与方向。状态未知不能伪装健康。

## 7. 交付与实施顺序建议

这不是实施 Ledger；下列是设计依赖和推荐批次，暂不创建 Issue、不修改功能。

1. 主题/字体/密度/状态词汇/浮层一致性 → 建立 Token 与组件视觉样板。
2. 外壳与 PageShell/DetailPanel → 在列表、配置、聊天三个代表页验证宽度。
3. 日常工作区与 Bot 链 → 完整覆盖名册、待办、活动、配置、运行与评估。
4. Craft → 验证多面板桌面和移动切换，再推广到 Playground。
5. 个人设置与费用 → 分开校验个人、公司和模型授权归属。
6. 后台资源与治理 → 覆盖配置、失败、试运行和只读权限。
7. 独立流程与兼容链接 → 登录、引导、公开分享、租户选择。
8. 全站明暗/双语/键盘/移动回归；随后独立代码审查与 OCR 属于未来实施阶段。

每批都需覆盖完整业务路径及相关浮层，不能只改路由首屏而留下旧弹窗。

## 8. 验收基线

- 每个页面 ID 具有结构、操作、状态、响应式及源码绑定；覆盖映射无遗漏。
- 设计图/索引标为示例数据，不把静态视觉稿描述成运行中的生产页面。
- 亮暗文字对比度目标 ≥4.5:1；大文字/必要 UI 边界目标 ≥3:1；焦点独立可辨。
- 真实应用后续至少在 390、768、1280、1440px 检查；200% 缩放和中英文长内容可使用。
- 对话草稿、附件、输入法、滚动、停止/重试、电脑接管、预览隔离、URL 搜索参数和返回行为不回退。
- 保存、授权、付款、清理与删除沿用现有确认/幂等/权限约束。
- 空数据、不可用、禁用、同步中、未授权不被同一“空状态”掩盖。
- 最终视觉以逐页规格、真实组件实现和浏览器核验为准；生成图中的小文字和局部状态不是业务依据。

## 9. 证据与限制
