## 现场决策与计划偏差

1. **`.env.example` 凭据占位用 `=""` 而非计划模板的 `change-me`**：计划自带的 "no secret value" 测试
   （`/OPIK_(MYSQL|CLICKHOUSE)_\w*PASSWORD\s*=\s*["']?[^\s"'$]{6,}/`）会把任何 ≥6 字符占位值判红——且其
   `\s*` 能跨行匹配（实测：`#OPIK_MYSQL_PASSWORD=` 行尾吞换行后拼上下一行 `#OPIK_MYSQL_ROOT_PASSWORD`
   即命中），计划自己的模板与测试从未能同时成立。保持测试逐字不动（它是验收契约），占位值改为空：
   compose 的 `:?` 对空值同样拒绝启动，语义不变，真实秘密（≥6 连续非空白字符）依旧会被抓。
2. **`docker/opik/` 下新增 5 个上游支撑文件**（`clickhouse-config/additional_config.xml`、
   `users.d/enable_time_type.xml`、`users.d/distributed_insert_queue.xml`、`nginx_default_local.conf`、
   `otel-collector-config.yaml`）：不在 owned_scope 的字面 6 文件清单里，但计划 Task 2 的 Files 块
   （条件 Create `docker/opik/otel-collector-config.yaml`）、compose 模板挂载（`./docker/opik/clickhouse-config`、
   nginx conf template）与计划自己的提交命令（`git add docker/opik/`）都要求它们；上游栈没有这些文件起不来。
   全部取自上游 2.2.100 固定 tag，改动仅限：去 jaeger（otel-collector）、密码 `from_env`（clickhouse，见第 6 条）。
3. **frontend healthcheck 用 `127.0.0.1` 而非计划的 `localhost`**：实测容器内 busybox wget 把 localhost
   解析为 `::1` 而 nginx 只听 IPv4 → `wget -qO- http://localhost:5173/` 恒 exit 1，healthcheck 永不转绿。
   改为 `http://127.0.0.1:${NGINX_PORT:-5173}/`（容器内实测 exit 0）后 healthy。保持计划指定的 wget 形式不变。
4. **biome 验证限定到改动文件**：按协调者 2026-10-14T18:57Z 的更正执行（仓库级 biome 基线即红，
   74E/132W/29I 与 format 377，属既有噪音），未修任何 owned_scope 外文件。
5. **`docker compose config --quiet` 需带 `:?` 凭据**：子 worktree 无 `.env`（且按约束不复制），
   用一次性 shell 测试值跑通（exit=0）；无值时的缺变量报错即 `:?` 守卫生效的直接证据，已粘贴。
6. **上游裁剪的具体取舍**（全部以「上游固定 tag 实际内容为蓝本」为原则）：
   - 保留上游一次性 `mc` 服务（建 `s3/public` 桶并设匿名下载——上游默认栈成员，attachments/数据集导出需要；
     复用 minio 镜像锚点，不引入新镜像）。
   - 去掉 `clickhouse-init`（`alpine:latest` 浮动 tag），其拷贝配置的职责由 `docker/opik/clickhouse-config/`
     的只读单文件挂载替代；`users.d` 逐文件挂载（与上游一致）以留出镜像 entrypoint 写 `default-user.xml` 的空间。
   - redis 与 minio 的上游默认凭据也参数化为 `${OPIK_REDIS_PASSWORD:?}` / `${OPIK_MINIO_ROOT_USER|ROOT_PASSWORD:?}`
     （上游默认值本身是凭据，约束禁止照抄进仓库）；backend 的 `REDIS_URL`/`AWS_*` 同步引用同一变量。
   - `additional_config.xml` 的 `remote_servers` 副本密码用 `<password from_env="CLICKHOUSE_PASSWORD">`
     替代上游字面量 `opik`——实测真实启动中 backend 迁移经 clickhouse 认证成功（等价于 from_env 生效的实证）。
   - 去掉 backend 的 `OPIK_ANONYMOUS_ID`（上游 launcher 遥测专用，非启动所需）与 build 相关字段（不构建）。

     healthcheck、entrypoint 逐字照抄上游。
