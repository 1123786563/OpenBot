## 现场决策与计划偏差（均为最小修复，签名与安全语义未变）

计划的测试代码与实现代码存在五处互相矛盾（Self-Review 未抓到），逐处按 Global Constraints 的优先级裁决并修复：

1. **「ordinary prose is projected unchanged」测试补 `{ allowFreeText: true }`**（改测试）。计划实现默认无 opts → `omitted(unhandled_free_text)`，与「allowFreeText 是显式断言，不是默认」的 fail-closed 不可协商约束一致；计划测试样例漏传了 opts。保留实现，修测试。
2. **`projectSafeUrl`：带 query/hash 的普通 URL 由「整体 omitted」改为「剥掉 query/hash 后投影」**（改实现）。计划代码 `if (isRawFile || isLoopback || url.search || url.hash) return omitted` 与其自身注释（"Query and fragment are dropped from what survives"）和其测试（`?sig=abc#frag` → projected 无 query 版）直接矛盾。按测试与注释修复：rawfile/loopback → `omitted(raw_attachment)`，否则重建 `scheme//host/path`（query/hash 自然被剥除）后投影。
3. **`projectSafeName` 白名单 regex `{0,256}` → `*`**（改实现）。原 regex 的字符数上限先于 128 字节 budget 拦截，400 字符名字返回 `omitted` 而非测试期望的 `truncated`——正是「三态不得塌缩」禁止的行为。长度职责完全交给 budget，regex 只管字符集。
4. **depth 测试叶值 `"value"` → `"deep-secret-leaf"`**（改测试）。`"value"` 与 `SafeValue` 联合的 JSON 键名 `"value":` 冲突，任何合法输出的序列化都含该键名，`not.toContain("value")` 永假失败。断言语义（深度外内容不得出现）原样保留。
5. **`projectSafeException` 用 `error.constructor?.name` 取异常类型名**（改实现）。Bun 下 `class UpstreamTimeout extends Error {}` 实例的 `error.name` 仍继承 `"Error"`，计划实现会丢失子类名、不满足其自身测试「an Error subclass keeps its name」。constructor.name 与计划非 Error 分支的既有用法一致；`Error` 本名仍不带前缀。

另有一处计划 Interfaces 与代码不一致，按 manifest 裁决：

6. **`SECRET_CANARIES` 未导出**。计划 Task 2 Interfaces 提及它，但计划给出的测试与实现代码均未使用（canary 清单实际定义在测试文件内，实现只持模式表），且 manifest 的 `produces`（"`projectSafe()` 接口 + 内容策略版本号"）不含它。按计划 Step 3 权威代码执行，不导出，避免把对抗样本字面量固化进生产模块。若下游（T37/#43）需要共用 canary 清单，可从 `server/tests/opik-redaction.test.ts` 的 `CANARIES` 提取。
