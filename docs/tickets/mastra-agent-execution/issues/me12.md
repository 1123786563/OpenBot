## What to build

通过主仓库调用 OpenBot 的 OpenMuse 任务与 Workshop 执行能使用统一 Mastra turn，并返回原业务可读取的结果和产物。

## Acceptance criteria

- [ ] 核对主仓库实际装配的 OpenMuse/Workshop headless 调用，分别记录调用入口、身份、scope、预算、产物与取消关系。
- [ ] 每个实际调用走前置受控 turn，不在子模块引入第二模型直连或通过 owner/Bot ID 猜全局环境。
- [ ] 任务等待审批/前端参与时保留通用 continuation，完成后按原任务/会话回传，重复回调不重复创建产物。
- [ ] 产物、预览、下载与执行环境继续按业务范围授权；跨团队/公司和撤销会话后拒绝。
- [ ] 原有执行超时、取消、错误展示与费用归属保持，缺失外部依赖明确 unverified 而非假成功。

## Scope boundary

仅迁移主仓库调用装配，不改 OpenMuse 子模块 TanStack Agent、Craft 或 Workshop 自身底层执行器。

## Interfaces

- Consumes：前置票经审查的实际交付合同，以及父 Spec 的身份、预算、消息与恢复约束。
- Produces：集成入口清单和对统一 turn 的稳定适配。
- Responsibility：backend_implementer；相应只读验证者 + 独立 Spec/质量 reviewer。

## Verification

主仓库 OpenMuse task 和 Workshop 端到端装配各一正常/取消/越权流程；检查任务状态与产物下载权限。

## Failure handling
