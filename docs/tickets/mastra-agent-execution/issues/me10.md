## What to build

职责推进、消息投递、唤醒和已批准操作续跑都使用同一受控 Mastra turn，保持各自稳定意图和用户可见状态。

## Acceptance criteria

- [ ] 逐项登记并迁移上述四种入口，记录业务归属、受限执行身份、预算来源、去重键、目标会话和回调。
- [ ] 每入口重验当事人/Bot/目标资源资格，来源撤销后不以全局扫描身份继续执行。
- [ ] 复用前置 headless turn 的 lease、完整历史、预算、工具与记忆，不新建平行模型或 Intelligence runner 路径。
- [ ] 同一业务推进意图在重投递/恢复中保持操作身份；已完成 receipt 不重复执行，未知副作用停止自动推进。
- [ ] 审批续跑必须引用准确 continuation，不能把批准事件当新聊天重跑整个计划。
- [ ] 每种入口独立完成正常推进及取消/超时/重复投递演示，用户可查看结果与失败原因，费用/观测归属正确。

## Scope boundary

受控迁移已存在四种入口；不增加长期任务产品、跨公司转交或新调度算法。

## Interfaces

- Consumes：前置票经审查的实际交付合同，以及父 Spec 的身份、预算、消息与恢复约束。
- Produces：四种入口到同一 turn 的薄装配及完整结果回传清单。
- Responsibility：backend_implementer；相应只读验证者 + 独立 Spec/质量 reviewer。

## Verification

四类入口各一条正常及故障/重复案例，共用前置 turn；对照入口清单核对无 Intelligence 执行/历史旁路。

## Failure handling

一个入口失败不改用另一身份/账户/引擎；未知意图隔离。
