## What to build

用户或后台 Bot 使用现有 Computer、gallery 和前端工具；需要本人参与时明确等待，并用真实工具结果继续回答。

## Acceptance criteria

- [ ] Computer/沙箱工具按公司/团队/本人/逻辑 Bot 解析环境和凭据，禁止以全局 Bot ID 共享有状态环境。
- [ ] 服务端可执行的工具沿原受控路径执行，需要浏览器的工具发出客户端请求并保存等待状态，不伪造客户端返回。
- [ ] 后台无人值守缺少参与人时持久挂起，原 UI 可查看并完成所需参与；停止或撤权后不能再执行。
- [ ] 工具结果关联原 operationId/toolCallId 和参数摘要，重复客户端回包不能重复追加结果或触发副作用。
- [ ] gallery/activity 与产物的渲染/授权语义保持，错误可诊断，页面刷新后等待状态不丢失。
- [ ] 保持原 Computer 审批和 host-access 限制；跨范围环境、已撤销控制凭据与过期恢复均拒绝。

## Interfaces

- Consumes：前置票经审查的实际交付合同，以及父 Spec 的身份、预算、消息与恢复约束。
- Produces：有人/无人值守的受控工具执行合同与持久前端结果关联。
- Responsibility：backend_implementer / frontend_implementer；相应只读验证者 + 独立 Spec/质量 reviewer。

## Failure handling
