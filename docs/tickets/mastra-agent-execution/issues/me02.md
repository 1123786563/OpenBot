## What to build

用户在受控测试范围的现有聊天界面发送纯文本，获得 Mastra 流式回答、准确费用和可停止/重连的运行状态。

## Acceptance criteria

- [ ] 保留 Bot 角色、常驻指令和可信内容指引；两个用户同用逻辑 Bot 时不串指令、模型、凭据或消息。
- [ ] 真实挂载入口完成身份、范围、会话、Run/Attempt/lease 准入；客户端指定 scope、引擎、provider、route 或 Run 身份无效。
- [ ] 流式文本开始/增量/结束及错误转换为现有 AG-UI；回答非空，错误或缺终态不得伪装成功。
- [ ] 每次模型调用通过原网关能力与输出/输入上界；非法上限、余额不足、未知价格和未知用量保持原拒绝/待结算规则。
- [ ] 付款方式在运行前固定；API 积分拒绝不能改走订阅/其他账户，订阅路径保持原费用归属且有兼容证据。
- [ ] 输出与结束事件持久化、用量确认成功之后，只有当前 owner 能完成 Run；stop 精确指向当前运行，断连不等同取消，重连不重复计费或消息。
- [ ] 一笔调用只有一组权威结算/观测关联；其他能力尚未迁移时不把该测试范围切成所有用户默认执行。

## Scope boundary

纯文本交互端到端；暂不提供连接器、附件或审批，不移除旧引擎，也不开放 remote Agent。

## Interfaces

- Consumes：前置票经审查的实际交付合同，以及父 Spec 的身份、预算、消息与恢复约束。
- Produces：受控执行模块、ExecutionBinding 与规范事件合同、按服务端范围选择引擎的测试装配。
- Responsibility：backend_implementer / frontend_implementer；相应只读验证者 + 独立 Spec/质量 reviewer。

## Verification

原聊天客户端加 fake provider 的挂载测试，覆盖正常/402/坏帧/事件落盘失败、并发用户、主动停止与重连；核对消息、事件及结算。

## Failure handling

缺 scope、lease 或预算拒绝执行；不能回退旧引擎绕过当前拒绝。
