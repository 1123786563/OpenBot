## What to build

每个 provider attempt 先持久化唯一承诺；未知 dispatch 不自动重发。

## Acceptance criteria

- [ ] 供应商调用前一定存在 dispatch 承诺记录
- [ ] 同一 attemptId 的重复派发不产生第二条承诺或第二次供应商调用
- [ ] 结果未知的承诺保持 pending，不被自动重发
- [ ] 承诺记录包含恢复所需的归属与预留信息

## Implementation steps

1. 在调用供应商前持久化 dispatch 承诺（先写承诺，后派发）
2. 以 attemptId 为幂等键，重复派发请求返回既有承诺而不是新建
3. 结果未知的承诺保持 pending，交由 08.x 恢复，不在本 Ticket 自动重试
4. 先写失败测试：进程在承诺写入后、派发前崩溃 → 重启不重复派发
