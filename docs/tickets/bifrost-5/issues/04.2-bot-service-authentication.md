## What to build

认证失败的 Bot 被拒绝；服务认证本身不授予任何个人积分权限；停用立即生效。

## Acceptance criteria

- [ ] 只有持有有效服务凭据的调用方能通过 Bot 认证
- [ ] 凭据撤销或 Bot 停用后认证立即失败
- [ ] 认证失败响应不区分“Bot 不存在”与“凭据错误”
- [ ] 认证结果不包含任何用户身份或积分权限

## Contracts

**Consumes（前置已交付的契约，开工前先读实际实现，不臆测）**

- 04.1 的 BotServiceRecord
- server/src/credentials.ts 的加密与轮换能力

**Produces（本 Ticket 交付给下游的契约）**

- Bot 服务凭据：加密存储、可轮换、可撤销，明文只在创建/轮换响应中出现一次
- authenticateBotService(presentedSecret) → BotServiceIdentity { botId, status }；停用或撤销后立即失败
- 明确语义：服务身份只证明“哪个 Bot”，不携带任何用户授权或积分权限

## Implementation steps

1. 复用现有凭据加密存储为每个 Bot 生成服务凭据，创建与轮换时一次性返回明文
2. 实现认证入口：常量时间比较、失败计数与限速，失败响应不泄露 Bot 是否存在
3. 停用 Bot 或撤销凭据后认证立即失败，不依赖缓存过期
4. 认证结果只包含 botId 与状态，不包含用户或账户信息
5. 先写失败测试：错误凭据拒绝、撤销后拒绝、停用后拒绝、失败不泄露存在性

- 本 Ticket 是业务完整切片，接口、数据库变更、授权、必要用户/管理状态和行为测试同时完成；只修改本切片涉及模块，不能顺便实施其他 Ticket。
- 领取前核验 Blocked by 各任务已验证并集成到当前工作区，读取其实际交付契约；依赖未完成不造假桩冒充已集成。任务内 provider fake 仅为测试，不得成为生产降级。
- 执行按仓库要求建立或核验工作区，记录原始 BASE 和用户改动，先 writing-plans 再 SDD/TDD；按稳定接口分派前后端及跨语言任务。没有提交授权时使用未提交检查点，不自动提交、推送或改父 Issue。
- 从公开业务边界验证输入、响应、付款账户、供应商是否被调用、台账和可用余额。SQL 原子性使用专用 PostgreSQL 测试库，缺 TEST_DATABASE_URL 不回退开发数据库、不记为通过。
- 计价必须包含全部维度并能强制上限；未知价格/usage/边界不可启用，明确免费与未知分开。默认全部能力范围不等于所有供应商天然具备严格保证。
- 未确认结果的预留始终占用可用积分；超时、Key 过期、客户端取消和查不到日志均非释放证据。经验 token 估算和周期预算不得替代严格预留。

- Key 明文仅发认证的 Bot 服务端，不入用户前端、聊天或普通日志。关闭配置、扩展缺失、凭据认证失败必须拒绝，不回退供应商直连。
- 每个切片使用功能准入防止未完成能力被启用；不等待最后一个 Ticket 才补关键拒绝路径。外部真实供应商缺凭据时完成本地确定性测试并将对应能力保留为未验证/不可启用，不编造供应商证据。
