## Contracts

**Consumes（前置已交付的契约，开工前先读实际实现，不臆测）**

**Produces（本 Ticket 交付给下游的契约）**

- 可恢复关联流程：远端已创建但本地确认丢失时，通过稳定关联键找回远端主体而不是新建
- provisionState 状态机：pending → confirmed | recoverable，恢复过程幂等
- 恢复不产生第二份 Customer，也不改变账户余额

## Implementation steps

1. 开户请求带上由本地生成的稳定关联键（如账户 ID 派生的外部引用），便于事后查找
2. 远端响应丢失时标记 recoverable，下次调用先按关联键查询远端是否已存在
3. 找到则确认映射，未找到才重新创建；两种路径都幂等
4. 先写失败测试：注入“远端成功但响应丢失”，断言重试后只有一个 Customer
