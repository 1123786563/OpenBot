## What to build

未配置比例时禁止启用计费；零、负数、非法精度被拒绝并给出原因。

## Acceptance criteria

- [ ] 未配置兑换比例时，任何付费模型能力都不可启用，且状态可解释
- [ ] 零、负数、超过精度上限或非法格式的比例被拒绝并返回具体原因
- [ ] 合法比例保存后可被读取为精确值，不发生浮点误差
- [ ] 配置校验在进程启动与管理员写入两条路径上结论一致

## Contracts

**Consumes（前置已交付的契约，开工前先读实际实现，不臆测）**

- 现有部署配置校验风格（server/src/config.ts）
- CREDIT_SCALE 积分精度约定（server/src/billing/credits.ts）

**Produces（本 Ticket 交付给下游的契约）**

- ConversionRateConfig { numerator, denominator, rateVersion }：以精确有理数表达 1 USD = X 积分，不用浮点
- 校验语义：未配置 → 计费路径禁止启用；零、负数、超出精度上限、非法字符串 → 拒绝并给出原因
- readConversionRate() 供 01.4 版本锁定与 06.5 结算消费

## Implementation steps

1. 定义兑换比例的精确十进制/有理数表示，明确允许的精度上限与拒绝规则
2. 在配置装载与管理员写入两处都执行同一校验，不提供隐含默认值
3. 未配置比例时向下游暴露“计费未启用”的明确状态，而不是回退到某个比例
4. 把比例与 CREDIT_SCALE 的关系写清：比例负责 USD→积分换算，CREDIT_SCALE 负责积分内部整数化
5. 先写失败测试：未配置、0、负数、超精度、非法字符串逐条拒绝
