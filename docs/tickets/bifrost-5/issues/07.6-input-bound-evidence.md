**Produces（本 Ticket 交付给下游的契约）**

- boundEvidence 结构：完整序列化输入计数 + 输出上限 + 供应商可强制性的证据来源
- 判定规则：证据不足（无法完整序列化、输出上限不可强制）→ 该调用方式不启用
- 经验估算只用于拒绝判断，不得作为价格或上限证明

## Implementation steps

1. 实现完整序列化输入计数（含工具定义、系统提示、附件等全部计费输入）
2. 确认输出上限被供应商实际强制（如 max_tokens 生效），否则判定证据不足
3. 证据不足时拒绝该调用方式，并给出可展示原因
4. 先写失败测试：缺工具定义计数、输出上限不可强制两类拒绝
