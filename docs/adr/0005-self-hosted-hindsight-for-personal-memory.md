# 以自托管 Hindsight 承担个人记忆的检索与推理

目标架构的职责归属更新见 [ADR 0012](0012-independent-personal-memory-authority.md)：记忆原文、审核、更正、来源、遗忘和历史由独立记忆服务统一拥有。本文其余规则继续适用；新合同与迁移方案尚待设计，本更新不代表现有实现已完成迁移。

OpenBot 的个人记忆继续由 OpenBot 管理来源、本人审核、访问权限和遗忘状态；自托管 Hindsight 承担已获准记忆的提取、检索与综合推理，并逐步替换 CopilotKit Intelligence 的个人记忆能力。用户于 2026-10-15 的设计访谈中选择了这个边界。Hindsight 不成为权限或审核的权威，也不与 Intelligence 长期维持两套并行的权威记忆；这样可以获得跨会话语义与时间推理能力，同时保留现有产品的用户控制和来源约束。

未审核候选记忆在所有跨会话召回路径中不可见，包括形成它的 Bot 与本地降级路径；多条信息综合出的新判断也须经本人确认。普通对话及已启用的授权连接来源均可产生候选；审核界面展示判断及其支持信息、时间和来源，允许本人确认、编辑或拒绝。个人记忆在同一公司内按本人及来源授权跨 Bot 使用，不跨公司。Hindsight 的模型调用复用 OpenBot 已批准的模型网关。现有本地召回会返回部分未审核记录，实施时必须收紧该行为。

迁移时，已有 OpenBot 记录且已确认的记忆按权限迁入 Hindsight；未审核记录仍待审核。仅存于 Intelligence、没有 OpenBot 记录的旧记忆不迁入，也不保留导出途径；用户在访谈中明确接受放弃这部分旧记忆。Hindsight 不可用时，Bot 仅从 OpenBot 本地的已确认且当前有权访问的记忆降级召回；新确认内容先留在 OpenBot，恢复后补同步。bank 划分、迁移切换时点及派生内容删除仍待后续设计决定。

有生效时间的更正保留历史：当前问题使用当前有效的已确认事实，历史问题使用当时有效的事实；时间证据不足时不臆断。本人遗忘记忆或撤销来源时，OpenBot 立即阻断原始信息及相关派生判断在所有召回路径中的使用，并记录待 Hindsight 恢复后完成物理删除的进度。自动提取、索引及综合的后台模型费用由平台承担，按个人和公司设置预算上限；额度不足时保留待处理状态，不把未处理结果当作已记住。

普通对话与已启用的授权连接来源可自动提出候选记忆；用户明确说“请记住”可直接确认其明确表述的普通事实，不自动扩写额外事实。密码与令牌即使被请求记住也不保存；其他敏感内容仅在用户明确要求时才进入候选审核。网页聊天、频道与定时任务等同一 Bot 入口共用记忆及权限规则。OpenMuse 独立的精确 ID 私有记忆保持自己的边界。

医疗、财务和客户资料等敏感内容即使由本人明确要求记住，也须再展示将保存的内容与来源并完成一次明确审核。确认记忆不扩大原来源授权；来源受限的信息对无该来源访问权的 Bot 仍不可见，派生判断继承全部依据的限制。未审核候选不能作为派生判断的依据。已确认记忆及更正历史保留至本人删除或公司保留政策到期；未审核候选在 30 天后过期清除，也不再参与后台处理。

Hindsight 负责查找、排序和提出待审核的派生判断；Bot 的正式回答只读取 OpenBot 已确认的原文和已确认派生判断，并再次核对当前来源权限，不把 Hindsight 新提取的事实或 reflect 回答直接交给 Bot。首版只在同一来源或通用个人记忆内部综合，不跨不同授权来源合成判断；公司及团队共享文档、知识库不属于本次个人记忆集成。涉及历史变化或派生判断的回答提供可展开的记忆依据、来源和有效时间，并允许本人从依据入口更正或遗忘。

功能上线后即对适用用户启用，不另设按公司试点阶段；上线仍以已批准的公司与团队多租户方案所要求的全功能隔离验收为前提。本人有独立的“暂停学习新记忆”和“暂停使用已有记忆”控制，后者立即阻断召回但不删除数据。公司管理员可查看服务健康、同步积压和预算用量，不因管理身份而读取员工个人记忆、候选或依据。

Hindsight 自托管版支持隔离 bank 和自定义 TenantExtension，但其内置简单 API Key 扩展使全部已认证请求共用 public schema；tag 过滤也不是公司或用户的强隔离边界。OpenBot 的公司、用户、团队及来源授权仍须由 OpenBot 的可信身份和权限接口决定，bank 映射及进一步的租户隔离方式待确定，不能仅凭 Hindsight 自称支持多租户就认为已满足 OpenBot 的多租户验收。依据：https://hindsight.vectorize.io/0.10/developer/extensions 与 https://hindsight.vectorize.io/blog/2026/08/04/per-user-multi-tenant-agent-memory 。

同公司跨团队的记忆区分通用个人偏好和团队业务事实：仅由本人明确设为通用的个人偏好可在同公司获授权的 Bot 间使用；团队对话和连接来源中的业务事实及派生判断继续受团队和来源权限限制。

删除验收须区分立即阻断召回、Hindsight 活跃文档及观察清除，以及任务载荷、模型追踪和备份的残留清理。Hindsight 默认会保留已完成任务的载荷而不设期限，模型调用追踪默认开启并保存原始提示及输出一天；不能仅凭文档删除成功就宣称所有物理副本已清除。实施时必须设定有限保留、关闭含内容追踪或证明其清理，并核验备份过期策略。依据：https://hindsight.vectorize.io/developer/configuration 与 https://hindsight.vectorize.io/api-reference 。

用户选择分阶段清除：立即阻断召回并清除活跃文档及相关观察；关闭 Hindsight 含内容的模型调用追踪，已结束任务载荷配置 1 天保留窗口，受控备份配置不超过 30 天保留窗口。界面分别显示“已停止使用”和“受控副本清除完成”；后者必须有任务实际清理、备份过期及恢复后重放删除记录的证据，不以一次远端删除请求成功或保留期限配置替代。
