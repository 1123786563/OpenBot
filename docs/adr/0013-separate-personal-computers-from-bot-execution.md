# 将个人电脑与 Bot 执行环境隔离

CubeSandbox 承载每位用户的个人电脑，并保留浏览器配置文件（profile）。OpenShell 运行 Bot 的 shell 命令、脚本和终端会话，只允许访问已授权的工作区，并按策略控制网络访问。OpenBot 提供统一的电脑入口，将浏览器操作和执行请求分别发送到对应环境。两个环境独立运行，便于 OpenBot 保护浏览器凭据，并独立升级任一运行环境。

文件通过 OpenBot 跨边界交付。每次只交付一个指定文件，OpenBot 在交付前校验用户、Bot 和文件的归属。下载文件和上传附件都遵循这条规则，两侧各自维护存储。

Bot 发起的浏览器下载成功后，文件自动交付到该 Bot 的工作区。用户手动下载的文件留在个人电脑上，等用户选定文件和接收的 Bot 后再交付。Bot 向外部网站上传文件须经用户一次性批准，审批时显示文件名和目标站点。文件或站点变更时须重新批准。用户接管浏览器后亲自上传文件，按用户本人的权限处理。

每个「用户 × Bot」组合都有一个持久化工作区。OpenShell 实例释放后，工作区可以重新挂载。OpenShell 默认拒绝出网，只允许访问管理员明确放行的目标。Shell 出网规则和浏览器上传审批独立生效。

一侧环境不可用时，另一侧继续提供自身的功能。文件交付失败时显示失败状态，重试同一次交付只会生成一份文件。如果对外上传请求已经发出且结果未知，须由用户确认后再试。

停止 Bot 执行会结束它的命令和终端会话，并保留工作区。停止个人电脑会结束浏览器和关联的执行会话，并保留文件和登录态。清空工作区与重置浏览器是两个独立操作，均须确认。清空工作区会删除所选用户和 Bot 组合的文件。重置浏览器会清除浏览器配置文件和登录态。现有隔离 Bot 在首轮发布中继续使用原后端。

个人电脑为用户自己的浏览器和该用户运行的每个 Bot 分别保留独立的浏览器配置文件。一个配置文件中的登录态只在该配置文件内有效。

首轮仅向指定用户开放自愿试点，使用新建的浏览器配置文件和工作区。扩大范围前，须验证实例替换后仍可恢复文件和登录态，并验证 Bot 执行环境无法读取浏览器配置文件、获取管理凭据或访问网络策略未放行的目标。试点用户可以切回原后端。现有数据的迁移在试点后另行决定。
