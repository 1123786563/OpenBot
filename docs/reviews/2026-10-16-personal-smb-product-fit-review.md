# 个人与小型企业 Agent：规格复核与市场对照

日期：2026-10-16。

定位依据：用户本轮明确“本产品主要针对小型企业和个人”。这是已确认的目标用户修正；下面的功能优先级、个人空间模型、套餐和入口建议尚未批准，不自动覆盖已有 Spec/ADR。

审核对象：[个人 Agent 主规格](../specs/2026-10-16-enterprise-personal-agent-product-permissions-spec.md)、[长任务专项](../specs/2026-10-16-long-running-task-lifecycle-spec.md)，并对照公司团队、付款、记忆、OpenMuse 完整产品合同、Craft/Workshop 设计及部署说明。输入版本为主规格 v0.4、长任务 v0.1；本轮分别修订为 v0.5、v0.2。

## 1. 结论及证据边界

当前文档对范围隔离、记忆来源、操作审批、费用责任和任务恢复已经写得较细；这只是设计覆盖判断，不是实现或运行成熟度的结论。

面向个人和小型企业，主要缺口集中在：完整个人业务模式及付款、快速开始、可靠的常用工具链、可检查的业务成果、容易理解的消费和异常恢复，以及小团队的轻量协作。下一步需要给出这些能力的实际用户路径和验收。

市场研究使用官方产品页、帮助和文档；检索日期为 2026-10-16。后台研究记录见[官方来源报告](../research/2026-10-16-personal-smb-agent-market-sources.md)。主 Agent 另查 OpenClaw、Microsoft、Google 官方材料补充个人入口和办公套件对照。没有登录实测、试付费或性能对比，不把营销描述、计划特定能力或不同产品的能力混为一谈，也不对竞争产品打完成度分数。

用户尚未在本轮指定首发地域和交付方式。地域按国内/海外两组候选工具链讨论；“托管优先、自托管保留”仅是产品评估假设，不代表用户已经选择该交付路线。

## 4. 优先补充的产品能力

以下按首个可用个人/小团队体验排序。P0 表示应先明确合同和打通路径，不等于允许绕过原全量隔离或 OpenMuse 完整切换门槛。

| 编号/优先级 | 当前覆盖情况 | 建议补成的可验收结果 |
| --- | --- | --- |
| G01 / P0 完整个人模式 | 公司/团队模式与个人模型授权已设计，个人完整业务空间及付款未冻结。 | 个人注册后直接使用私有 Bot、文件及任务，不必先理解公司架构；明确真实归属、个人付款及个人→团队的转换规则。个人数据不因加入公司而自动迁移，旧公司/个人余额不合并。底层是否复用租户实体须单独裁定，不能把 Tenant 的公司语义悄悄改掉。 |
| G02 / P0 快速获得首个成果 | 有首次进入和受管理 Bot 模板，但业务入门合同不足。 | 提供少量业务模板，按需要连接一个应用，用自己的资料试跑并产出真实成果；未配置知识库/外部连接也可先完成文件任务。入门成功率及完成耗时需实测，不直接承诺“几分钟一定完成”。 |
| G03 / P0 一套可靠的常用工具链 | Google、M365、知识和插件已有不同规格，未决定首发地域。 | 先打通邮件、日历、文件/表格、一个通知入口的完整生命周期：同意连接、实际账号、权限、试跑、错误、撤销、产物和回执。地域选择后排序，不把全部 SaaS 或 IM 设为同时首发。 |
| G04 / P0 可理解的费用与限制 | 账本、严格预留和账户隔离较细；个人/SMB 的购买与任务成本说明不足。 | 开始前展示可用能力、本次上限/预计区间与依据，运行中展示已用/占用/剩余，触及阈值明确停下；区分套餐固定项、credits/用量和可选附加项。估算不是报价，实际费用按原账本合同处理；不任意新增价格或无限额度。 |
| G05 / P0 可运行且能自助恢复 | 有部署手册及长任务状态，但整合后的安装/运行路径和用户恢复入口待定。 | 托管模式明确客户端关闭后由谁运行；自托管检查 Worker、环境隔离、存储、连接和备份，机器休眠/断电时显示受影响任务。提供补连接、补预算、继续、终止及查询未知结果的可理解入口，未知写操作不提供盲目重发。 |
| G06 / P1 可编辑的业务成果 | Files/PDF/CSV、Craft 报告/导出和预览均已有设计基础。 | 统一任务成果页：预览、修改、版本、原始来源、下载或写回目标应用。按实际需求选 DOCX/XLSX/PPTX/网页等格式；不能用截图或聊天长文替代可用文件，也不要求一次支持全部格式。 |
| G07 / P1 轻量团队协作 | 团队公共资源、显式分享和离职交接已有约束；日常协作路径不足。 | 老板邀请成员、分配有权任务/成果、评论和确认交付；私人助理与团队公共能力可辨认。先做这些路径，不必同时增加共享 Thread、共享邮箱或多人共用浏览器；新增任务交付权限需独立确认。 |
| G08 / P1 今日工作与消息入口 | Activity、任务通知、静默时间及主动建议已有设计。 | 聚合今日安排、等待我决定、今天完成、即将到期及需要关注；主卡片用自然语言，技术状态可展开。一个入口决策可分别记录 Reviewed/Policy 事实，不能合并判断或省略必要批准。 |
| G09 / P1 连续业务上下文 | 有 Task/Goal/记忆和跨月生命周期，缺少面向客户/项目工作的产品组织方式。 | 按项目或外部客户引用关联资料、任务、产物、规则和后续跟进，显示来源与授权；先复用已有对象/外部系统引用，不另造一个完整 CRM 或新的内容权威。个人项目也不应要求虚构一家客户公司租户。 |
| G10 / P1 数据可带走与可验证隐私 | 有单文件下载、记忆更正/遗忘及账号恢复，完整数据可迁移合同不足。 | 用户能按权限导出本人任务/产物/记忆记录及必要依据，导入有来源和归属校验；秘密值和无权公司数据不包含其中。说明数据去向、模型处理、保留及删除状态，支持明确退出而不只是停订阅。 |

推荐先打通的三种体验：

1. **个人每日工作准备**：邮件/日历中的有权资料 → 今日安排及会议简报 → 用户确认的待办；按权限读资料，明确哪些只是草稿或建议。
2. **小企业客户事项跟进**：收到询价/材料 → 组织相关资料 → 报价或回复草稿 → 等待补充/提醒 → 确认后发送 → 回执和后续任务。优先验证业务闭环，不先开发完整 CRM。
3. **每周经营资料整理**：上传 CSV/表格/文件 → 可核验的汇总与报告 → 可编辑成果 → 周期更新及异常提示；沿用原 finance 计算证据及分享规则。

这三项用于入门和实现优先级，不取代原完整产品合同中的其他功能或验收；若要缩小首次公开交付范围，应先明确修订相应已批准 Spec。

## 5. 应简化的体验与可以暂缓的扩展

小企业的负责人可以同时承担产品、安全/数据和运行责任，在没有强制职责分离政策时不要求设置三名不同员工。内部仍分别记录角色、决定与权限。普通用户首先看“助理、工作、资料、连接、用量”，Company/Workspace/Run/策略版本/审批类型等实现概念仅在需要时解释。

默认安全路径应提供清晰的读/写、账号及目标提示，一张操作卡片可以汇总当前所需决定，再分别交给对应权威记录。不能为了减少点击取消已经批准的外部变更复核、提升所有者对其他人私人内容的读取权，或默认允许无限期后台写操作。

在保留隔离、恢复、费用及审计基线的前提下，可暂缓的是尚未批准的扩展：复杂部门继承、任意跨公司协作、商业 Agent 市场分成、任意外部 Agent 联邦、无边界多 Agent 协作、同时覆盖所有区域 IM、面向高规模集群的额外运维界面。已有 Spec 明确要求的功能不能因本建议自动延期或删掉。

## 6. 地域与交付方式的条件分支

| 条件 | 应优先验证的产品路径 | 当前不能默认的事项 |
| --- | --- | --- |
| 国内个人/小企业 | 本地文件、中文文档/表格、其实际邮箱、所选国内工作消息入口。飞书/企微/钉钉等仅为候选。 | 不能承诺所有平台均已支持，不把任意个人消息账户当作可接入企业 API；认证、回调和能力须按官方接口另查。 |
| 海外个人/小企业 | Gmail/Outlook、日历、Drive/OneDrive/Notion 和首选消息入口。 | 不因有 Google OAuth 就认定 M365 完整接线；连接器权限/计划和成本仍分别验证。 |
| 托管优先 | 直接注册、有限试用/试跑、连接自己的账号、后台继续执行、升级取消及自助恢复。 | 不能在未确认容量、计费、存储及隐私前把旧单容器称为完整托管方案。 |
| 自托管优先 | 实际可复现的安装/升级/备份/恢复配置，依赖诊断与小团队默认设置。 | “单容器启动”不自动等于 Worker 持续运行、范围环境隔离或机器休眠后继续工作。 |

若两种交付都要做，需定义同一功能合同的支持矩阵和数据迁移边界，避免维护两套独立产品状态。当前仅提出评估框架，没有替用户选择市场或部署方式。

## 7. 需要明确的下一批产品合同

最先应冻结“个人业务空间与任务付款”及“首个成果与默认设置”两份合同，再按已选地域和部署方式冻结主要连接器、成果交付、消费展示和自助恢复。跨月任务在此基础上成为持续工作的能力，不能用长期运行功能替代首次使用价值。

本轮在主规格记录目标用户修正、D10/C07，并澄清签署职责可由同一合资格主体兼任；长任务只澄清唤醒的逻辑意图与队列投递语义。其他建议保存在本报告，未写成已批准 ADR、未改公司/个人付款规则、未实施生产代码或发布。
