# OpenBot Web 整改计划

以 [89 条逐页评分](web-impeccable-scorecard.md) 为整改基线。先交付会话恢复和敏感操作防错，再统一导航和视觉。旧外观专属流程迁完、书签验证通过后，按 ADR 0003 退役旧外观。评分版本为 `a2376497`。实施以届时的目标分支为准，先用评分表对照已合入的 Astryx 和会话变更，逐项复验可关闭的问题。

## 第一批 · 会话恢复和敏感操作防错

- **会话交接与恢复**。在首页、新建会话和 `/start/$startId` 中用可恢复的草稿交接替代仅驻留内存的过渡。显示选 Bot、创建会话、等待响应及提交结果。刷新、后退、断网和重复确认分别验证。首次发送失败前保留文本和附件引用。提交结果不确定时先查询服务器的权威状态，然后提供符合该状态的恢复动作。回到同一个 Conversation 和 Thread 后只出现一份用户消息。
- **会话与 Bot 执行反馈**。`/bot`、单 Bot 和多 Bot 会话复用同一套发送、停止、等待审批、恢复和失败反馈。执行时显示是哪位 Bot 在处理。审批展示请求动作、作用域与继续路径。批准后恢复到原 Thread，拒绝和过期可解释。按照 ADR 0011 使用 Astryx 呈现 transcript、composer、工具和审批控件，CopilotKit 保留 AG-UI 接入及 A2UI 解释，验证已有 `openbot/ui@1` 表单渲染与提交。 [ADR 0011](adr/0011-use-astryx-for-openbot-ui-and-copilotkit-for-agents.md)
- **高影响操作**。覆盖 Admin People 的停机、撤销访问和管理员角色改动，SSO 提供者删除、Team/Personal 凭据撤销、保存登录项删除、技能删除、Forget，以及授权规则的部署级变更。确认前列出目标、作用域和已知影响，说明能否恢复。取消后不发请求并还原焦点。提交中防重复，失败时保留上下文并允许就地重试。陈旧对象或权限变化时重新读取有效状态并解释下一步。
- **本批验收**。实测 Personal 和 Team 各一次 Bot 发送、等待审批及恢复。用慢响应、网络中断、过期审批和重复点击验证恢复。管理员用键盘完成一次预览后取消、一次变更成功和一次被拒绝，确认提交前后语义、焦点和审计记录一致。

## 第二批 · Astryx 基础、壳和页面状态

- 在目标分支确认 Astryx Neutral、入口 reset 和基础样式已经接入。用 Bots 清单和创建 Bot 两个入口对照主线试点。先验证默认及定制品牌、轻暗两套外观和 Personal/Team 权限，再推广到后续批次。根据 `AGENTS.md` 读取 `astryx docs layout` 后调整框架。新增页面从模板开始，已有页面沿用模板框架并更换内部区域。密集数据采用 Table、List/Item，Badge 用于计数，布局用组件，样式用组件属性及令牌，颜色走主题。主题改动后用 `astryx experimental theme editor show <name> --png` 复核。 [项目约定](../AGENTS.md)
- 工作区围绕继续 Conversation、找 Bot、查看待处理事项组织导航。Settings 按人的偏好和个人授权组织，Admin 按配置对象和治理任务组织。统一子页标题、当前位置、返回路径、焦点及窄屏行为。保留深链接和查询参数，找不到旧目标时说明原因并给可达的入口。
- 所有读取页面区分正在加载、真正为空、读取失败、无权限和暂未配置。用内容区骨架、能直接行动的空态、就地重试和明确的返回路径。表单提交失败保留输入和校验定位。对真实状态变化做读屏提示，避免重复播报。
- 建立 Web 设计说明，记录 Astryx 主题、品牌、布局密度、交互状态和代表性截图。现阶段 Web 产品说明与主线迁移决定有分歧。落地时按已确认的 ADR 同步产品说明。主线 ADR 0003 位于 `docs/adr/0003-pilot-astryx-for-web.md`。

## 第三批 · 按场景重做信息层级

| 涉及评分表 | 整改动作与复验 |
|---|---|
| 登录、首次使用、桌面交还、为 Bot 登录 | 用持久字段标签和状态解释替代占位提示。完善登录受阻、供应商取消和桌面协议未完成时的下一步。保存首次使用进度，从受保护链接登录后能继续原任务。 |
| 首页、新建会话、单 Bot、多 Bot 与快速会话 | 聚焦发送与继续。有明确的收件人和当前执行者。高级模型、命令及附属设置渐进披露。验证历史打开、长消息、长附件名、模型不可用及权限变化。 |
| Bots 清单、创建、档案及全部子页 | 档案首屏交付该 Bot 的身份、待处理工作和主要操作。将运行、授权、记忆、例行任务、分享和设置归入对应区块。用来源与有效范围解释权限。实测空名单、多人共享、挂起、只读角色及深链接。 |
| Browser、Computer、Credentials、Passwords、Recorder、This computer | 明示设备或会话归属、连接状态、最后活动及断开后的动作。验证浏览器断线与重连、设备不可用、凭据撤销的影响和桌面接续。 |
| Capabilities、Skills、Memory、组件库 | 列表提供筛找，编辑有明确提交和离开行为。范围变化、忘记记忆、注册组件和发布分别给后果预览。长内容仍能找回主要操作；组件预览失败保留列表上下文。 |
| Routines、Responsibilities、Tasks、Ideas、Bot Activity | 让管理者从下一次触发、执行状态、等待谁与最近结果定位行动。排程预览时区和夏令时。把 Goals、Routines 和 check-ins 的入口放到各自任务流程，确保待办和历史均能回到源 Conversation 或 Bot。 |
| Connections、个人应用、团队应用、外部身份、broker 目录、插件 Bot/Tool 子页 | 把发现应用、登录账号、授权和验证连通性排成可回溯的步骤。明确授权主体、作用域及 Bot 继承关系。验证 OAuth 同意、退出、回调失败、重复绑定和断开。保留搜索、选择态及返回位置。 |
| 审批、Permissions、Boundaries、What if、People | 以有效策略查看、修改预览、生效和审计串起治理任务。保留自然语言回测，并把受影响对象带入 What if。边界规则的旧索引深链接需避免落到另一条规则，先验证当前目标，再决定是否迁移为稳定标识。 |
| Admin 概览、Audit、Providers、Learning、Proactive、Playground 与 Settings 其余页面 | 概览把常用任务和待处理事项置顶。Audit 支持恢复过滤及失败导出。Providers 是部署能力与模型选择入口。Learning、Proactive 的运行状态和配置分层。Playground 保留草稿、局部报错和预览。Settings 的通知、学习、环境与常规设置统一页内可恢复反馈。 |

## 第四批 · 迁移专属流程与兼容验收

| 旧地址 | 统一 Web 目的地与保留任务 |
|---|---|
| `/s/tasks` | 任务页或对应待处理区域，保留 Active、Up next、完成历史和原会话入口。 |
| `/s/routines` | Routines，保留全局清单与 Bot 上下文。 |
| `/s/memories` | Memory。能力关闭时给符合该角色的返回路径。 |
| `/s/activity` | Bot Activity 或统一 Activity，保留选定 Bot、待处理与档案链接。 |
| `/s/ideas` | Ideas 或 check-ins 对应页面，保留选定 Bot 和设置入口。 |
| `/s/goals` | Responsibilities 的 Goals 视图，保留 Bot 筛选及原 Routines 入口。 |

采用目标分支已存在的规范目的地，复用其数据与权限守卫。逐条跑 16 个兼容跳转，加上 6 个外观专属路径的旧书签，验证查询参数、Bot 上下文、登录回跳以及 Personal 和 Team 的回退。未知或已移除链接提供可恢复页面。旧皮肤的流程、链接和权限全部验证后，再移除设置中的外观选择、旧壳与仅供旧壳使用的资源。

## 逐页达到 99% 的证据

1. 整改分支先与当前评分表比对。每个页面或独立视图记录对应评分行、关联修改、测试账户、构建版本和证据，已改变的路径补充新旧映射。
2. 每页覆盖适用的默认、空、首载、失败和权限状态。会写入的页面补成功、拒绝、取消和重试。覆盖浅暗、1440×900 与 390×844，验证键盘、读屏和缩放。真实身份回调、Bot 流式会话、审批、A2UI 和跨客户端交接使用对应测试环境补证。
3. 用原十项量表独立复评。每个适用项均需有可复验依据，门槛为 40/40 或 36/36。源代码和模拟接口可以记录暂定分，真实任务无法走通或证据不足时保持待验。共用组件的通过结果用于减少重复检查，每个入口的角色、路由与失败反馈仍需验证。
4. 覆盖所有三类角色，并对旧链接、共享布局、浏览器控制台异常、暗色对比和 Astryx 生产构建执行回归。高影响动作必须有可用的取消、失败和可恢复性验证。用 Impeccable 检查设计和技术缺陷，发现的问题回填到对应评分行。
5. 保留每页前后原始分、截图或流程记录及剩余问题。整个 Web 以每个仍提供的页面达标、旧入口和任务迁移验证完成为验收条件。

## 产品术语

Conversation 是用户看到的交流，Thread 是其中可恢复的执行上下文，Bot run 是 Bot 的一次执行。等待审批是运行状态，Approval 是决定，Approval rule 是规则，Grant 是授权。员工在审批页面需要知道批准什么动作与何时恢复，管理员在规则页面需要知道影响谁及何时生效。连接页同时区分外部账户、应用提供的 Tool 和 Bot 获得的 Grant。沿用现有术语表和权限语义。 [领域术语索引](../GLOSSARY-MAP.md)
