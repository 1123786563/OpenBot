## Problem Statement

OpenBot Web 的 `openbot`、OpenDuet、OpenDots 和 OpenMuse 四套皮肤使用不同的导航和界面表达。使用者在切换皮肤或页面时要重新寻找常用操作。维护者需要在多套皮肤和自制基础组件中重复处理样式、交互和可访问性问题。统一界面时，使用者仍需要从原有入口完成工作，既有 Bot、Conversation、权限、部署品牌和明暗偏好都应继续生效。

## Solution

以 Meta Astryx Neutral 作为 OpenBot Web 的统一设计规范，沿用其默认组件和交互，适配部署品牌的产品名、标识、明暗强调色及必要布局。首批提供可运行的 Bots 列表和 Create Bot 弹层，覆盖从列表及新建 Conversation 发起的创建流程。用户签收试点视觉后，按功能分批迁移其余 Web 页面。四套旧皮肤在过渡期继续可用，等各皮肤的导航入口、专属页面和工作流程在统一界面中都有可用去处，再退役旧皮肤。

## User Stories

1. 作为 Web 使用者，我希望常用控件在不同页面表现一致，以便切换任务时仍能迅速辨认和操作。
2. 作为回访使用者，我希望原有导航及收藏的深链继续到达相应功能，以便接续原来的工作。
3. 作为使用明暗主题的使用者，我希望迁移后的页面继续使用我的外观偏好，以便在不同环境下阅读。
4. 作为在窄屏使用 Web 的人，我希望能读完列表并提交创建表单，以便在小窗口完成同样的操作。
5. 作为键盘使用者，我希望能打开弹层、找到焦点、完成表单、按 Escape 退出并回到触发位置，以便全程用键盘操作。
6. 作为使用辅助技术的人，我希望输入项有名称，校验和提交错误可感知，以便理解并修正问题。
7. 作为管理多个 Bots 的人，我希望按现有分组定位待处理、固定、自己拥有、他人共享和已隐藏的 Bot，以便从列表继续管理。
8. 作为 Personal 使用者，我希望继续看到 OpenBot 随附的 Bots 和 Skills 入口，以便知道我的 Bots 能做什么。
9. 作为首次创建 Bot 的人，我希望能从列表顶部或「Yours」空态打开同一个创建表单，以便直接开始。
10. 作为从皮肤快捷入口或旧创建链接进入的人，我希望仍能打开 Bots 列表上的创建弹层，以便沿用习惯的入口。
11. 作为从列表创建 Bot 的人，我希望成功后进入新 Bot 详情，返回时看到已关闭弹层的列表，以便继续配置或浏览。
12. 作为正在起草 Conversation 的人，我希望在收件人选择器里创建 Bot，并让它加入收件人列表，以便带着原有收件人和草稿继续对话。
13. 作为使用内置托管的 Bot 创建者，我希望用名称和可选指令完成创建，以便快速开始使用。
14. 作为连接自定义 Agent 的创建者，我希望在保存前验证 AG-UI 连接，并能在失败后修正重试，以便确认 Bot 可以正常连接。
15. 作为 Personal 使用者，我希望新 Bot 继续按 Personal edition 的可见性、隔离和应用默认规则创建，以便得到一致的使用体验。
16. 作为 Team 成员，我希望新 Bot 默认私有，并在请求超出权限时看到可纠正的错误，以便保留输入并继续创建。
17. 作为 Team 管理员，我希望能按部署配置和我的 Capabilities 使用公开创建、隔离和应用授权选项，以便保留团队管理能力。
18. 作为在 Chat 中使用创建提案的人，我希望继续查看提案并明确批准后才创建 Bot，以便掌握创建的内容和时机。
19. 作为从 Bot 详情复制 Bot 的人，我希望继续通过原有操作获得自己的私有副本，以便复用已有配置。
20. 作为部署维护者，我希望能配置产品名、标识和明暗强调色，以便使用自己的品牌并保持控件可读。
21. 作为 Web 维护者，我希望页面复用 Astryx 组件和设计规范，以便减少维护同一交互的多份实现。
22. 作为试点验收人，我希望能在真实运行的 Personal 和 Team Web 上核对功能和视觉，以便判断是否开始后续迁移。
23. 作为仍使用旧皮肤的人，我希望其导航入口和专属流程都有可用的统一界面后再移除皮肤选择，以便过渡期间持续工作。

## Implementation Decisions

- 采用 Astryx Neutral 默认的组件、排版和交互。OpenBot 通过部署品牌配置提供产品名、标识和明暗强调色，沿用现有明暗偏好。布局调整服务于现有的信息层级和操作顺序。
- 试点通过独立的 Web 构建开关启用。常规构建继续使用现有界面。预览使用隔离的 OpenBot API 实例及 PostgreSQL 数据，通过真实的 Bot 创建和授权路径运行。
- 试点覆盖 Bots 列表和两处调用共用的 Create Bot 弹层。列表保留分组、状态、个人隐藏、详情导航，以及 Personal 和 Team 各自的区块与空态。Bot 所有权继续决定「Yours」归属，Bot 可见性和共享继续由服务端控制。
- 列表顶部、列表空态、现有皮肤快捷入口和兼容深链继续打开同一个弹层。列表创建成功后进入新 Bot 详情，返回时弹层保持关闭。新建 Conversation 中创建成功后将新 Bot 加入收件人，保留草稿及原有收件人。首条消息仍是创建 Conversation 的时机。
- 沿用表单字段和校验、内置托管、自定义 Agent 的 AG-UI 连接测试，以及失败后的修正和重试。沿用创建者所有权、Personal 私有创建和应用默认规则，以及 Team 的私有默认值、公开/隔离权限、部署限制和应用授权。服务端继续执行适用的 Capability 检查。
- Chat 创建提案和 Bot 详情复制分别随所属功能迁移，沿用各自的批准或复制流程。每个后续批次盘点入口、深链、角色和常用工作流程，再迁移该批次的页面及共用组件。
- 按功能分批迁移全部 Web 页面。旧皮肤退出前，逐项核对四套皮肤的导航、专属页面和操作路径，为有对应功能的已有链接保留可用目的地。完成核对后移除旧皮肤和皮肤选择器。

## Testing Decisions

- 以浏览器上的真实 OpenBot Web 和隔离数据为主验收入口。断言用户可观察的导航、数据保存、权限拒绝、错误恢复、草稿保留、焦点和主题效果。复用 Bots 列表、Create Bot 弹层、新建 Conversation、旧链接与权限的现有回归测试。
- 从列表顶部、空态、现有快捷入口、旧深链和新建 Conversation 验证入口。实际创建后核对列表详情跳转及浏览器返回、会话收件人及草稿保留。覆盖字段错误、取消、提交失败和重试。
- 使用 Personal、Team 成员和 Team 管理员覆盖可见性和创建权限。验证 Team 成员公开创建被拒后能改为私有并重试，有权限的管理员在自定义连接失败后能修复连接并完成创建。
- 检查桌面和窄屏、默认与自定义部署品牌的浅色和深色外观。验收表单名称、键盘顺序、初始焦点、退出后焦点恢复、错误提示、对比度和窄屏溢出。由用户签收试点视觉。
- Web 类型检查、常规生产构建以及 Personal 和 Team 试点生产构建分别验证。后续批次沿用浏览器验收和构建检查。退役旧皮肤前用入口清单验证原有功能和深链去向。
- 试点已记录旧界面回归 59 项、试点回归 27 项通过，且上述构建与类型检查通过。Chromium 已验证列表和新建 Conversation 的实际创建、Team 权限拒绝及重试、自定义连接失败及重试、键盘焦点和窄屏深色弹层。Team 自定义品牌的强调按钮文字对比度为浅色 6.87:1、深色 13.24:1。

## Out of Scope

- 独立的原生客户端视觉改造和新业务功能。
- Bot API、数据模型、角色、Capability 或授权规则的重新设计。
- Bots 试点中的 Chat 创建提案、Bot 详情复制及其他 Web 页面视觉迁移。这些工作归入后续功能批次。

## Further Notes

- 设计依据为已接受的 ADR 0003《Pilot Astryx for OpenBot Web》。运行方式和部署品牌配置见《Astryx Bots preview》。
- Bots 试点已经实现并通过上述验证，视觉签收仍待用户完成。签收是启动其余功能批次的前置条件。生产环境按批次切换的方式待定。
