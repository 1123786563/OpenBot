# 套餐与积分页 — 设计稿差异分析与实现方案

> 设计稿来源：workbuddy.cn/profile/plans-usage（4 张截图，2026-10-11）
> 对照实现：`app/src/routes/_authed/settings/usage.tsx`、`invoices.tsx`

## 一、核心结论

设计稿的页面是 **「套餐与积分」**：以「积分」为唯一计量货币，页面由四个区块组成
（订阅计划 → 购买积分 → 平台奖励积分 → 积分消耗明细），外加一个「升级套餐」弹窗。

当前实现是 **「套餐用量」**：以 Lago 多资源计量（llm_tokens 等逐指标配额）为模型，
页面是 套餐卡 → 用量概览 → 趋势图 → 事件明细。

**两者不是同一套数据模型。** 当前系统（server + app）中不存在任何「积分/credit」概念；
数据库仅有 `billingCustomers / billingSubscriptions / billingWebhookEvents / paymentOrders / paymentEvents` 五张表。
因此这不是在现有页面上补组件，而是一次**信息架构 + 数据模型的对齐**。

## 二、逐区块差异清单

## 三、实现步骤与改动范围

### 阶段一：数据模型 + 只读接口（server，前置依赖）
1. **新表**（`server/src/db/schema/billing.ts` 增补 + 迁移）——**积分账本本地自建，Lago 只管订阅与计量原始事件**：
   - `creditGrants`：来源(plan/promo/signin)、总量、已用、发放时间、到期时间、状态
   - `creditLedger`：每笔积分消耗的本地账本（扣减明细，含时间/业务标题/请求ID/积分额/模型/使用端），消耗明细页直接读它
2. **只读接口**（`server/src/billing/` 新增 credits 模块，仿 statements.ts 的写法）：
   - `GET /api/billing/credits/summary` — 套餐基础积分 + 奖励积分汇总（可用 N 个·剩余 X）
   - `GET /api/billing/credits/grants` — 发放记录列表（含临期标记）
   - `GET /api/billing/credits/consumption?range=today|7d|30d&from&to&page` — 消耗明细
3. 套餐档位与价格：配置化（`config.ts` 仿 `LAGO_PLAN_ENTITLEMENTS` 增加 `PLAN_CATALOG`）

### 阶段二：页面重构（app，可先用 mock 走查视觉）
1. `usage.tsx` 重写为四区块：欢迎横幅 → 订阅计划 → 购买积分 → 平台奖励积分 → 积分消耗明细
2. 新组件（放 `components/billing/`）：
   - `WelcomeBanner`（横幅 + 角标 + 领取按钮）
   - `PlanCard`（套餐卡 + 升级按钮 + 兑换卡入口）
   - `CreditGrantList`（发放记录行 + 使用中 pill + 24h 过期红色提醒）
   - `ConsumptionTable`（今天/7天/30天 Tabs + 日期范围 + 导出 + 设计稿的五列）
   - `UpgradeDialog`（三档套餐 + 周期选择 + 套餐对比 + 扫码支付区）
3. `QuotaBar` 保留复用（积分进度条即同一形态）；`InvoiceStatusPill` 复用为「使用中」
4. i18n：`settings.json` 新增 creditsPage 段（zh/en）；侧边栏命名对齐

### 阶段三：交易链路（依赖支付，改动最大）
1. 升级/购买下单：`POST /api/billing/orders` 复用现有 `paymentOrders` + WeChat Native 扫码（payments 模块已支持 wechat provider）
2. 协议勾选门控扫码、支付回调刷新积分、到期自动续费文案（产品层规则）

### 8. 账单与发票页（补充截图）⚠️ 结构相似，列与头部不同
设计稿：标题「账单与发票」+ 副标题「查看管理您的支付历史记录」+ 右上黑底「开票管理」按钮；
表格八列：描述 / 类型 / 金额 / 日期 / 状态 / 订单号 / 时长 / 数量。
行示例：描述=平台奖励…、类型=购买、金额=0.00 CNY、状态=已完成、订单号=20260831…、时长=–、数量=1。

## 四、已确认的决策（2026-10-11）
1. ~~账单页设计稿~~ 已补（见第 8 节）。**「开票管理」不实现**：以最初需求第 4 条为准，移除发票相关内容，账单页不加「开票管理」入口。
2. **积分账本本地自建**：Lago 只管订阅与计量原始事件；阶段一用 `creditGrants`（发放）+ `creditLedger`（消耗）两张本地表。
3. **套餐价格配置化**：新增 `PLAN_CATALOG`（仿 `LAGO_PLAN_ENTITLEMENTS`），「写死」是其固定值的特例。
4. **「成长计划」「API 管理」不在本次范围**：只做「套餐与积分」+「账单与发票」两页，侧边栏不动。
