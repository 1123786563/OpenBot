## 首批验收记录

- PostgreSQL 验证了响应丢失后以相同请求标识恢复原 Conversation 和 Thread，以及两个管理员依据相同旧值提交 Permissions 变更时只有一次成功。异步审计记录改用限时等待实际写入，单项复验通过。
- 12 项首页与交接页回归验证了保留首条消息、复用创建请求标识、账号隔离和从首页恢复。Astryx 项目诊断通过 11 项，警告和失败均为 0。
- 在 390×844 Chromium 组件场景中，共用确认弹窗通过了默认焦点、Escape 取消、焦点返回、重复提交保护和部分失败重试检查。场景使用模拟写入响应。
- Vite 生产构建成功，Astryx 产物诊断通过 12 项。Chromium 使用该产物和模拟 API，在 1440×900 浅色及 390×844 深色通过了 People 停机确认和会话交接。会话交接模拟创建响应丢失，验证首条消息继续可见、刷新复用请求标识并进入同一个 Conversation。
- Impeccable 在桌面浅色生产页面的采样中标记了 People 的嵌套容器，以及会话交接错误状态的横幅间距、Bot 名称重复出现和嵌套容器。其余页面状态的渲染检测和可视化标记留待逐页验收。
- 直聊首发由浏览器持久化领取，多个标签页只能有一处发出请求。若页面在领取后、发出请求前退出，系统会检查原 Thread 并保留消息，供用户复制或确认丢弃。自动安全重试仍需服务端对首条消息的发送提供幂等保证。
- 当前工作区复验通过 15 项 Web 交接与恢复测试，以及 9 项运行、计量和审批测试。后端测试验证首条消息只触发一次运行和一次计量，并验证 AG-UI 的审批暂停和调用身份。模拟测试服务覆盖这些断言。真实模型的断线重连、同一首条消息重复提交和已批准的运行继续仍待端到端验证。

### 首次发送的 PostgreSQL 复验

独立 PostgreSQL 集成测试与 Web 交接测试共 34 项通过。群聊以同一个 UUID 并发重试创建与首发，恢复原 Conversation 和 Thread，记录一条用户消息，每个 Bot 按选择顺序执行一次。运行结束后再次发送同一条消息，仍只有原来的记录。OpenBot 直聊端点在两个服务副本同时接收同一消息时只执行一次，随后以不同的运行 ID 重发也会返回原结果。群聊审批测试覆盖回复途中暂停后续写原记录。审批收件箱已修复将列表索引返回为暂停原因的问题，回归验证同一 Thread 内两条拒绝记录都只返回实际拒绝原因。

以上使用可控 Bot 流验证 OpenBot 直聊端点和群聊服务。浏览器通过 Intelligence 网关发出首条消息时，断线后的安全重发及部署环境中的审批恢复仍待验收。

### 首批整改后复评

**设计判断。** People 在桌面把三个操作放在成员行内，窄屏把三个操作集中到行菜单。停机预览点名成员，说明影响本人和其 Bot 的电脑、可能中断工作以及磁盘保留。撤销访问失败后区分已移除访问与待完成的凭据退役。首发设计仍需走完整任务复评。当前对话样本覆盖打开状态和未找到草稿时的恢复路径。 [逐页 Nielsen 分与截图索引](web-impeccable-scorecard.md#首批整改复评)

**自动检测。** 生产构建 `6a0756d3f`（`index-CczWRu6D.js`）用本机 Chromium 和隔离 HTTP fixture 检查。矩阵包含 1440×900 与 390×844，各跑浅、深主题。Team 管理员用键盘取消停机、授予角色、处理移除访问的 503 部分完成及 409 冲突。取消后零写入且焦点回到触发器。连续确认只发出一次角色写入。Team 成员打开 People 时回首页。可访问性树记录对话框文本和结构。Astryx doctor 未报失败，Impeccable 源码扫描报告一条动画建议。A2UI 组件浏览器测试另行覆盖键盘、对比度、表单提交和 1440/390 宽度的截图。隔离 PostgreSQL 跑过 People 审计、SSO 影响和凭据用量。浏览器写入记录对应模拟请求，PostgreSQL 测试验证服务端数据库行为。 [复跑脚本](../scripts/browser-acceptance/first-batch.sh)

**待验。** Personal 与 Team 的真实首次发送、慢响应、掉线、重复提交、模型串流与审批续跑仍需已授权的账号、模型和 Bot。审批没有 TTL。用撤销、他处已决和工作被停验证等待结束后的行为。管理员的真实角色拒绝、跨浏览器读屏、实体触屏及使用真实部署串联的写入与 Audit 仍待验。群聊 Stop 已移除，待服务端支持安全停止后台执行。隔离 PostgreSQL 回归确认，两名管理员并发授予同一角色或撤销同一人的访问时只写一条对应的 Audit 记录。
