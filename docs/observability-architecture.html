OpenBot 日志与链路架构

统一 logger（pino JSON）+ 请求/链路关联 ID + Alloy 双路采集 + LGTM 自托管栈 ｜ 2026-10（P1–P3 已落地）

应用层 所有进程统一走 shared/logger + shared/trace

server（宿主机进程 :3001）中间件顺序：requestId → trace → accessLog
每请求一行 access log，x-request-id 回写响应头；出站调用（agent fetch / computer / supervisor）注入 traceparent
worker（宿主机进程）routines 清扫循环；sweep logger 注入（service=worker）；出站注入待接入
agent-bot / agent-computer / supervisor（容器）withTraceFetch 包装入站；supervisor 中间件在 Bearer 之前（401 也被跟踪）
每 Bot computer（supervisor 动态创建）OTEL 端点经 environmentFor 白名单转发；聊天链路的跨服务跳变点
runtime-go（容器）TraceMiddleware 挂链最外层 + callback 出站注入；与 Bun 侧 off/端点语义逐字对齐
共享模块：shared/logger.ts（pino，service 基字段，LOG_LEVEL，TTY pretty / JSON 单行）＋ shared/trace.ts（W3C traceparent 解析/注入，initProcessTracing，OPENBOT_TRACES=off 总开关）。日志字段：service / request_id / trace_id / method / path / status / duration_ms / msg。Biome noConsole 上锁 server/src 与 worker/src。

一次请求的完整足迹：客户端 → server（requestId 生成/复用，trace span 开启，access log 落盘）→ 出站注入 traceparent → 容器服务续接同一 trace → 日志经 Alloy ~4 秒入 Loki、span 批量入 Tempo → Grafana 中按 request_id 搜日志，点 trace_id 跳瀑布图。
两条不变式：① stdout 永远是事实源（观测栈只是搬运工，停机不影响排障）；② 未配置端点时各进程 recording-only（span/日志照常产生，只是不导出），OPENBOT_TRACES=off 可整体关闭。
