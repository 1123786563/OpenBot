# Spec：吸收 OpenBot 上游能力并保留 OpenMuse 治理边界

日期：2026-10-20。状态：**用户于 2026-10-20 确认“采用”详细设计、测试边界和 12 张业务票拆分，授权发布 Issues；尚未启动代码实施或生产上线**。

来源：用户连续要求比较上游、制定详细更新方案、细化改造计划，并在本轮要求详细设计、拆为具体 Issue 及提供其他 Code Agent 的执行提示词。本设计综合现有讨论，不扩大为全量上游合并。

本地规划基线 `3b4a7c68132c3507300408346a44fb9d56f3c14c`；上游基线 `e8bb27368ff436958b614292ae91283e51d5a813`。实际实施必须重新核验 HEAD、现有用户修改和已集成交付。当前状态不是“计划已实现”。

## Problem Statement

本地已扩展公司/团队、个人与公司 Payer、Craft、个人记忆及模型治理，上游同时持续改善安全边界、网页研究、连接引导与 Computer 体验。整分支同步会触碰已批准的 Hindsight、KB 移除及 Mastra 方向；仅按目录差异判断则会把本地已有移动端、记忆镜像和 Learning 误列为缺失。

用户需要能逐项交付和回滚的更新：保留自己的授权、费用和业务数据，吸收有价值的上游行为，并使另一名 Code Agent 能按稳定验收独立执行。

## Solution

以现有产品行为为入口，移植独立安全补丁，改进对话中的看屏与连接体验，完成密码之后的验证码交互，并让可选研究供应商共享同一套授权和审计。实施保持普通聊天与已配置服务兼容；架构及客户端差距单独输出决策，避免在功能更新中同时迁移执行框架。

交付为父 Spec + 12 张业务 Issue。前后端/数据库拆分保留在 Issue 内的实施 Task 中，每张业务 Issue 自身能演示或验收完整结果。首次执行先核验范围和事实源；已由其他工作实现的要求提供同版本证据后消项。

## User Stories

1. 作为部署维护者，我希望无 hostname 的地址不能启用无登录访问，以便配置错误不被当成可信私网。
2. 作为本地用户，我希望合法 localhost/私网部署继续可用，以便升级不阻断原使用方式。
3. 作为维护者，我希望导出的 shell 事件不带参数中的秘密，以便收集器不成为凭据副本。
4. 作为审计使用者，我希望脱敏后仍能理解命令与对应动作，以便定位执行结果。
5. 作为邮件触发用户，我希望非 UTF-8 邮件按声明编码读取，以便 Bot 不误解正文。
6. 作为邮件触发用户，我希望 HTML-only 邮件显示原字符，以便转义符不影响任务理解。
7. 作为例程使用者，我希望重复分钟只描述一次，以便理解实际运行时间。
8. 作为对话用户，我希望只有实际屏幕操作才自动显示电脑，以便文件或 shell 操作不抢占面板。
9. 作为用户，我希望被拒绝动作撤销其自动开屏，以便不看到没有动作发生的静止屏幕。
10. 作为用户，我希望手动面板、设置和 Workshop 优先，以便 Bot 不打断自己的操作。
11. 作为用户，我希望直接在当前对话连接 Bot 需要的个人应用，以便保留原问题。
12. 作为用户，我希望授权完成以服务端有效连接为准，以便取消或撤权不会被显示成功。
13. 作为用户，我希望授权后自己决定是否再次发起任务，以便写操作不被自动重放。
14. 作为用户，我希望相邻工具活动汇总且可展开，以便理解过程并查看原始结果。
15. 作为用户，我希望审批、连接要求和人工介入保持可见，以便及时做决定。
16. 作为用户，我希望先提交密码，网站确实需要时再提交验证码，以便不预先索要尚未生成的 code。
17. 作为用户，我希望密码/code 只在私有表单与受控电脑之间流转，以便模型与日志不接触秘密。
18. 作为用户，我希望错误、过期或结果不明的登录有明确处理方式，以便不会被误告知成功或自动重复提交。
19. 作为管理员，我希望启动时得到有限时长的模型/可选服务诊断，以便提前排查配置。
20. 作为未启用学习的维护者，我希望缺少 Intelligence 时不会因新增诊断改变已有依赖边界。
21. 作为研究用户，我希望 Parallel、Exa、Firecrawl 具备一致的搜索/读取角色，以便技能不绑定某一家工具名。
22. 作为资源所有者，我希望新 provider 只在现有授权内调用，以便费用、撤权和工具权限仍有效。
23. 作为公司成员，我希望切公司/团队后的延迟响应不改变当前界面或操作其他范围资源。
24. 作为维护者，我希望每批有验证、Review 和回滚证据，以便独立决定发布。
25. 作为架构维护者，我希望移动端/harness/toolkit 的差距与现有计划去重，以便避免重复客户端或执行权威。

## Implementation Decisions

### 1. 采用边界与权威

- 按功能适配已有模块，保留 OpenBot 身份、公司/团队范围、Run/Attempt、审批、副作用、预算、Payer 和结算权威。
- 新功能沿用批准的全局身份/个人账户例外；不为账户引导擅自新增 tenant 归属。涉及 Bot 的访问仍以当前授权为准。
- 个人记忆沿已批准 Hindsight 路线，保留本人审核、遗忘和来源权限；不重新恢复 KB，也不建立第二套长期记忆权威。
- Mastra 执行迁移维持自己的已批准范围。本次不将上游 toolkit 作为新强制依赖。
- 已有能力分别记为已有、需补边界或待证据；有页面、有接口、有运行证据是三种不同状态。

### 2. 安全、邮件与调度

- single-user 地址分类先解析并归一 hostname；hostname 为空视为不可接受的公开/未知地址，不能按无点单标签名识别成私网。
- 参数脱敏以具体命令语义识别 docker login、sshpass、redis-cli、mysql 和 curl 等上游覆盖形态；保留现有 token、header、JSON、URL 脱敏。
- 本次针对导出数据的新增保障，不承诺追溯修复历史日志，也不将任意 shell 语法净化视为可完全保证。
- MIME 每个 part 先 transfer decoding，再按自己的 charset 解码；未知 charset 回落 UTF-8。plain text 不做 HTML entity 解码。
- HTML-only 正文沿既有去标签流程后解码一次字符引用，不把双层引用递归还原。调度只去重可描述的分钟集合，不改变 next occurrence。

### 3. 看屏与工具活动

- 浏览器显示动作使用明确路径集合产生活动公告；文件、shell 和未知请求不据猜测开屏。
- 每次公告具有独立标识，拒绝只撤回相同标识打开的面板；保留手动面板和已显示有效动作。
- 网络失败、500 和取消不证明外部没有执行，因此不能直接按“未执行”撤回或重发。
- 保留现有 10 秒静默 epoch 启发式，不把它宣传成精确服务器 runId；用户关闭后抑制在该 epoch 内生效。
- 相邻可普通展示的 connector/browser 工具聚合；文本、审批、连接要求和人工介入形成边界。保留步骤原始参数与结果、失败/拒绝分类和稳定组 ID。

### 4. 对话连接闭环

- 服务端以现有拒绝结果携带结构化连接提示；提示仅用于展示，不能作为授权依据或向任意 origin 导航的来源。
- 只对个人可自助连接的账户缺失/断开/撤销给出连接引导。缺 Bot grant、管理员配置、共享账户不改写为“请个人连接”。
- 卡片复用现有 connect endpoint，服务端重新验证身份与当前权限。点击时预占新 tab，得到授权地址后导航并切断 opener；弹窗受阻提供明确退路。
- 只在等待期间每 2 秒轮询本人连接，最长 5 分钟；以未撤销有效记录为成功依据，不以返回页面/窗口关闭为成功。
- key 模式进入原有设置页面；连接成功后提示再次发起，不重放原工具。切换范围或卸载时停止旧请求对当前 UI 的影响。

### 5. 密码后验证码

- 初次密码提交不再询问/输入验证码，旧客户端随密码携带的 code 被忽略。Computer 报告实际出现验证码字段后，请求进入 code_required。
- 新增私有验证码提交入口，沿用原登录的 owner、请求有效期、Bot 范围、origin、服务认证与人工控制屏障。验证码不成为模型工具参数。
- 只有 code_required 可领取验证码执行 lease；采用条件状态更新防止并发领取，同一请求的并发失败返回 409。
- 状态链为 pending→filling→code_required→filling→signed_in；明确错误 code 返回 code_required，回密码页返回 pending，取消/到期保持终态。
- 已发出动作但响应无法确认、或执行 lease 过期，进入 failed 并说明结果不明；不自动重发，不声称登录成功。用户可检查/接管，或在了解不确定性后发起新请求。
- 迟到响应不能覆盖取消/过期、保存密码或恢复 Agent。code_required 不是终态，不恢复挂起对话；终态恢复复用现有机制。
- 验证码不落库、不进日志/追踪/聊天。仅本人明确选择保存的密码进入现有加密 vault；表单提交/取消/卸载清理秘密及 mutation variables。
- 数据库只扩展合法状态，不复制上游迁移编号；按本地 journal 分配。发布顺序为 schema→兼容 Computer→API→UI，新入口最后开放。
- 回滚前停止新请求并排空/终结 code_required、在途 filling，保留扩展 schema 后回滚应用；不承诺所有新旧组件任意混搭。

### 6. 可选启动诊断

- 启动诊断 3 秒预算、取消支持的网络操作、只报告一次分类结果；失败不抛回阻断启动。
- 模型检查只使用允许的官方元数据或已批准网关 metadata；兼容服务无 lookup 则 skipped，不用其 404 判断模型不存在。
- 不为探测绕过虚拟 Key、创建推理 token 调用或扩大供应商权限。
- entitlement 仅针对实际启用的可选学习依赖；不改变当前未启用 Intelligence 的部署契约，也不把诊断当授权事实。

### 7. 研究 provider

- 逻辑角色为 search/fetch，声明与实际工具授权求交；原 Parallel 真实 ref 保持兼容。
- 增加 Exa/Firecrawl 的固定 reviewed HTTPS catalogue、认证 header 与明确工具分类；header、URL 由服务配置约束，不信任 caller 自定义。
- 只读是权限分类，不代表免费；未知工具和会启动任务/改变远端状态的能力不因 provider 名而降为 read。
- 复用 MCP、egress、凭据、授权、预算与审计，不为失败自动换供应商。缺 key、撤权、超时、政策拒绝分别显示真实结果。
- 供应商 credits 与本地模型 token 计费边界保持清楚；不凭空把外部 API credits 写为 token，也不重复现有计量。
- 不默认启用新 provider 或后台研究。真实来源 URL 保留，摘要页面数量只取实际结果。

### 8. 分批与后续范围

- 先独立安全/正确性，再体验，再协调登录升级，再可选研究/诊断；调度默认串行，共享文件随任务集成。
- harness/mobile/toolkit 交付比较与采用/延期结论。已有 OpenMuse mobile 为唯一现有移动产品，不能因根目录没有 mobile 就复制第二套。
- 父 Issue 承载整体验收；子 Issue 承载业务闭环；更细的前后端和 migration Task 在实施计划内执行。

## Testing Decisions

首选现有高层公共 seam，避免测试复制实现：配置加载；真实审计事件到本地 OTLP collector；真实 SNS/MIME 抽取到 trigger 内容；用户可见屏幕/卡片/摘要；私有登录 API→受控浏览器页面；技能选择→真实授权工具集合→模拟 MCP；应用启动装配。

- 沿用仓库现有 config、enterprise-controls、责任触发、Routine、Computer、plugin connect、passwords、MCP 授权等测试先例。新增 suite 按 ADR 0008 归 native/driven，实际运行须可对账。
- 逻辑函数测试补最小边界；功能通过须有公共接口或浏览器行为证据，不以新增函数存在当验收。
- 两公司/同公司两团队、撤权、切换期间迟到响应、个人/公司 Payer、重启/取消/超时均覆盖对应变化。
- OAuth/MCP/数据库真实联调缺环境时说明 blocked；全 skip、只 mock 合约或无 report 不算实际服务验收通过。
- 每业务票独立 Spec + quality Review；最终全范围 OCR 后核实有效 finding，按编号修复计划循环复审。
- 密码/code、真实 key 和授权 URL 不保存到测试报告；fixture 采用明确虚构值。

用户于 2026-10-20 采用设计时确认上述测试边界。当前只做文档静态检查，未执行产品测试或实际联调。
