# 个人与小型企业 Agent 长任务生命周期规格

状态：**评审草案 v0.4；已接入个人/小型企业产品规划，新增详细方案未整体批准**。

日期：2026-10-16。

来源：用户指出当前企业个人 Agent 设计缺少跨几天、几个月任务的支持，要求在现有设计讨论中补足。本文为新增产品方案，不表示已经批准具体行为、技术选型、实施或发布。

v0.2 文档复核：明确 LT08 的“一个逻辑推进意图”与队列重复投递/合法恢复重试的区别，保留业务步骤和外部效果的去重要求。个人用户的完整业务范围和付款仍待主规格 C07 冻结，本文不以长期 Task 绕过该前置。

v0.3 规划衔接：用户要求纳入个人/小型企业规划，已将三类业务流程、运行就绪、自助恢复、费用展示、项目与数据退出接入[产品规划](2026-10-16-personal-smb-product-roadmap.md)。个人范围与完整任务付款采用 G01/提议 ADR 0007 的书面方案，评审和准入前置仍保留。

v0.4 审核修订：按用户要求区分固定业务归属与版本化工作范围，明确计划/委托变更使旧提案失效、合法跨轮恢复保持操作身份；正常环境回收可安全重建，离职交接使用新的关联 Task。新增 L13–L16，对应主规格 A58–A61；仅修订文档，不表示新增方案已整体批准或通过运行验证。

## 2. 产品模型与范围

推荐把长任务作为现有 Task 的生命周期能力，不新增第六种任务类型。一个 `agent`、`document`、`finance`、`plan` 或 `monitor` 任务可以跨日存活；是否跨月取决于其期限、计划、等待和续期规则。

| 方式 | 适用性与取舍 |
| --- | --- |
| 持续延长同一 Run 的超时和进程寿命 | 无法独立解决等待、凭据到期、进程丢失、成本及版本变化，不作为长期任务模型。 |
| 只周期重跑同一条指令 | 适合独立的定时产物；缺少累计进度、前置条件和结项规则，不能代表所有长期业务工作。 |
| Task 持久保存计划、证据和等待，多轮有界推进 | 本稿推荐。每轮重验权限并生成明确结果；等待时释放资源，按已保存的条件继续同一任务。 |

长期项目与持续职责仍分别表达：Task 有具体成果与验收，Responsibility 定义长期关注范围，Routine 定义触发时间，Monitor 观察条件，Goal/Milestone 跟踪业务目标。Responsibility 或 Routine 可以请求推进一个 Task，但不能形成第二个 Task 状态所有者。同一 Task 不能被两个调度入口各推进一次。

首版设计覆盖跨日等待、数周分阶段推进及跨月周期检查。开放式持续职责允许存在，但每轮执行许可和预算须有界，到期进入续期流程，不承诺永久无人关注的自动执行。

## 3. 用户可见合同与时间边界

创建时至少明确：目标与验收、范围与负责人、预计持续时间或业务截止日、阶段及依赖、等待条件、复查频率、单轮执行限制、授权有效期、累计与周期预算、状态汇报频率、停滞处理及完成条件。简单任务使用默认有界执行，不要求所有员工填写长期项目表单；识别出跨日等待或反复推进需求时，须让本人看见长期工作安排。

| 时间概念 | 产品规则 |
| --- | --- |
| 业务持续时间/截止日 | 任务可以存活几天或数月。到截止日仍未完成，标明逾期并暂停未获延期的新增业务动作，等待本人延长或结束；原有回执核对与费用责任继续。 |
| 单轮执行时限 | 每次唤醒只执行有限时间、步骤和成本的工作。保持原有有界执行保证，不能把 300 秒简单改成几个月。新限制需按能力验证。 |
| 执行租约 | 仅保护当前领取的一轮工作，随执行结束、失效或安全停车释放；不是任务的业务寿命或长期授权。 |
| 等待期限与下次检查 | 表示何时可再检查、等待谁/什么、最晚何时提醒或升级。等待几天不消耗几天的 Worker 槽位，也不保持模型会话或浏览器进程不断开。 |
| 委托与连接有效期 | 可以早于业务截止日。到期后保留任务和进度，阻止后续业务执行并要求续期/重新连接；任务没有失败重建的必要。 |
| 审批有效期 | 每个具体外部操作按其提案期限、计划/委托版本、参数、目标和连接代次判断；任务续期不自动延长原审批。沿用原动作有效期，等待跨日不延长提案；到期后按当前计划重新提案。 |

默认无需员工在线保持会话。后台使用有效、可撤销的业务委托及当前授权资格，不保存或模拟员工的过期登录会话。

个人用户和小团队按产品规划 G05 明确实际执行位置：托管侧继续工作的条件、自托管 Worker/存储/环境就绪、本地设备休眠或断网影响分别显示。等待时释放计算槽位不等于没有存储/扫描/通知成本；自助恢复按有效资格和安全状态处理，不把未知外部动作变为可重发。

## 4. 分阶段推进和计划变更

LT01：同一个长期 Task 保留稳定任务标识及不可变业务归属：范围类别、个人空间或公司/执行团队、请求人/所属人、Bot 身份和付款账户。可版本化的是该归属内的目标、验收、获准工作范围及计划；“工作范围”指来源、动作、目标与成果，不允许编辑归属字段。确需更换归属时按主规格 P03a 和交接合同创建关联 Task，重新授权与确定付款，原操作及费用留在原任务。阶段具有明确结果、前置条件、输入来源、预计完成或复查时间、预算边界及交付证据。阶段属于 Task 计划，不自动等同于 Goal 的 Milestone，不自动修改其完成状态。

LT02：阶段可以由多个有界执行轮次完成；每次执行记录所属计划版本、阶段、轮次及操作回执。一次 Run 成功只能证明本轮工作结果，不能直接结束整个长期 Task。最终成功要求预先约定的全部必要成果及证据齐备，不以“没有下一步”或“已经运行很久”认定完成。

LT03：阶段或任务存在依赖时，只推进已满足当前验收/证据条件的工作。外部效果未知时暂停依赖该效果的推进；相互独立的部分是否继续，须由已授权计划明确，不能自行绕过阻塞或创建同义任务重复发送。

LT04：Agent 可以提出更新计划的建议。改变目标、工作范围、外部动作、验收、截止日、累计预算或委托上限必须本人重新确认，并按组织政策审批；确认不允许改变 LT01 的业务归属。既有权限内的步骤细化也须保留计划版本和变更理由。已完成事实和回执不被改写为新计划的未执行步骤。输入变化使旧产物失效时，标记受影响的阶段并重新验证，不删除历史证据。

计划/委托版本变化与操作准入遵循主规格 §8.3：首版使该 Task 旧版本未消费提案失效，需要的动作按新版本重审；删除阶段后，旧卡片即使参数未变也不能新取得执行许可。旧等待记录失效后，在新版本为仍需等待的条件重新登记有效等待，并沿用已观察事实/游标及未决操作引用，不通过重发动作重建等待。仅更换 Worker/恢复 Run 且计划、委托及其余绑定未变时，可以在原期限内原子消费同一未消费提案，分别记录来源 Run 与消费 Run。已 claim 或结果未知的操作只能核对，不能因改版或恢复重置。变更、批准、claim 与发送并发须验证一致性边界。

首版采用既有 Task/Plan 及步骤表达；如需要独立子任务，仍归同一 Task 模块拥有，明确父子关系、依赖、取消和结果汇总。不能默认无限递归拆分，也不通过子任务复制预算、转授身份或增加隐含调度所有者。

## 5. 等待、唤醒与资源释放

LT05：等待须持久保存原因、关联阶段、确切的事件/对象或时间条件、最近观察游标、下一检查时间、截止/超时策略及通知去重标识。支持等待时间、外部状态、其他任务、本人输入和具体操作审核；等待授权续期、预算及结果核对须显示不同阻塞原因。它们是 Task 的等待/阻塞信息，不把模型正在输出的状态保留几个月。

LT06：等待期间释放当前 Worker 领取和运行租约，按环境生命周期回收空闲 Computer；需要后续恢复的文件/产物保存到已授权的持久存储，并记录是否安全停车、检查点版本及未决操作。正常回收按 LT11 在原范围重建，旧环境控制权失效不等于 Task 必须人工恢复。不能把已确认的外部操作重做一遍来恢复页面。当前一轮若不能在时限内安全停在持久检查点，应记录可恢复中断或待核对，不能宣称已可靠进入等待。

LT07：唤醒通过持久时间条件、已认证事件、已验证外部观察或本人操作进入权威任务命令。登记等待与登记/发出下次唤醒须具备一致性和补偿恢复路径；事件早于订阅登记、重复到达、乱序或丢失回执不能导致永久沉睡或重复推进。定期扫描查找已到期但未推进的等待，扫描只发现候选，不绕过权限、去重或执行租约。

LT08：每个唤醒绑定 Task、计划/阶段、等待记录及观测/事件标识，原子确认当前等待仍有效，并只创建一个逻辑推进意图。队列可重复投递或按原合同恢复重试；以原子领取、有效代次及检查点确认保护阶段推进，不把重复消息当作新业务请求，也不承诺物理消息只投递一次。旧计划的迟到事件、已取消等待、已消费的人类输入或重复提醒不能继续旧流程；外部效果未知仍暂停核对。具体 CAS/Outbox/游标结构由实施合同冻结，复用现有队列的领取租约，不新增竞争租约系统。

本稿不自动把任意 Webhook 或业务事件接入提升为已批准首版能力。既有允许的定时重查、本人提交和已认证事件入口可以提供唤醒；新增供应商事件源、扫描范围、频率和数据出口须按原分期和领域合同处理。长期等待能力不等于已经实现所有事件连接器。

## 6. 工作状态、检查点与恢复

LT09：Task 保存可恢复的工作记录：当前目标/计划版本、已完成及未完成阶段、决策和变更理由、来源引用与版本、输入答案、待办与下一动作、操作/回执和产物引用、等待条件、有效委托和预算引用、运行/环境兼容信息及最后成功推进时间。只保存必要的凭据引用和可公开执行说明，不持久化供应商密钥或模型思维链。每轮结束或进入等待前形成持久检查点；更新任务状态和登记下一动作的关系必须可核对。

LT10：用于恢复的摘要应简短并能定位原始依据，不能只保存模型自由叙述的“我做到了哪里”。不可丢失的业务事实、精确计算输入、最终操作参数和回执独立保存。每次恢复加载当前阶段需要的有权资料，不把数月全部聊天无限追加进上下文。

这些工作记录用于继续同一个获授权 Task，不自动成为个人记忆或团队共享技能；候选记忆审核规则仍然有效。Task 记录及摘要继承公司、团队、本人、Bot 和来源限制，不能用“工作记忆”绕过 Hindsight/精确 ID 记忆的授权或遗忘规则。来源撤权、删除或保留到期后，先阻断受影响内容及派生上下文，停止相关推进或基于剩余有权依据恢复。

LT11：重启或灾难恢复后，先重放撤权、遗忘、取消和操作结果事实，再重建任务视图、重新授权及恢复唤醒。恢复区分以下情形，不从头重跑全部步骤：

| 情形 | 恢复行为 |
| --- | --- |
| 已安全停车后正常回收，检查点持久且兼容、无未决副作用 | 当前资格、委托、预算及连接仍有效时，可在原业务范围自动建立新环境并加载有权文件/检查点，签发新代次控制票据；不要求仅因环境回收而人工确认。不需要 Computer 的阶段也无需恢复旧浏览器。 |
| 环境意外丢失，但可证明检查点兼容且无未决副作用 | 按现有有界恢复策略重新领取并重建；保留丢失/恢复记录，不能恢复旧控制票据或重放已完成动作。 |
| 缺少必要连接/登录授权，或当前资格/委托/预算不足 | 显示相应阻塞，等待有资格主体补充；新建环境不代表重获供应商登录态，不模拟过期会话或借用其他范围连接。 |
| 检查点与当前计划不匹配且无已验证迁移，或不能排除未决副作用 | 暂停受影响推进，进入有明确原因的迁移处理/核对；原操作确认前不可重发，不能凭环境重建宣布失败或成功。 |

所有恢复均拒绝旧环境代次的控制命令和重连票据；环境相关 Policy 决定须重新判断。Reviewed action 按主规格 §8.3 校验其独立绑定，正常环境重建不延长审批、不改变连接代次规则，也不解除人工接管后的显式交还要求。

LT12：Task 的 Bot 身份保持固定，每轮固定本轮 Bot 配置、模型/工具/技能及计划版本。跨月期间可以通过有记录的兼容性检查迁移到受支持的新配置版本，并记录后续 Run 使用的版本，不改写旧 Run；更换 Bot 身份须建立另一个获授权关联任务。安全政策收紧立即约束新动作，不能因旧版本被固定而保留失效许可。不得静默解析 `latest`；无法证明检查点兼容时暂停，保存旧成果，按批准后的迁移或重规划继续。

## 7. 授权续期、预算与异常处理

LT13：业务期限、委托期限和凭据期限独立。到期前在任务视图提示谁应续期、下一动作及其影响；提醒频率有上限且可去重。到期后进入待授权，不自动续期授权、不借其他人的身份继续，也不丢失任务。续期只能由当前有资格主体显式确认，公司/团队限制继续有效，不能复活已消费或失效审批。

LT14：长期 Task 有累计成本上限和适用的周期/阶段/单轮上限，判定时纳入已结算、已承诺未结算及其他应计责任。周期开始不是新的累计额度；拆成子任务、重试或更换模型不能重置累计限制。周期归属按准入事实固定，迟到结算不能把费用挪到另一周期掩盖超限。后台检查、模型总结、监控轮询、失败重试和通知相关费用均进入明确的费用归属；平台承担的个人记忆处理保持单独合同。

LT15：任务预算是消费限制，不是一开始冻结三个月预计消费的供应商预留，也不保证将来余额可用。每次实际付费尝试前按原付款账户执行原子预留，未知费用继续占用，不能因等待、跨月、暂停或到期自动释放。新一轮余额不足时保留任务并展示待预算；扩大限额、变更截止日或新增周期规则必须经过相应确认，不静默改扣个人余额。

以上不免除已批准的异步作业准入要求：若某次提交本身承诺一个长期供应商作业，提交前仍须预留该作业可强制的完整成本上限。不能把已承诺的单个作业拆成未来轮次，以少预留的方式绕过严格计费。

LT16：暂时故障采用有界退避与重试，记录下次检查和最大尝试/总时限；长时间无进展、重复相同失败、输入过期、委托到期或即将逾期须有提醒和处理责任人。用户能选择补充资料、调整计划/期限、继续等待、暂停或结束；默认到期/到达限制后不继续无人关注的付费尝试，不自动把长期等待标记为成功。正常等待外部条件与系统未调度必须分别显示。

负责人离职或失去团队资格后，沿用主规格停止其工作；交接仅转交有权正式成果和清晰的未完成事项。继任者在自己的合法范围创建新的关联 Task、确认委托及付款，不接管原私人 Task、不复制其完整检查点或继承凭据。原 Task 停止新增业务动作，保留受限核对、审计及结算责任，历史操作、范围、发起人及付款事实不被改写。交接关系须关联未决操作，仅向继任者提供有权的阻塞说明及核对结论；原操作未知时阻止新任务中重复或依赖该效果的动作。确认已完成后承接后续事项，确认未发送后才可在新任务下重新提案，不能通过更换任务绕过核对。

## 8. 进度、暂停、取消与结项

任务详情至少呈现目标与截止日、当前计划版本、阶段/成果、最新事实和时间、当前等待原因、等待谁/什么、下次检查、最后成功推进、授权到期、预算与待结算、风险及可用控制。无法定义真实完成比例时显示阶段成果和剩余工作，不编造百分比。本人可以要求有限频率的摘要或只接收关键变化；静默时段不掩盖到期和风险。

暂停阻止后续自动推进，保留等待和证据，明确当前轮何时安全停下。恢复后重新授权、重验外部条件和资料版本，再重新计算下一次合法检查；不补做所有历史遗漏的敏感操作。取消阻止父任务及其所拥有阶段/子任务的新唤醒，向当前执行发出取消请求并保存部分成果；独立业务对象通过其领域命令处理，不能直接改其他域的状态。

结项至少区分目标完成、未完成结束/取消和失败，结果未知及未决费用分别可见。完成保留验收证据，未完成结束保留差距；任何结项都不删除审计、外部效果和既有费用责任。已成功/已取消任务不因迟到事件重新打开；新增业务需求创建关联任务并重新授权，不能把旧许可当作新委托。

本节是目标产品行为。公开 Task 状态、阻塞原因、等待记录和控制转换须在实施前扩展/映射现有严格合同；不能仅增加一个 UI 标签，就宣称当前 `waiting_approval`、任意 Plan 步骤等待或长期续期已接线。

## 9. 代表性业务场景

以下时间为验收场景，不是产品默认期限或授权默认值。

| 场景 | 跨期推进与验收重点 |
| --- | --- |
| 10 天收集并比较供应商方案 | 保存比较标准和已收资料；等待反馈时不占 Worker；新资料唤醒后去重、验证来源并更新阶段成果；提醒或对外跟进须逐次满足审批，不能用创建任务替代发信批准。 |
| 90 天准备季度审查材料 | 每周在许可范围内更新资料清单，保存来源及变更；委托早于项目到期时暂停待续期；每个阶段留存成果，输入版本变化时重新验证；最终成稿经约定验收后结项，不自动完成所关联 Goal。 |
| 数月监测条件并在满足时提出行动 | 周期检查保存游标、观察去重和累计成本；条件满足只生成约定建议或待审提案；重复观察不重复发出行动。达到授权/预算/业务期限时停下，除非取得相应延期。 |

## 10. 验收与验证方式

| ID | 场景与通过条件 |
| --- | --- |
| L01 | 同一 Task 经多次有界 Run 跨 10 天推进并保留稳定身份；关闭客户端、停止 Worker 后恢复仍有正确阶段和证据，单轮超时不会被解释为业务期限到期。 |
| L02 | 测试时钟跨 90 天、跨月和业务截止日，正确区分检查时间、截止日、时区、执行租约和授权到期；资料与结果不因跨月清零。 |
| L03 | 等待数日时无持续领取、模型请求或浏览器保活；重启后到期扫描补发现未调度工作，只生成一次有效推进，不形成紧密循环。 |
| L04 | 事件早于等待登记、重复/乱序、登记后进程崩溃、唤醒投递丢失及过期计划回调均能收敛；旧计划、取消任务及已消费输入不会复活或重复推进。 |
| L05 | 明确展示等待时间、外部资料、输入、审批、授权、预算和结果核对等原因；合法下一动作与允许的状态转换一致，不能用保留状态名伪装已接线。 |
| L06 | 委托早于项目截止日到期，任务保留但后续业务停止；续期重新确认工作范围并重验成员，不改变业务归属；旧委托版本的审批、已失效连接及旧环境控制票据不能继续使用，仍有效连接按原范围重验。 |
| L07 | 多轮/子任务/重试/跨周期调用同时满足累计、周期、阶段和单轮上限；并发未结算责任计入；无全期供应商冻结或到期自动释放，余额不足不换付款方。 |
| L08 | 工作摘要能定位原始证据；来源撤权/遗忘后旧摘要、备份恢复和缓存均不能复活内容；恢复不依赖数月完整聊天或将工作记录自动变为个人记忆。 |
| L09 | Plan 中间阶段可持久等待及继续，已确认外部效果不重放；资料更新使产物失效时保留旧证据并重新验证；计划变更不改写已完成回执或自动改 Goal/Milestone。 |
| L10 | Bot/工具/模型/检查点版本升级须记录兼容性结果；旧政策不保留失效权限，不静默换 latest；不兼容则暂停并保存成果。 |
| L11 | 暂停、取消、到期、离职、人工接管及迟到回复并发时，阻止后续不合法唤醒，保留部分成果和核对责任；成功/取消终态不被迟到事件重开。 |
| L12 | 停滞、授权临近到期、预算不足、截止日与通知失败均有可见原因和处理人；告警/摘要去重，通知重试不重做业务；三种代表场景都取得端到端结果和费用证据。 |
| L13 | 计划编辑、续期、重新确认不能将个人 Task 转到公司、团队 A 转到 B、变更所有者/Bot 身份或付款；合法关联 Task 重新授权，原操作/审批/费用不随新任务移动。 |
| L14 | 删除阶段或计划/委托改版与批准、claim、发送并发时，旧提案不得在变更生效后新准入；纯跨 Run 恢复在有效期内只消费原操作一次，过期则重审，已 claim/未知结果只核对；新计划重建等待不丢观察事实、不重发业务动作。 |
| L15 | 纯读取任务安全等待一周期间回收 Computer，唤醒后自动在原范围重建并继续；全部旧控制票据拒绝。发送结果未知、检查点不兼容及连接失效分别进入核对、迁移处理和待连接，不以重建环境绕过。 |
| L16 | 员工离职且原邮件发送结果未知时，继任者的新关联 Task 无法重发或推进依赖步骤；合法核对结论驱动后续决定，私人历史/完整检查点不可见，原费用仍向原付款账户结算。 |

时间跨度通过可控测试时钟、真实持久化和进程重启/租约丢失故障注入验证；权限和外部操作仍使用既定真实授权入口、受限数据库角色及供应商隔离账号。时间加速不代表实测连续运行 90 天，也不能替代供应商幂等/未知结果和恢复证据。运行耐久性、保留和容量另按约定观测窗口提供证据。

等待任务仍占业务对象/活跃任务额度，虽不占计算槽位，也不能忽略数量上限、索引、定时扫描、事件积压和保留成本。原自托管部署每用户活跃任务数及 Worker/Computer 规划限制继续有效，调整需有审核和容量证据。
