### 1.2 设计取向

采用“员工在公司内的持续个人工作入口”：复用既有 Bot、会话、任务、职责和工具领域，统一展示该员工的工作与授权，不要求新建一个万能运行时。

首次进入按原合同幂等创建该用户的逻辑私有 OpenMuse Bot，使用受管理模板；公司和团队切换保留逻辑身份，实际 Computer、浏览器配置和工作目录按 §4.1 隔离。模板更新公共安全配置及能力授权时保留用户可编辑字段，并展示相应差异；公司/团队配置和含业务内容的角色描述、提示词及偏好仍在所属范围解析，不能混入全局可变配置。入口中可见某个团队 Bot 不等于该 Bot 获得私有 Bot 的个人工具。

各公司入口展示当前授权范围内的个人工作。逻辑私有 Bot 身份可以保持稳定，公司间的业务上下文、配置、凭据和费用仍分别管理；跨公司身份关联本身不开放业务访问。入口是否需要新增持久化实体由后续模型设计决定。

## 2. 产品目标、用户与成功定义

企业个人 Agent 帮助员工在当前有权的公司及团队范围内理解信息、准备工作、执行明确授权的操作，并持续跟踪结果。员工可以离开聊天页面，随后回来查看真实进度、处理审批或接管任务。

| 使用者 | 要解决的问题 | 可观察的成功结果 |
| --- | --- | --- |
| 员工 | 信息分散、重复准备、待办遗漏，不清楚 Agent 做到了哪一步。 | 能找到依据、取得产物、确认实际执行结果，并随时暂停或撤销委托。 |
| 团队负责人 | 提供团队公共能力，避免公共 Bot 变成共享私人凭据的入口。 | 能发布团队能力、收紧动作范围、查看有权的团队产物及运行健康。 |
| 公司管理员 | 管理成员、能力开放、数据出口和风险边界。 | 能停用能力与撤权、查看治理状态，同时遵守员工私人内容权限。 |
| 审批人、财务与审计人员 | 只处理职责范围内的审批、用量和审计。 | 有明确权限与证据，不因岗位名称获得全部员工内容。 |

首版须交付三个完整业务场景：有引用的知识与文档协助；邮件/日历等业务操作的草稿—审批—执行—回执；周期任务的触发—受限执行—异常通知—人工处理。所有场景共用同一权限和费用边界。

上述三个场景是企业个人 Agent 的验收组织方式，不缩减 OpenMuse 既有完整体验：`agent`、`document`、`finance`、`plan`、`monitor` 五类 Task、Files、PDF、Activity、个人上下文和后台恢复均须保持原产品合同。

产品成功按业务结果、证据正确性、人工接管率、延迟和单位成功任务成本衡量。模型返回一段文字、HTTP 请求成功或客户端显示完成，均不能单独作为业务成功依据。

## 3. 范围与术语

### 3.1 首版范围

覆盖个人入口与工作台、已授权 Bot 的个人会话、知识与持久个人文件、两条边界独立的个人记忆路径、五类 Task 与目标关联、职责与定时任务、主动建议、连接器、受控 Computer、Reviewed action、Policy approval、费用和审计。新增跨日/跨月 Task 的生命周期设计见 §9.1 及专项草案，保持独立的待评审状态。Google 经 OpenConnector 的个人 OAuth、Mail/Calendar、PDF 和 finance 保留完整产品合同；Microsoft 365 继续作为企业移动端方案中的要求，其具体供应商合同尚待冻结，不因 Google 已选 OpenConnector 就推定 Microsoft 路径已获批准。能力未通过门禁时显示不可用原因，不因此计为完成。

首版不增加跨公司业务协作、部门树权限继承、员工数字分身对外承诺、共享 Thread/多 Bot 群聊、共享邮箱、无人类归属的业务主体或自动转交个人凭据。外部个人模型授权继续保持独立路径。

### 3.2 本稿新增的产品术语

除已由 C01 确认的逻辑私有 Bot、业务执行范围及范围执行环境外，新增术语暂存本稿；相应确认后再同步根 `CONTEXT.md`，不另建第二份全局词汇表。

| 术语 | 含义及边界 |
| --- | --- |
| Enterprise Personal Agent（企业个人 Agent） | 一个员工在一家公司内持续管理个人工作及授权的产品入口；可使用多个已授权 Bot，不是独立员工身份或永久超级账号。 |
| Bot | 具备角色、能力配置和运行版本的执行资源。团队公共 Bot 可以被多位员工使用，但各调用人的任务、上下文和个人连接仍须隔离。 |
| Logical Private Bot（逻辑私有 Bot） | 用户持续使用的私有 Bot 身份与档案；公司/团队切换保留逻辑身份，业务访问仍按当前范围解析。已确认术语见根 `CONTEXT.md`。 |
| Business Execution Scope（业务执行范围） | 固定一项业务执行的公司、团队、本人及逻辑 Bot 边界；不能仅凭当前界面或客户端字段构造可信身份。 |
| Scoped Execution Environment（范围执行环境） | 对应一个业务执行范围的 Computer、浏览器及工作目录，隔离其登录态、文件及控制状态；与组织 Workspace 概念分开。 |
| Task（任务） | 有请求人、范围、目标、验收标准和结果的具体工作。一项任务可以产生多个 Run。 |
| Run（运行） | 一次固定配置和版本下的执行记录；重试和恢复遵守运行领域合同。任务状态不能由最后一条消息直接推断。 |
| Responsibility（职责） | 员工明确委托 Agent 持续关注的工作范围，包含触发条件、处理规则和停止条件。职责不是无限期的任意行动许可。 |
| Routine（定时任务） | 按明确时间规则触发工作的计划。计划暂停与取消已经启动的 Run 是两种操作。 |
| Goal / Milestone（目标/里程碑） | 员工跟踪的业务目标与检查点。任务可以关联它们；一次运行成功不自动完成目标或里程碑。 |
| Task Delegation（任务委托） | 员工授予特定 Bot 在限定公司、团队、资源、动作、时间和预算内执行工作的许可。可一次使用或有期限地重复使用。 |
| Operation Approval（操作审批） | 有资格的审批人批准一项具体操作及其参数。审批不创建资源访问权，也不替代任务委托。 |
| Reviewed action（具体外部变更审核） | 对展示了最终内容、账号和目标版本的具体外部变更作出记录在案的决定，由 Reviewed-action 领域拥有提案、消费及结果。 |
| Policy approval（策略审批） | 对 Bot 动作策略所要求的决策请求作出决定，由既有 Policy 领域拥有；与 Reviewed action 分别判断，任一不能代替另一个。 |
| Operation Receipt（操作回执） | 对某次外部操作的可信执行证据，可证明成功、失败或结果尚不确定；文本自述不能替代回执。 |
| Handover Package（工作交接包） | 经有权主体确认可交付、在指定目标团队/资源保存的业务产物及必要说明，不包含原员工私人历史、凭据或个人记忆。 |

## 4. 身份、归属与产品导航

P01：同一员工在不同公司分别进入个人工作范围；公司切换不携带上一公司的会话、记忆、连接、草稿内容、搜索命中或推送正文。全局身份和应用外观等非业务设置按既有规则处理。

P02：每次任务和 Run 固定公司、执行团队、请求员工、Bot、配置版本和付款账户。任务所属团队由服务端持久化事实确定；切换当前团队不改变已有任务归属。无有效团队资格时，不启用团队业务执行。

P03：首版每个业务任务在一个团队范围内运行。多团队员工可切换团队，且可查看汇总的本人任务状态；汇总项只展示其当前仍有权看到的内容。跨团队内容组合须先按既有规则取得目标范围内的显式分享，不自动把“我加入了两个团队”解释为可合并数据。

P04：个人入口可以提供多个已授权 Bot；每个 Channel/Thread 固定一个 Bot 和一个团队上下文。切换 Bot 或团队进入另一个会话，原会话不重新绑定。切换前保留草稿并明确其原归属；异步返回的数据不能显示到新范围。

P05：Agent 的姓名、角色描述、提示词、技能或头像不提供权限。发布团队公共 Bot 只发布能力资源，不发布调用人的会话、记忆、浏览器登录态或个人工作目录。

### 4.1 逻辑私有 Bot 与业务执行范围（C01 已确认）

用户已确认保留逻辑私有 Bot，并对实际执行环境、工具及个人上下文作范围隔离。以下是该选择与既有多租户约束共同要求的行为，不预先指定数据库表或容器架构。

SC01：逻辑私有 Bot 的 owner、身份及非业务展示标识按原预配合同保持稳定；业务执行的完整归属由可信的公司、团队、本人和逻辑 Bot 共同确定。同一 Bot 在甲公司、乙公司或同公司两个团队的执行属于不同范围。团队 Bot 等其他资源继续保留自身发布/授权合同，不被合并成个人 Bot。

SC02：服务端从当前认证身份、实时成员/资源权限及持久化任务/会话归属解析业务执行范围，再获取对应的环境、工具授权和上下文；客户端的公司/团队选择仅作选择器，`botId` 或 `environmentId` 本身都不是权限证明。缺少范围、资格失效或解析失败时拒绝，不能选第一个团队、旧环境或默认连接回退。后台任务按原归属重建并重验范围，不信任队列中自报的可信 Scope。

| 对象 | 逻辑身份与实际归属 | 必须隔离或重验的内容 |
| --- | --- | --- |
| Bot 展示与安全模板 | 同一逻辑私有 Bot 可保留身份和非业务展示；公司/团队配置在各自范围装配。 | 角色/提示词中的业务内容、范围配置、权限版本，模板不能扩大当前公司许可。 |
| Computer/浏览器/沙箱/工作目录 | 实际环境按公司、团队、本人及逻辑 Bot 绑定。物理池可共享，运行中的状态属于明确范围。 | Cookie、登录态、剪贴板、文件、快照、终端、模型会话和环境控制权不得跨范围复用。 |
| 工具与连接 | 每个范围解析有效能力、安装/配置版本、账号及授权；公共目录或代码可共享。 | 工具已安装、Bot 已获能力或另一个范围已连接账号，均不自动授权当前范围。相同外部账号也须显式范围绑定，不能自动复制连接凭据。 |
| 个人上下文 | Channel/Thread、任务、文件、Goals/Ideas 和精确 ID 私有记忆按公司、团队、本人、Bot 及来源授权读取。 | Bot ID 相同不合并历史、索引、摘要、缓存或候选；Hindsight 保留独立 bank 及来源授权边界。 |
| 控制与审计 | 每个 Run/操作/审批绑定原业务范围，相关环境控制凭据还绑定实际环境及有效代次。 | 旧范围的下载、流订阅、控制命令、回调或审批不得改变新范围状态；付款账户不随切换改变。 |

SC03：不同范围可以同时执行，分别持有自己的环境引用及控制状态；不能用“该 Bot 当前活跃环境”这一份全局可变指针路由请求。界面切换只切换显示/新任务范围，不搬迁旧 Task/Run。缓存、事件订阅、会话索引和配置解析必须区分实际范围及适用版本。已绑定旧环境的迟到响应仅能返回原范围的已授权视图。

SC04：环境句柄、控制凭据和重连票据必须验证原范围及有效代次。回收、恢复、重新绑定或人工接管后，旧控制者不能继续操作；有状态环境再次分配前须证明旧状态已清除，不能通过改标签完成隔离。具体实例数、池化方式、凭据格式和 fencing 协议在实现合同中冻结。

SC05：保留已批准的有限例外：同公司通用个人偏好可按本人确认及 Bot 授权使用；同公司显式分享按 §7.1 访问。例外只开放指定数据/动作，不把整个源环境、来源登录态、精确 ID 私有记忆或公司业务配置带入另一范围。个人上下文和工具授权必须由各自领域重新判断，不因共享逻辑身份合并授权。

SC06：历史 Computer、连接、会话、工作目录及记忆仅在公司、团队和本人归属可证时建立范围关联。无法判定的旧对象受控隔离，不能仅从原全局 Bot owner 推定业务范围；恢复也不得重新接入失效资格或已遗忘内容。后续实现合同须冻结范围解析接口、逻辑 Bot—范围—环境引用、代次及迁移核验，所有入口都必须经过该解析边界。

主动建议必须说明“为什么提示我”和信息来源；默认只生成建议，不因用户查看、点击通知或未拒绝而执行业务写操作。主动读取连接来源须有本人明确启用的来源和目的；用户可调整频率、静默时段及关闭该来源。

## 6. 生命周期、暂停与工作交接

以下是个人入口的产品状态，不替代 Bot、账号、成员、Task 或 Run 的领域状态。生效条件由这些权威状态共同决定。

| 事件/状态 | 新工作和在途工作 | 内容、恢复与交接 |
| --- | --- | --- |
| 未启用 | 不发起个人 Agent 工作；员工仍可访问其有权的普通资源。 | 只展示设置和不可用原因。 |
| 正常使用 | 每次执行检查实时资格、委托、资源与能力。 | 只展示当前有权的个人工作内容。 |
| 本人暂停个人 Agent | 阻止新触发和后续业务动作，暂停职责、计划并请求取消在途执行。已发出的外部动作进入确认/核对流程。 | 本人仍可在有效权限内查看历史与处理核对；恢复后由本人显式选择恢复哪些自动工作，不补跑遗漏的敏感操作。 |
| 团队资格移除 | 停止原团队归属下的新工作；后续敏感步骤拒绝，暂停相关计划并请求取消。其他团队按各自资格继续。 | 依赖原团队成员资格的访问失效；另有有效同公司显式分享的资源按 §7.1 重验，不因分享继续执行原团队任务。保留内部核对与结算责任。 |
| 公司成员暂停或离职 | 该公司全部新触发、业务执行及长期委托失效；撤销该公司业务会话/连接访问和流订阅，尽力停止在途工作。 | 不撤销其他公司资格或把公司离职直接当成全局账号删除；历史按既定保留政策保存，不向继任者自动开放私人内容。 |
| 全局账号删除 | 停用该账号登录会话、私有 Bot、排队/在途任务及连接使用，按相应合同断开 Google，阻止新活动。 | OpenMuse 私有数据沿用删除记录和 30 天可恢复期，随后执行可重试最终清理；恢复不自动重启外部写操作。公司正式产物、审计及账务按其独立权属与保留合同处理。 |
| Bot 撤回、连接失效、预算耗尽 | 停止受影响能力的新尝试，任务显示具体阻塞原因；不能换账号、付款账户或未经允许的 Bot 继续。 | 修复后重验权限与参数；不自动恢复已过期审批或失效委托。 |
| 归档个人入口 | 不发起工作，不再自动触发。 | 仅在当前权限及保留政策允许时读取；归档不等于删除。 |
| 更正/删除数据 | 更正建立新的有效内容及历史，旧版本不再作为当前事实；遗忘/删除先阻断使用，再执行适用的副本清理。 | Hindsight 记忆更正、遗忘按原设计；账号 30 天恢复期不允许恢复已被单独遗忘的内容。区分“已停止使用”“受控副本清除完成”，保留必要且受限的非内容审计和费用事实。 |

公司与团队撤权以权威变更提交为界；此后新取得执行许可的敏感步骤必须拒绝旧资格。已经发送给供应商的请求不能宣称被撤回；取消请求、取消确认和外部效果分别报告。更新成员状态与准入之间必须有可验证的一致性边界，不能依靠模型自觉或长效缓存。

工作交接由有权主体选择已在其访问范围内的正式产物，核对来源允许的目标受众，再交付到目标团队资源。员工私人会话、个人记忆、私人邮箱、账号凭据和浏览器登录态不能打包转交。离职前未形成的交接包不能由管理员借“交接”之名读取私人历史生成；组织已有的正式业务产物可按其独立权限重新分配。

原账号删除合同中的管理员恢复仅允许执行恢复操作，不授予内容阅读、凭据取用或冒用身份的权限。恢复后重新核验公司/团队资格及来源授权，重放后续遗忘/撤权事实，连接需要重新授权时须本人重新连接。首版不提供管理员静默代入员工、查看私人内容或冒用原员工执行的机制；特殊调查访问须独立评审。

## 7. 授权原则与角色矩阵

### 7.1 一次动作的有效权限

权限按以下约束的交集判断：

> 员工当前公司/团队资格 ∩ 资源及来源访问权 ∩ Bot 已开放能力 ∩ 当前任务委托 ∩ 连接账号授权 ∩ 公司/团队动作与数据出口政策 ∩ 预算和执行限制；需要审批的动作还必须具有当前有效的匹配审批。

不涉及连接、模型计费等条件的本地动作，只可依据明确的动作分类判定该项“不适用”；缺失本应存在的条件不能跳过。普通资源读取按其读权限授权，不要求先创建任务委托；代表员工执行任务和后台工作时应用完整执行约束。

团队资格一项有两条明确路径：普通资源要求其所属团队的有效成员资格；同公司显式跨团队分享按已批准多租户合同验证公司资格、有效受众、资源动作及分享未撤销，不强制分享接收者加入来源团队。该例外只开放分享记录指定的资源/动作，不授予来源团队任务执行权、未分享子资源、个人凭据或受限来源。共享产物不自动公开全部引用依据；引用只展示接收者有权内容。

必须遵循：未知动作/策略版本拒绝；read 不推出 run/write/share/manage；用户个人规则只能收紧组织限制；成员/授权变化后重新判断；授权依赖不可用时拒绝相关动作；数据进入模型、检索重排、工具或日志之前完成相应授权与出口检查。

模型生成的角色、任务说明、网页、邮件、附件、工具返回和记忆都不是权限来源。内容中的“管理员已同意”不能创建审批，不能修改委托或调用范围。

### 7.2 角色与权限

下表是业务职责，不强制新增同名系统角色。每项特权须显式授予并限定公司、团队、资源和动作；同一人可以承担多项职责，但不能因此合并内容权限。

| 对象/动作 | 本人 | 团队管理职责 | 公司管理职责 | 财务/审计职责 |
| --- | --- | --- | --- | --- |
| 本人的个人会话、草稿、私有文件 | 有效成员资格及个人资源权限内读取/修改。 | 无隐式读取权。 | 无隐式读取权。 | 无隐式读取权。 |
| 个人记忆、候选及依据 | 按本人及来源权限查看、确认、更正、遗忘。 | 无隐式读取或代确认权。 | 可看服务健康和授权范围内用量；无记忆内容读取权。 | 只见获准的审计元数据；不能以审计默认读取正文。 |
| 团队公共 Bot/知识库 | 有效团队成员按对应 read/run/search 权限使用。 | 获明确权限后发布、修改、撤回。 | 可治理开放范围；管理身份不自动获得团队内容。 | 按明确授权读取对应治理记录。 |
| 个人连接、凭据、登录态 | 本人确认连接及断开；秘密值不回显。 | 不可借用。 | 可依政策禁用能力；不能因此取得个人 token。 | 不可读取秘密值。 |
| 正式团队产物 | 按目标资源权限访问。 | 获明确权限后分配或管理。 | 仍需相应资源权限。 | 按审计/财务范围访问必要记录。 |
| 任务、职责、计划 | 管理本人有权的工作和委托。 | 获授权后可停止有风险的团队执行，不能借停止入口读私人正文。 | 可实施公司范围紧急停用，不能借此冒用员工继续执行。 | 看明确授权的任务/操作审计元数据。 |
| 操作审批 | 仅能审批本人有资格批准的动作。 | 作为指定审批人时处理相应操作。 | 管理审批规则不等于批准任意操作。 | 作为指定审批人时处理费用等相应操作。 |
| 公司用量、余额、订单 | 只看获准的个人相关用量及订单。 | 明确用量权限内看本团队报表。 | 公司财务权限另行授予。 | 按账务权限查看；不通过账务下钻泄露会话正文。 |

### 7.3 数据出口与审批信息最小化

读取权不包含转发、共享、导出或交给任意模型/外部 Bot 的权利。发送邮件、上传外部站点、生成分享链接、导出文件、模型调用和追踪导出都必须检查目标及内容等级。基于受限来源生成的摘要和产物继承来源限制，直至完成明确允许的解密级/发布流程；首版不提供自动降低敏感级别的能力。

指定审批人须有权查看审批所必需的信息。若审批卡片会泄露其无权内容，应先取得合法的限范围访问授权，或转交有资格审批的人；无法完整判断影响时拒绝执行，不能用内容不可见的空白审批绕过。

## 8. 自主程度、委托与操作审批

### 8.1 产品执行模式

| 模式 | 允许行为 | 首版默认 |
| --- | --- | --- |
| 协助模式 | 在当前读权限内检索、分析和生成个人工作产物，不修改外部业务状态、不扩大受众。保存个人草稿仍遵守本地资源写权限。 | 默认。 |
| 确认后执行 | 展示具体动作及最终参数，经所需审批后执行一次。 | 邮件发送、日历变更、业务系统写入等适用。 |
| 有界自动执行 | 在本人单独确认、公司/团队允许、动作已验证为低风险的白名单内，按有期限委托重复执行。 | 默认关闭；首版白名单只含写入本人私有工作区的任务结果和提醒，不含外部发送或业务系统写入。 |

权限/凭据变更、支付、资金转移、破坏性批量操作及高影响对外承诺不进入首版有界自动执行。已有策略要求人工操作的动作仍由人工完成，不能通过一次确认或扩大委托改成 Agent 自动执行。

### 8.2 任务委托合同

委托必须能向员工展示并由服务端验证：发起员工、公司、团队、Bot/能力、目的及成功标准、允许读取的来源、允许动作和目标、触发规则、通知目标、有效期、最大次数/频率、总时限、单次与累计成本限制、是否需要逐次审批、撤销状态及策略版本。

一次性任务许可只覆盖已确认任务与允许动作；不要求简单问答先填授权表单。职责和计划的重复执行必须有有限有效期，不能通过长效登录会话获得永久许可。首版未明确到期时间时不启用后台重复执行，由本人选择；界面不得预选永不过期。公司可限制最长授权期限。

委托不扩大员工原权限，不能自动转授其他员工或外部 Agent。更新目标、动作、来源、预算或有效期而扩大范围时，必须重新确认。Bot 内部步骤拆分不生成新的权限，首版不支持通过子 Agent 层层转授。本人撤销后阻止后续动作，保留核对、审计和结算处理。

### 8.3 一次操作审批合同

Operation Approval 是本文的通用业务描述，不要求合并 Reviewed action 与 Policy approval 的存储或执行入口。外部 Gmail/Calendar 写操作必须经过 Reviewed action；Computer 或工具策略另需 Policy approval 时，两类决定分别满足，由各自领域执行，Activity 只聚合展示。

Reviewed action 至少绑定操作 ID、公司/团队、执行员工、Bot/运行、实际账号及连接 generation、动作、目标及目标版本、最终参数摘要及提案内容哈希、数据出口、有效期和策略版本。账号标识相同但断开重连导致 generation 变化，或目标自提案后变化时，旧提案失效。供应商不能提供版本核验时，须在对应动作合同明确安全限制；不能省略检查后宣称已满足同等保证。

执行前原子 claim 匹配的批准；两个客户端、两个 Worker 或迟到回调不能各消费一次。Policy approval 不能直接标记 Reviewed action 已批准或消费。结果未知时仅核对原操作，不能通过新操作重新发送。若副作用已经发生但保存回执失败，原操作保持不可重发的待核对状态并持续恢复，不能回滚本地记录后当作未执行。

邮件审批展示实际发件账号、收件/抄送/密送、主题、正文和附件；日历展示日历/账号、时区、时间、参与人、修改的是单次事件还是系列。审批后模型改写正文、替换附件或增加收件人，均必须重新批准。

本人确认与公司指定审批按政策分别满足；需要职责分离时禁止请求人自批。Agent 可以建议审批理由，不能批准自己的请求、修改审批结论或把聊天文本作为服务端审批事实。待审、拒绝、过期、撤销、已消费及实际执行结果必须可区分。

“以后允许”不得生成无目标、无期限的通配许可；只能进入 §8.2 的有界委托流程。自然语言中明确的执行请求能否视为本次确认，须由动作合同明确规定；首版外部业务写操作仍展示最终参数并完成操作确认。

## 9. 任务、运行与外部操作结果

T01：Task、Run、操作、审批、通知和费用分别保存权威事实并关联；客户端展示统一工作视图，不把它们合并为一个 success 标志。Go、外部 Bot、AG-UI 或模型自述不成为任务成功的权威写入方。

T02：可恢复任务须保存足够的版本、来源引用、已完成操作回执、待审批内容与状态。恢复时重新授权；无法证明来源仍可用、版本兼容或操作结果的，先暂停处理，不从头盲目重放写操作。

T03：同一任务的重复提交、重复触发、客户端重连、Worker 重启和重试不能重复产生已确认完成的外部效果。供应商没有可靠幂等或核对能力时，不承诺 exactly-once；结果未知就暂停该操作及依赖它的后续写操作，展示待核对。

T04：外部操作区分未发送、执行中、成功、明确失败和结果未知。工具超时、响应丢失及本地取消都不能自动变成失败无副作用。人工已处理时记录证据与处理主体，阻止 Agent 再执行相同动作。

T05：取消首先表示请求停止；确认停止后才报告对应运行已取消。部分完成时保留已产生的外部结果和费用；补偿属于新的业务动作，需要自己的权限和审批，不宣称自动回滚邮件或现实世界操作。

T06：通知只投递到本任务获准的渠道与受众，正文不泄露无权来源；推送默认仅提示有新进度，打开后重新鉴权。通知失败不改变业务结果，也不能触发业务动作重做。断线和离线不自动重发未知写操作。

T07：时区、重复与错过策略可见；暂停自动工作不补跑敏感遗漏项。复用 Routines 已有间隔下限、启用上限及连续失败保护，组织可进一步收紧；调度器迁移须保证同一计划只有一个执行所有者。

上述 Routines 限制只适用于 Routine，不自动套到 `monitor` Task、Responsibility 或主动扫描。五类 Task 由专用 Task 模块拥有状态、步骤、运行、类型化证据、产物、等待、重试、取消及租约恢复；复用工作队列和执行接口。Monitor 保留条件、观察游标、观测去重、检查周期和故障退避；Responsibility 保留长期职责和订阅事件语义，不替代 Task。调度迁移是单独合同，不能因底层共用队列就认定已由 Routine 或另一调度器接管。

### 9.1 跨日与跨月的长期工作（新增草案）

长期 Task 保留稳定目标、计划、证据和进度，按已授权条件反复执行有界的一轮工作。业务可持续几个月，单轮执行时限、领取租约、等待期限、授权有效期和审批有效期分别判断；等待期间释放 Worker 和空闲执行环境，恢复时重新解析原范围和当前权限。

推荐将长任务作为五类 Task 的生命周期能力，保留阶段依赖、持久等待与可靠唤醒、可恢复工作记录、授权续期、累计/周期预算、资料有效性、版本兼容和长期停滞处理。Task 工作记录不能自动成为个人记忆；一轮成功、一次周期触发或一个提醒均不自动结束整个 Task。扩大目标、动作、期限或预算仍须确认，外部写操作继续遵守原审批要求。

详细行为、示例及 L01–L12 验收见[专项草案](2026-10-16-long-running-task-lifecycle-spec.md)。其中包含现有 Task 状态及等待生产者尚未覆盖的扩展，不把现有逐步 Plan、Monitor 或 300 秒单轮期限说成已经支持完整跨月工作；编排/调度唯一所有者在具体实施合同冻结。

## 10. 知识、记忆、学习与连接

### 10.1 知识与上下文

检索须在召回与重排前限定当前可用知识库/文档。引用须能定位当前有权依据，并标记来源和时间；证据不足时明确说明，不把模型常识写成企业制度。来源撤权后，不得继续通过历史摘要、检索缓存、向量索引或旧运行上下文向失权者提供内容。

长任务在进入下一敏感步骤前重验来源及目标权限。来源失效时丢弃失效上下文并从仍有权依据恢复，或暂停等待人工处理；不能只拦截最终下载却让失权内容继续进入模型或工具。

### 10.2 个人记忆

个人上下文保留两条独立边界：Hindsight 集成的已确认语义/时间记忆，以及 OpenMuse 独立的精确 ID 私有记忆。前者按已批准 Hindsight 设计处理；后者保持原 OpenMuse 的本人及私有 Bot 范围，不能自动迁入 Hindsight、转成通用偏好或向其他 Bot 开放。Goals、Ideas 和精确 ID 记忆的跨 Bot 使用仍需单独、明确授权，用户能访问另一个 Bot 本身不构成该授权；企业范围还须满足公司/团队隔离。

Hindsight 路径完整继承其已批准设计：候选仅本人审核；普通“请记住”只确认其明确表达的普通事实；敏感信息额外确认；密码/令牌不保存；派生判断自身须确认；来源撤权或遗忘后立即停用相关判断。两条路径在界面明确显示类别、来源和适用 Bot；不能以一条路径降级、导出或恢复为由绕过另一条路径的访问限制。

只有本人明确设为通用的个人偏好可在同公司获授权 Bot 间使用。团队业务事实不能通过记忆转为跨团队共享知识；首版不跨不同授权来源综合派生记忆。个人 Agent 入口不扩大 Hindsight 的召回范围。

分别控制新增记忆与已有记忆使用。30 天候选过期、任务载荷及备份的清理窗口、SQL 降级和遗忘重放沿用原设计。按公司试点启用个人记忆不属于本稿方案；其已批准的适用用户统一启用及全功能隔离前置继续有效。

### 10.3 技能与自动学习

个人记忆、从个人历史形成的技能和团队公共技能是不同对象。学习不能绕过审核或来源授权，不能把员工私人会话自动训练成团队能力。首版新增建议：个人 Agent 的私人会话默认不贡献共享 Learning 容器。

若要贡献共享技能，须先确认参与来源、内容权限、目标受众和必要脱敏；候选技能经过评测与有资格主体发布后才生效。运行固定技能/提示词版本；自动学习只能提出候选，不能直接修改生产行为、政策或工具权限。无法证明来源隔离、发布治理和删除传播的共享学习路径保持禁用。

### 10.4 连接与 Computer

登录公司、连接第三方账号、授权读取、授权写入是独立过程。OAuth 回调绑定最初发起的公司、团队、本人及目标连接，不能跟随界面当前团队变化。连接界面显示实际账号、授权能力、用途和最近使用，并支持撤销。

OpenMuse 的 Google 集成继续只经 OpenConnector：OpenBot 管业务授权、连接选择和领域合同，OpenConnector 管供应商凭据及动作执行，前端不直连供应商或持有 token。不因为抽象为“连接账号”就另建 Google token 存储或增加未批准的替代供应商路径；Microsoft 的实现由其企业合同另行冻结。

首版个人任务使用本人的明确授权连接；公司/团队共享账号须走单独的受控共享连接合同，不借用 Bot 发布者的个人账号。`Coworkers` 中旧部署描述的发布者账号使用方式不能直接迁入企业路径。

Computer 绑定当前员工及业务范围；隔离浏览器登录态、文件、剪贴板与快照。人工接管、自动控制、租约撤销和旧连接失效必须互斥且可验证；接管后自动动作停止，重新授权接回时重验页面目标和待执行参数。具体控制租约、generation/fencing 与断连核对由 Computer 领域规格冻结。

### 10.5 持久 Files、PDF 与 finance

Files 是本人有权的持久文件库，不用会话附件或 Craft 临时文件代替。文件及派生版本具备稳定标识、归属、内容哈希、任务/产物关联与删除状态；上传、预览、下载、分享和转入 Bot 工作目录分别授权。

PDF 保留邮件附件导入、字段检查、不支持字段报告、补充缺值、确定性填充为新副本、Web/移动阅读及工作目录转移；不能覆盖原件。Finance 保留服务端 CSV 验证和可重复计算的支出汇总，保存输入依据、结果产物及任务关联。文档/财务任务准备外发回复后，仍等待匹配 Reviewed action，不能以产物生成成功代替外发成功。

OpenBot 是唯一业务后端，拥有这些对象的权威状态；OpenMuse 只负责展示、表单、阅读和本地交互。集成运行不启动旧 OpenMuse 业务 server/TaskWorker，也不保留第二套文件、OAuth 或任务权威。多租户整改复用已有权威对象，不能再新旧双写。历史单用户 OpenMuse 数据不在原切换迁移范围；该排除不影响公司多租户方案对现有 OpenBot 数据的归属核验要求。

## 11. 费用、预算和资源限制

公司工作台任务固定使用公司付款账户，记录团队、员工、Bot、Task/Run/操作的用量归属。外部个人模型授权继续使用个人账户且不获得公司业务权限。转岗、切换团队、取消、恢复或离职不改变已发生费用的付款账户。

公司余额之外可以配置团队/个人/任务消费上限，但它们是限制，不是复制出来的独立钱包。调用同时满足适用上限与公司原子预留；限制必须包含并发未结算责任，不能只看已完成用量。余额或上限不足时暂停新的付费尝试，不自动降到另一付款账户或绕过网关。

本人可查看自己有权任务的成本、预留和待结算状态；财务报表不附带私人正文。取消或未知结果不自动释放已承诺额度；费用按既有证据结算及处置合同处理。后台个人记忆处理由平台承担并受公司/个人上限限制，不因其服务于公司任务而改向公司重复收费。

每项自动工作必须有时限、次数/频率、并发、重试和成本边界。达到任一限制后记录原因并停止后续尝试，不能在子任务、模型 fallback、通知重试或不同工具中重新计数以绕过。

## 12. 治理、审计与可用性

治理入口展示能力开放、有效委托数量、阻塞任务、未知操作、授权异常、服务健康及有权用量。负责人能识别“谁要处理、处理什么”，但列表、计数、搜索、日志、追踪及导出都受同一公司/团队/个人边界约束。

审计记录至少关联公司、团队、发起员工、执行服务、Bot 与版本、Task/Run/操作、触发来源、委托、政策版本、审批及决定人、外部结果证据和费用引用。日志不得保存秘密值、完整内部能力或模型思维链；常规治理记录优先保存脱敏摘要和引用，内容查看另行授权。

对外模型、运行时、检索、对象存储和可观测性服务按公司允许的数据出口与保留政策使用。外部黑盒 Bot 无法证明内部模型/工具治理时，须明确能力等级与可接收的数据范围，不能展示为全链路受管。Opik 等追踪不是业务或计费权威，不能通过追踪链接绕过 OpenBot 内容权限。

公司应明确业务正文、产物、审计、账务、连接元数据和备份的保留/删除政策，以及异常处理负责人。保留数据不意味着可供 Agent 继续召回；断开来源后的后台核对只处理必要操作/费用事实，不能重新浏览员工业务内容。

关键授权、审批、操作意图及回执不能可靠持久化时，拒绝新业务写操作。可观测性导出不可用与核心授权不可用按各自合同处理，不能把全部依赖故障统一表示为成功或空列表。管理员执行公司紧急停用时，仍允许受限的核对、审计和结算维护流程完成既有责任。

| A28 | 两次并发首次进入只取得一个属于本人的逻辑私有 Bot；切换公司/团队保持该逻辑身份，实际环境按 §4.1 解析。安全模板更新保留用户字段、收紧后续动作；任意可见团队 Bot 均不能因可见而获得私有工具。 |
| A29 | Activity 同时存在 Reviewed action 与 Policy approval，决定分别路由；断开重连但账号名相同、目标版本变化、双端并发批准、双 Worker claim 均不会复用失效提案或重复执行；回执落库失败进入待核对。 |
| A30 | 精确 ID 私有记忆、Goals/Ideas 和 Hindsight 记忆按各自合同授权；可访问另一个 Bot 不自动获得精确 ID 记忆，Hindsight 召回/SQL 降级不读取该独立存储。 |
| A31 | `agent/document/finance/plan/monitor` 均验证后台执行、租约丢失恢复、输入/审核等待、暂停/恢复/取消/合格重试、证据及通知已读状态；Monitor 观测去重与退避独立验证，不套用 Routine 默认频率。 |
| A32 | 公司离职只撤销该公司业务访问，不撤销其他公司登录资格；全局账号删除则立即阻断工作并按 30 天期限恢复/最终清理。恢复不复活单独遗忘数据、撤销资格或外部写操作；管理员恢复能力不授予内容阅读权。 |
| A33 | 持久 Files 跨会话可用且始终授权；邮件附件 PDF 检查、缺值等待、新副本、原件保留、阅读和工作目录转移通过；finance CSV 正常/异常数据及可重复计算通过，并保存独立产物。 |
| A34 | 两个用户、两个真实 Google 测试账号在 iOS/Android/Web 完成完整业务场景；Google 只经 OpenConnector，集成环境无旧 OpenMuse server/TaskWorker，1–20 活跃用户参考容量及资源限额取得实测证据。 |
| A35 | 同公司显式分享可对未加入来源团队的有效受众开放指定资源/动作；未分享子资源、私人凭据和受限引用仍拒绝。分享撤销立即失效，退出来源团队不误保留依赖成员资格的权限，也不误拒独立有效的分享。 |
| A36 | 同一用户及逻辑私有 Bot 在两家公司及同公司两团队执行，逻辑 Bot 标识保持稳定；Cookie、浏览器登录态、剪贴板、终端、文件和快照分别隔离，切换不创建另一套产品私有 Bot 或迁移旧任务。 |
| A37 | 某范围已安装工具或连接账号，其他范围仍须独立解析能力与连接授权；伪造范围/环境 ID、仅提交 Bot ID、使用默认环境或旧控制票据均不能调用。相同外部账号不自动继承原范围授权。 |
| A38 | 同一逻辑 Bot 并行执行两个范围的任务，界面反复切换并注入迟到事件，结果、控制、缓存、审批与费用始终回到原归属，撤销一个范围不影响另一范围的有效工作。 |
| A39 | 同一逻辑 Bot 查询多个范围的历史、Goals/Ideas、精确 ID 记忆和 Hindsight 记忆，默认不能跨范围召回；已确认同公司通用偏好及独立有效分享仍按原合同可用，不因此获得源环境或私人凭据。 |
| A40 | 环境回收再分配、人工接管、重启和代次变更后，旧控制命令/重连票据均被拒绝；再分配无旧状态残留，后台恢复按原范围重建资格，未知历史归属不会自动绑定。 |
| A41 | Web/移动/桌面、Computer、工具、检索、后台任务、内部与旧兼容入口都经过可信范围解析；缺范围或解析依赖故障不回退。模板和范围配置更新不把一个公司的业务提示词、凭据或权限应用到另一公司。 |
| A42 | 同一个 Task 在跨 10 天/90 天的测试时间线中由多轮有界执行继续，进度、计划版本、证据及范围保持正确；单轮执行期限与业务截止日分别判断。详见 L01–L02、L09。 |
| A43 | 长期等待释放 Worker/空闲环境，等待登记与唤醒可恢复；重复、乱序、丢失和迟到事件最多推进当前有效等待一次，停机后补发现到期项且不补跑敏感历史操作。详见 L03–L05。 |
| A44 | 业务尚未到期但授权/连接到期时保留任务并停止业务，续期重验资格；跨月累计与周期预算纳入未结算责任，不复制额度、冻结全部未来费用或自动释放未知预留。详见 L06–L07。 |
| A45 | 数月工作记录可定位原始依据，恢复不依赖完整聊天；失权/遗忘内容不通过摘要复活，资料变化和版本升级有验证/迁移记录，不静默换 latest 或自动写入个人记忆。详见 L08–L10。 |
| A46 | 长任务暂停、取消、到期、离职或接管后不非法继续；展示明确等待、下次检查、最后推进、预算/授权、停滞原因及处理人，通知不重复触发业务操作。详见 L11–L12。 |
| A47 | 长期推进复用 Task 唯一权威和经核验的调度边界，无双触发器或新竞争租约；覆盖等待任务数量、恢复扫描及积压容量，测试时钟验证不冒称连续运行 90 天。详见专项 §10–11。 |

## 14. 质量指标与发布证据

| 指标 | 计算口径与评审要求 |
| --- | --- |
| 业务任务成功率 | 按预先冻结的业务验收条件判定；分清完成、部分完成、人工完成、失败、待核对。不能把有文本输出计为成功。 |
| 证据正确率 | 引用可定位且当前有权；外部成功陈述与可信回执一致。缺证据和错误证据分别记录。 |
| 人工接管率 | 区分预期审批、用户主动接管及异常救援，不将正常审批统计为失败。 |
| 延迟与可靠性 | 分别记录首次反馈、排队、实际执行、等待人工及总历时；未知状态与恢复耗时单列。 |
| 成本 | 计算固定付款账户下单位成功任务成本、失败/重试成本、未结算责任；平台记忆后台成本单列。 |
| 主动功能价值 | 记录建议采纳、关闭、重复提示及无效触发；不能用通知数量衡量价值。 |
| 权限与数据边界 | §13 的越权、泄露、过期授权复用及未经许可外部写入均为零容忍验收项；真实阻塞问题不能延期后标为通过。 |

发布前由产品负责人、公司安全/数据负责人及运行负责人共同签署容量、性能、任务成功率、成本、SLO、恢复目标和保留政策的验收配置，绑定部署模式、版本及测试样本。缺少该配置不具备发布条件；本文不编造未经确认的业务阈值或容量承诺。

已有 OpenMuse 自托管首版的约 1–20 同时活跃用户是参考验收规模，不是本稿新增容量承诺，也不能全量延期为未知值；其计算机、磁盘和 Worker 限额须遵循经审核的规划基线并实测。企业共享部署的公司数量、总并发和故障恢复目标需另行确定，不能把单部署 20 人等同于企业平台总容量。

证据包至少含：批准 Spec/裁决、功能与权限覆盖清单、真实测试报告、关键故障注入结果、供应商操作核对证据、版本/部署配置、备份恢复及撤权/遗忘重放结果、已知限制、处理责任人和回滚方案。批准设计、通过协议测试或具备页面入口均不能替代这些证据。

以下列出完整推荐值及确认边界。C01 中保留逻辑私有 Bot 和范围隔离的选择已由用户确认并记录 ADR 0006；这不自动批准 D01 的全部入口/聚合建议或 D02–D09。

| --- | --- | --- |
| D01 | 每位员工在每家公司有一个逻辑个人工作入口，保留逻辑私有 Bot，聚合多个已授权 Bot；入口聚合不授予私有工具或数据。 | **部分已确认**：逻辑私有 Bot 及按范围隔离执行环境、工具、个人上下文见 C01/ADR 0006；入口及其他 Bot 聚合建议仍待确认，不预先决定表结构。 |
| D02 | 首版任务固定一个团队，个人汇总可跨其有效团队展示有权状态；内容跨团队使用先取得明确分享。 | 限定任务上下文和跨团队聚合行为。 |

| D08 | 采用 §13 的验收与 §14 的发布证据要求，具体业务阈值由有责主体签署。 | 确定产品验收范围；不降低原全功能隔离和记忆上线前置。 |
| D09 | 增加跨日/跨月的 Task 生命周期，采用多轮有界推进与持久等待，按专项草案管理计划、唤醒、工作记录、续期、累计预算和结项。 | **新增建议，待评审**。不新增第六类任务，不延长单 Run 至数月，不扩大自动外部写权限，也不在本文新选编排框架。 |
