状态：**产品规划评审稿 v0.2；已按用户要求纳入产品规划，新增详细方案未整体批准，未启动实施**。

日期：2026-10-16。

用户依据：产品主要针对小型企业和个人；用户在规格复核及市场对照后要求“把这些规划更新进去”。本文件将审核报告 G01–G10 写入产品范围、优先级、业务路径和验收。目标用户、纳入规划的方向及 C01 既有决定已经明确；新增个人空间模型等详细方案尚不因此成为 accepted 架构决定。

## 2. 产品定位与默认体验

个人用户能直接用自己的文件和连接账号交代工作，获得可检查的成果、后续跟进及可理解的费用；小团队可以在此基础上邀请成员、使用团队公共能力并交付有权成果。

主导航采用“助理、工作、资料、连接、用量”，团队入口按加入/创建关系出现。先展示用户当前可以做什么、结果在哪里和下一步需要谁；范围、账号、付款账户和动作影响必须在相关决定处可见。Run、环境代次、记忆索引分区等实现信息留在有权限的诊断视图；记忆类别和清理状态仍以可理解文字展示。

默认可开始文件整理/分析或个人草稿工作，不要求先建立知识库或连接多个应用。需要付费尝试时仍须具备真实、足额且可验证的额度及费用上限；未配置或余额不足时显示原因，不使用成功形态的演示数据替代运行。

## 3. G01–G10 产品合同

### G01 · P0 · 完整个人模式与付款

推荐建立 **Personal Space（个人空间）**，归属于一个 OpenBot 用户；不是公司 Tenant 或团队 Workspace 的别名。首次启用个人模式时幂等建立真实范围与所有权关系，隐藏组织设置，不依赖虚构公司、默认公司或空 Scope 回退。

业务执行区分个人与公司两条路径：个人范围绑定本人、个人空间和逻辑私有 Bot；公司范围继续绑定有效公司、团队、本人及 Bot。两者均由服务端从身份和持久化对象解析，客户端字段只作选择/提议，范围类别及标识都须校验。一个稳定逻辑私有 Bot 可以服务两个模式，其环境、工具、会话、文件、任务、项目资料及上下文分别隔离。

Task 的范围类别、个人空间或公司/团队、请求人/所属人、Bot 身份及付款账户在生命周期内固定；可调整的工作范围只指该归属内获准的来源、动作、目标和成果。计划变更或重新确认不迁移任务。改变归属须创建获授权关联任务并交付有权成果，不能带走原审批、未决操作或付款事实；细则见主规格 P02/P03a。

推荐个人工作台的新业务调用固定使用 `PayerRef(personal, 本人)`，公司任务继续使用服务器确定的 `PayerRef(company, Tenant)`，外部个人模型授权继续走原合同。付款依据在准入时持久化，后续切换、恢复及回调不改变它；个人模型 Key 不能调用业务工具。个人余额、公司余额不合并、不复制、不互相兜底，个人不能自行发放无来源额度。

个人空间中的语义记忆和精确 ID 私有记忆继续分别管理本人审核、来源、适用 Bot、遗忘和保留；个人与公司记录、候选、摘要及索引不得混用。原 Hindsight 的公司 bank 方案不能通过塞入空 tenant 或复用公司 bank 直接承担个人范围，个人映射与删除/恢复证据须补独立合同。

加入公司/团队只新增成员资格与相应入口，不自动导入个人历史、连接、登录态、项目、记忆、余额或在途任务。需要交付个人材料时，由本人选择当前有权且可发布的正式产物，核验目标权限后形成公司内交付；秘密值、旧审批和委托不随材料转移。退出公司不关闭个人空间；全局账号删除按各数据类别的既定停止、恢复和保留合同处理。

产品模型与替代方案见[提议 ADR 0007](../adr/0007-personal-space-business-scope-and-payer.md)。物理存储、路由和迁移不在本文件指定，不能在该方案完成评审前宣称个人模式已经可用。

### G02 · P0 · 快速获得第一个成果

首次进入依次完成当前模式/范围说明、逻辑私有 Bot 就绪、选择一个具体场景、最少必要的输入/连接、试跑和成果查看。组织创建须是部署政策允许且本人明确发起的业务操作；团队邀请显示真实组织、受邀身份及权限，经确认后建立关系，SSO/邮箱域不自动赋权。

小企业首次开通采用以下产品合同；自助创建是否开放由部署政策明确配置，未开放时提供有资格管理员预配路径，不靠数据库人工补权限：

| 步骤 | 行为与授权结果 |
| --- | --- |
| 创建/预配公司 | 自助模式由已认证本人确认公司信息及初始权限清单，服务端按部署授予的创建权限执行；预配模式由有创建资格的管理员登记目标公司及待确认的初始管理者。名称、邮箱域及客户端角色字段不能决定已有公司归属。重复同一创建请求返回同一结果，不重复创建或发权。 |
| 建立首个可用团队 | 初始管理者确认后，受控初始化流程显式记录有效公司成员关系、公司管理权限、首个团队及其成员/团队管理权限、授予依据与操作者；全部必要关系完成才展示开通就绪，部分失败可幂等恢复。管理权限不自动打开其他成员私人内容。 |
| 启用公司付款 | 创建页面单独展示公司采购和账务查看权限；只有部署初始化政策明确允许且本人确认，或已有合资格授权者显式授予后才生效，并分别留记录。不授予无来源积分发放权；无采购权限时仍可管理获准组织事项，但购买入口拒绝并说明向谁申请。购买产生真实权益后才运行付费公司任务，不从个人余额补足。 |
| 邀请并完成首项工作 | 有邀请权限者选择目标团队及允许授予的权限，受邀人以真实身份确认；拒绝、过期、撤回邀请不建立成员资格。成员在有效范围和授权内执行公司任务；初始管理者可以兼任采购职责，但各项授权、决定及费用仍分别记录。 |

最后一名有效公司管理者主动退出或放弃管理职责前，须由有资格主体完成新管理者的授权与接受，或显式启动公司受控关闭；不能先清空管理职责再保留无人负责的自动业务。受控关闭立即阻止公司新增业务和长期触发，保留有权限的成果访问、未决操作核对及账务责任，处理负责人/通知渠道须登记。此流程不是删除所有公司资料。全局账号删除或紧急撤权不能为等待交接而延后：应立即停用该身份；若因此无管理者，公司进入停止新增业务的受控关闭状态，由部署预先指定的运行/账务处置职责处理既有责任。该职责不获得员工私人内容或代入权限，恢复公司业务须重新建立合法管理资格及明确恢复决定。未配置处置职责的部署不能启用组织创建。

提供三种可直接开始的业务模板：每日工作准备、客户事项跟进、每周经营资料整理。连接未就绪时可先用本地上传文件完成适用步骤，不伪装为已经读到邮件或云端表格。模板展示输入、输出、来源、付款和操作范围；发布或更新模板不自动连接账号、放宽权限或改写在途任务计划。

试跑须产生真实、受授权的结果；涉及写操作的试跑默认生成本地草稿或待审提案，真实外部写仍要匹配批准。完成后允许用户查看结果再选择是否开启例行工作，列明期限、频率、预算和通知，不能把一次试跑自动变为永久自动化。记录首次成果完成率、耗时及失败原因，用实测确定优化目标。

### G03 · P0 · 常用工具链和连接就绪

工具链按邮件、日历、资料/表格、通知入口分类。每个受支持连接提供实际账号、当前范围、用途、读写能力、试跑、状态、重新授权、断开及对受影响任务的说明。连接器可见、已安装或目录中有动作，都不能视为实际账号已授权或该动作已通过验收。

个人连接从发起到 OAuth 回调、重连及断开均绑定本人和真实 Personal Space；组织连接绑定本人、公司及团队，均含目标连接并重验原范围资格。界面切换不改变回调归属，失权不回退到另一模式。相同外部账号在不同范围分别授权；连接代次、供应商实际失效及 Bot 使用权限按主规格 §10.4 判断，不复制凭据或用空 tenant 表达个人模式。

沿用 Google 经 OpenConnector 的既有合同；M365 范围继续保留并单独冻结合同。国内/海外首发工具链由 §7 的决策确定，候选不等于支持承诺。每种已支持动作明确分页/截断、文件引用、时区及事件语义、供应商 ID、结果核对和不可用原因；第三方动态 Schema 不直接成为客户端权威接口。

优先使用稳定 API/连接器完成可验证的业务动作。通过 Computer 执行的能力另行显示所需在线环境和限制，继续经过网关/Policy/Reviewed 决策，不因 API 失败自动转向未授权的浏览器账号。首发链路选择只决定入门和验证顺序，不删去已批准产品中的其他连接要求。

### G04 · P0 · 费用、套餐与消费限制

开始前显示本任务的付款账户、计费来源、适用套餐权益、预计区间及依据、可强制上限和超限处理；无法可靠估算时说明未知项，以已验证上限准入，价格或强制上限缺失的能力保持不可用。预计区间不是固定报价，不把存储缩放值当作用户费用单位。

运行中分别展示已结算、预留/待结算和可继续使用的余额/任务预算；长期任务同时展示累计与本周期限制。结束时展示实际消费及未决项，关联到具体成果/尝试，避免将取消或失败显示成自动退款。价格更新只影响符合原合同的新尝试，既有费用按锁定依据处理。

套餐说明区分固定权益、用量消耗、附加服务及支持的能力。试用只使用真实记录的权益，不承诺无限免费；余额不足时可充值/购买、调整合法限额或停止，不能切换付款账户。具体价格、试用额度、折扣和正式票据能力不在本文件编造，沿用付款合同并在启用前配置/确认。

### G05 · P0 · 可运行交付与自助恢复

托管与自托管共用业务语义，并各自形成可复现的支持配置。启动/就绪检查至少覆盖认证、范围隔离、模型准入、Worker/定时唤醒、持久存储、连接器及适用备份/恢复。相关依赖缺失时标注受影响能力，不将旧单容器共享浏览器或没有调度 Worker 的状态当成完整隔离及持续运行配置。

托管任务关闭客户端后继续在已授权后台推进；自托管必须说明哪台机器承担执行，停机、休眠、断网时如何等待、提示和恢复。依赖本地设备的工具不因产品有云端服务就被显示成可离线执行；未明确授权、能力和费用前不自动把本地任务转交云端。

普通用户可从任务/连接页面补资料、重新连接、补预算、在资格有效时继续、暂停或结束。暂时故障的安全重试与外部效果未知的核对分别呈现；未知操作仅允许查询证据、联系有资格处理人或登记经核验的处理结果，不显示会重复外发的“一键重试”。超出本人权限的处置给出原因及可联系的职责，不默认提供管理员代入。

长期等待时正常回收环境不要求用户逐次人工恢复：已安全停车、检查点兼容且无未决副作用时，在资格/委托/预算/连接有效的原范围自动重建并签发新控制票据。旧票据始终失效；缺连接授权、检查点不兼容及未知外部结果分别展示阻塞，按长任务 LT11 处理。仅更换 Worker/Run 不重置操作消费，计划或委托改版后的旧提案按主规格 §8.3 失效并重新审核。

自托管提供版本、依赖/调度健康、备份及恢复状态的诊断摘要和可脱敏导出；升级/恢复检查撤权、遗忘和未决操作，不回退到不理解范围隔离的版本。实现前需明确服务故障/账务异常的处理责任及可验证的运行目标。

### G06 · P1 · 统一成果交付

Task 成果页汇总产物、来源、版本、完成/部分完成、预览、编辑、下载或有权目标写回，并显示实际操作回执。复用 Files、PDF、finance、Craft/Workshop 等既有所有者；统一展示不创建另一套文件主库。

按业务模板给出具体格式与验收：PDF 保留原件并生成填充副本；表格/经营汇总保留输入与可重复计算结果；报告提供可继续编辑的格式及相应预览，其他文档/简报/网页格式按支持清单开放。文件后缀、能下载或有一张截图都不能单独证明内容和格式合格。

外部写回/发布绑定明确目标和最终内容，继续经过相应批准。重新编辑形成新版本；来源变化或失权时重新判断派生产物的可用性，不向无权接收人泄露完整依据。

### G07 · P1 · 轻量团队协作

团队面向普通用户提供负责人/成员等有限入口，实际沿用原成员及动作授权。管理权不授予私人内容，财务权限单独授予；没有强制职责分离时同一合资格人可承担多项职责，相关决定和审批类型仍分别记录。

首批日常协作采用有权成果/交接包：发起人选择可交付的正式资料及必要说明，限定同公司目标团队和受众；接收人可接受、拒绝、评论或确认交付。若接收人需继续业务工作，在其当前范围创建自己的关联任务并明确确认委托，保留原任务/操作/费用事实，不把原私人 Task 或 Thread 改成多人公共对象，也不继承原员工凭据。

交接不复制完整私人检查点；离职/撤权后的原 Task 停止新增业务，仅保留受限核对、审计及结算。交接关系记录原任务及未决操作，只向接收人提供有权的阻塞说明和核对结论，原操作未知时阻止新任务重复执行或推进依赖动作。确认已完成后继续后续事项，确认未发送后才可重新提案；更换任务或负责人不清除原操作的去重与核对责任。原任务关联不开放私人历史，新增任务不能借交接重置已有未结算责任。

团队进度只汇总当前有权的交付信息；评论与附件继承目标资源的可见性。共享 Thread、共享邮箱、共用浏览器及任意跨公司协作不因本规划自动进入范围。后续需要更直接的任务分配时，先冻结参与者、执行身份与可见内容合同。

### G08 · P1 · 今日工作与消息入口

统一显示今日安排、待我决定、正在等待、最近完成、即将到期、需要处理的连接/预算及长期任务最近推进。沿用 Activity/Task/通知权威事件，不由客户端猜成功。卡片直接说明下一动作、账号/目标和费用影响；可展开来源、记录及有权限的技术详情。

同一界面可以汇总 Reviewed action 与 Policy approval，但按类型分别验证和提交，不能以一次笼统确认替代所有决定。消息入口要绑定真实用户、范围、设备或渠道；通知默认最少正文，打开后重验权限，支持静默和去重。消息渠道中的身份与批准传递须有专门合同，不能凭显示名或未认证回复放行。

### G09 · P1 · 项目及连续业务上下文

用 **Project（项目）**组织同一授权范围内的任务、资料、成果、规则和外部业务对象引用。Project 不是公司/团队 Workspace，也不因放入项目就授予所有关联对象读取权。初期使用受控引用，外部 CRM/邮件/表格仍为其原业务事实的权威，不重复建设完整 CRM。

个人项目、公司团队项目分别存放；客户名称或当前选中的项目不决定付款账户，不要求为每个个人客户虚构一个公司 Tenant。长期任务可关联项目，仍独立记录验收、授权、预算及计划版本；跨项目关联和共享检查实际范围、来源及受众，不自动综合不同公司的数据。

### G10 · P1 · 数据可带走与隐私可核对

支持按当前权限选择本人任务、正式产物、记忆记录及必要来源说明导出；标明格式、所属范围、时间、版本、审核/删除状态及可能无法携带的外部内容。公司内容的导出需要独立动作权限，所有者身份不自动越过来源限制。密钥、token、环境控制票据及完整内部能力不导出。

受控导入需本人选择目标范围、检查格式/来源/归属并预览结果，不信任导入文件中的角色、批准或 owner 字段；旧审批、委托及执行票据不能恢复成有效权限。已遗忘/撤权内容在受控恢复和索引中不能复活；用户已经下载到外部的副本不能被宣称已由平台远程清除。

界面展示已连接来源、模型/外部处理去向、适用保留政策及删除进度。账号删除的 30 天恢复与单条记忆即时停止使用继续分别处理；加入公司、停订阅和全局账号删除是不同动作，不能用隐藏取消入口或自动转移私人资料制造退出障碍。

## 4. 三个核心业务流程

| 流程 | 输入与首次成果 | 持续工作与控制 | 验收 |
| --- | --- | --- | --- |
| 每日工作准备 | 授权邮件/日历或本人上传资料 → 今日安排、会议简报及建议待办，来源与时间可查看。 | 本人选择后启用例行检查，设期限/频率/预算/通知；外部日历变更另审。 | X01、X03、X05、X08、X15。 |
| 客户事项跟进 | 询价/附件/已有资料 → 有依据的回复或报价草稿与缺值清单。 | 等待资料/复查时间，提示未解决事项；批准具体回复后执行，保存回执和后续任务，结果未知先核对。 | X04、X07、X10、X13、X19。 |
| 每周经营资料整理 | CSV/表格/文件 → 可核验汇总、异常清单及可编辑报告。 | 周期更新保存输入与版本，受累计/周期预算限制；资料变化重验，分享或写回另审。 | X06、X11、X12、X16、X20。 |

流程中的“报价”指基于用户提供且有权使用的业务资料形成草稿，不由 Agent 自行承诺交易条件。所有流程只使用真实输入及明确权限，缺资料时澄清或等待；已有全量功能仍按其合同验收。
