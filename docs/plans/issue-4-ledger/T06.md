## 关键契约

- `ObservationScopeKind = "workbench"` 是唯一成员；企业 hint 存在即 `ENTERPRISE_SCOPE_UNSUPPORTED` 403，且该检查在 ownership 判定**之前**——合法 owner 也不能借走工作台 scope（无回退路径）。
- `resolveObservationScope` 是唯一签发点；产物 `Object.freeze` 并登记模块私有 `WeakSet`；序列化还原/展开复制/手搓对象一律 `OWNERSHIP_REQUIRED` 403。归属事实（`ownership`/`epoch`）由调用方注入，本模块不查库（查库是 #7/T07 的职责）。
- `scopeKey` 长度前缀布局 `wb|actor|bot|epoch`，防分隔符位移碰撞；epoch bump 使旧游标/缓存失效。
- 游标 HMAC 绑定 `CURSOR_KEY`（per-boot：`pid+Date.now()`）与 scope key；跨 scope、篡改、epoch 过期均 403。
- `cacheKey`/`jobKey`/`exportKey`/`scopeKey` 统一走 `joinKey` 长度前缀连接。
- `resolveStorageLocator` 从 scope key 单向派生 workspace/project（keyLen + sha256 前 8 位指纹，E7 修复），无任何从 locator 反推 scope 的函数。
- `resolveEvaluationEligibility` 工作台答案即 scope 本身。

## 下游义务（F2 落实）

- **#17（T11）分页**：进程重启后 `CURSOR_KEY` 轮换，存量游标全部失效——这是刻意的安全失败。T11 实现分页时必须把该失效表达为**可解释错误**（403/OWNERSHIP_REQUIRED 语义），不得静默回第一页，也不得返回空页冒充「没有更多数据」。
- **#7（T07）权威归属**：`ownership`/`epoch` 由调用方从活数据解析注入；移交/撤销 → epoch bump → 旧游标与缓存自然死亡。
- **T07/T08 首个真实调用方**：cache/job/export key 已带长度前缀，调用方参数含 `\|` 亦安全；无需再约束字符集。
