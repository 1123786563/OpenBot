# Governed Built-In Model Execution Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement one assigned Task at a time. Steps use checkbox (`- [ ]`) syntax for tracking. The coordinator freezes and independently validates/reviews each Task before its consumer runs.

**Goal:** Execute existing built-in Bots through the reviewed OpenBot ModelGateway under one authenticated Run, with a caller-supplied Run ceiling, a bounded capability for every model step, truthful usage settlement and exact terminal Run outcome.

**Architecture:** Keep CopilotKit's current built-in Agent, tools, approvals and per-run rebuild seam. The durable Runner owns the admitted Run/lease and invokes that Agent only with a server-created, request-local governed model; the AI SDK v3 adapter sizes each step from the remaining Run ceiling and issues a persisted invocation capability. The gateway rebinds the stored route to current server configuration, resolves credentials server-side, and closes failures without confirming usage.

**Tech Stack:** TypeScript, Bun, CopilotKit Runtime 1.77.0, AI SDK 6.0.264, AG-UI, existing Drizzle Run/Gateway/route services.

**Spec:** `docs/superpowers/specs/2026-10-11-mastra-intelligence-only-design.md`; parent Task 2 `docs/plans/2026-10-11-mastra-intelligence-only-dag.md`; continuation `docs/plans/2026-10-12-mastra-t2-production-cutover.md`.

**Source evidence:** `.superpowers/sdd/2026-10-12-mastra-t2-production-cutover/reports/governed-execution-continuation-map.md`, `governed-success-route-architecture.md` (SHA256 `70091d421fa9c8151a0bbec9fb39c700d4376e83cdff8b3f115228e1698b3417`), `governed-per-step-cap-ruling.md` (SHA256 `360bc24a4ec525d9d410b70ee2a4ee87795d4c81a3a70853567673fc0b082e37`). The last report proves pinned CopilotKit passes one static `maxOutputTokens` to every tool step; the adapter must derive a fresh per-call cap.

## Global Constraints

- Mastra owns persistent thread/history, memory and learning. OpenBot keeps Agent execution, tools, approvals, pause/resume, SSE Runner/API, Run budget and terminal decisions. This plan touches only governed built-in execution, not headless history or frontend.
- Validate caller `forwardedProps.maxOutputTokens` as the existing positive integer in `1..2_147_483_647` before Run creation; it is the exact persisted aggregate Run ceiling. No missing/default/rounded cap, client model/provider/route, or client run ID becomes authority.
- Every model step carries an explicit cap no greater than the remaining Run ceiling; `RunService.issueModelInvocationCapability` and the persisted budget remain authoritative. The adapter sizes its request; a store-side 402 fails closed. No direct provider call bypasses ModelGateway.
- Runtime stream `type` mismatch, malformed/missing terminal usage, abort, upstream failure and settlement failure cancel/error the stream and settle usage as `unknown`; never confirm unverified usage or mark the Run succeeded. A clean terminal can succeed only after verified usage settlement and final event append.
- Existing `remote_ag_ui` and `remote_mastra` execution remain refused with `REMOTE_RUN_BUDGET_UNVERIFIED` until separately reviewed upstream enforcement and usage proof exist. Keep existing skills, tools, HITL and pause/resume behavior.
- Use the approved uncommitted-checkpoint strategy: HEAD, complete before/after contents of owned files, full git-visible manifests, task-only patch/new files, SHA256, RED/GREEN logs, protected-file comparison, independent backend validation and independent Spec/quality Review. No commit/stage/stash/reset/rebase/merge/push/PR/publish/worktree removal.
- No local or production DB operation or isolated DB probe; the user is configuring the isolated test database. PostgreSQL RLS/concurrency/restart/two-instance acceptance remains unverified.

## Review Focus

- A second tool step with a static CopilotKit config cap still gets a smaller `max_tokens` and capability maximum equal to remaining budget; Task 1 multi-step test pins this.
- A malformed stream `type`, absent terminal usage, or failed confirmation produces `unknown`, RUN_ERROR/failed Run and zero success calls; Task 1 gateway and Task 3 Runner tests pin this.
- An abort that CopilotKit reports as `RUN_FINISHED{outcome:"cancelled"}` or as completion without a terminal event never becomes a succeeded Run; Task 3 tests pin both shapes.
- A route credential, plan endpoint, native base URL or provider/model drift after admission refuses before credential use/network; Task 3 consumes the independently reviewed route-rebind helper and tests the gateway composition.
- A stale/released/replaced request owner, stop race or failed event append cannot produce success; Task 3 tests the exact lease and event-before-complete ordering using the reviewed success API.
