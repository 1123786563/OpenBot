## What to build

杀进程重启后不重复 dispatch，也不重复扣费。

## Acceptance criteria

- [ ] 进程在派发前/派发后被杀，重启后扫描都能识别对应未知项
- [ ] 扫描不触发第二次供应商派发，也不重复扣费
- [ ] 多 worker 并发扫描时同一 RecoveryItem 只被认领一次
- [ ] RecoveryItem 固定原预留、付款账户与价格版本

**Produces（本 Ticket 交付给下游的契约）**

- RecoveryItem { attemptId, reservationId, payerRef, snapshotVersion, rateVersion, state, failureCount, lastReason, detectedAt }
- 扫描任务：识别“承诺已写入但供应商派发结果未知”的记录并生成 RecoveryItem
- 认领语义：多 worker 下同一 RecoveryItem 只被一个 worker 认领处理

## Implementation steps

1. 复用既有周期扫描模式实现恢复扫描，识别 dispatch 未知状态
2. 为每条未知记录生成 RecoveryItem，固定 attempt/reservation/payer 与原价格版本
3. 实现认领锁，避免多 worker 重复处理或重复派发
4. 扫描本身不得释放预留、不得重新派发供应商请求
5. 先写失败测试：杀进程后重启，扫描识别未知项且不重复派发、不重复扣费
