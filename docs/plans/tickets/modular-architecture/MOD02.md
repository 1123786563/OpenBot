# MOD02：抽离 HTTP 路由装配并保持认证与挂载顺序

根架构 Issue：https://github.com/1123786563/OpenBot/issues/620。阶段：第一批：基础。本票覆盖：AR03；迁移 S1；不重复 #614 的 BA 专用启动验收。

## 目标与范围

从现有 HTTP 应用工厂抽出一个真实运行入口的路由组合，调用方只传声明依赖；保留 middleware/认证/Origin/业务路由的原次序和实际响应。

本票不新增业务功能、不替代已存在的功能 Issue；优先封装当前已启用行为。接口内部调整保持现有对外合同。

## Consumes / Produces

- Consumes：直接依赖票的已验证并集成 Interface、当前公开 wire、对应原功能合同与现有数据事实；不能引用另一票的私有 store。
- Produces：具名 HTTP 装配工厂及窄依赖合同；原 app 入口兼容调用；新旧路由行为对账。
- 全部 Interface 必须定义输入/结果、当前资格、幂等键、版本、事务/锁与超时/未知结果行为；供应商类型与秘密保留内部。

## 验收标准

- [ ] 实际启用路由的方法、认证、错误和响应合同不变
- [ ] 未认证、错误 scope、preview Origin 与合法请求覆盖原有判定
- [ ] 可选能力关闭不挂空成功路由，缺必要配置保持原拒绝
- [ ] 业务规则仍归所属 Module，不能只把 app.ts 全文换文件

## 验证与失败处理

复用现有路由证据，补装配次序/开关反例与实际启动 smoke；运行相关 typecheck。

优先复用匹配当前代码的有效证据，再补缺失的 Interface 行为/真实集成验证。回退保持单一写入者与稳定持久事实；未知副作用或费用不能为回退而删除/释放。不能验证的场景明确报告阻塞；完成前修复真实有效 critical/high/medium finding。
