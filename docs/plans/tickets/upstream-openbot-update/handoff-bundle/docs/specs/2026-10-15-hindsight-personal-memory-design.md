## 目标与范围

在自托管 OpenBot 中，用自托管 Hindsight 改善个人记忆的跨会话语义召回、时间变化处理和多次经历综合。OpenBot 继续作为来源、审核、可见性、更正、遗忘和保留状态的权威；Hindsight 负责已确认内容的索引、检索、排序及产生待审核的派生判断。逐步替换 CopilotKit Intelligence 的个人记忆路径，团队共享文档和知识库、OpenMuse 独立的精确 ID 私有记忆不纳入本次范围。

上线即对适用用户启用，不设按公司试点；先满足已批准的公司与团队多租户方案要求的全功能隔离验收。Hindsight 模型调用只经 OpenBot 已批准的模型网关，自动处理费用由平台承担，按公司和个人设预算上限。

## 业务规则

1. 普通对话及已启用的授权连接来源可以提出候选记忆。未审核候选对所有跨会话召回不可见，包括原 Bot、频道和降级路径；它也不能成为派生判断的依据。候选展示内容、来源、时间与证据，本人可确认、编辑或拒绝；30 天未处理则过期清除。
2. 用户明确说“请记住”的普通事实可直接确认为其明确表述的内容，不自动扩写。密码和令牌即使被要求记住也拒绝保存。医疗、财务和客户资料只在明确要求时提出候选，并需再经一次明确审核。
3. 仅本人明确设为通用的个人偏好可在同公司获授权的 Bot 间使用。团队对话、连接来源和 Bot 形成的业务事实默认维持团队、来源和 Bot 权限；确认不使其变为通用偏好。个人记忆不跨公司，管理员身份不授予员工内容访问权。
4. 派生判断只使用同一授权来源或通用个人记忆中的已确认依据，判断自身也须确认；首版不跨不同授权来源综合。每条判断保留完整依据关系，任一依据被遗忘、撤销或失权即停用相关判断。
5. 当前与历史问题按已确认事实的生效时间回答；明确更正保留历史，不明时间不臆断。涉及历史变化或派生判断的回答提供可展开的记忆依据、来源和有效时间，并可从该处更正或遗忘。
6. 本人可分别暂停学习新记忆与暂停使用已有记忆。前者停止自动提出候选，后者立即阻断召回而不删除数据。网页聊天、频道和定时任务使用同一规则。

## 隔离与接口设计

OpenBot 的授权模块先从可信会话或后台任务身份取得公司、用户、团队、Bot 和来源资格，再调用个人记忆模块。客户端不得指定 Hindsight bank。个人记忆模块的外部接口只表达“提出候选、审核、召回已确认内容、更正、遗忘、查看依据”，隐藏 bank、文档 ID、索引重试及故障降级。Hindsight 是该模块内部的索引与检索适配器，不是权限或审核权威。

建议在单套自托管 Hindsight 中用不同 bank 表达硬隔离：每个 `(tenant, user)` 有通用个人偏好 bank；团队或来源受限内容进入各自 `(tenant, user, workspace, source-or-bot)` 范围的 bank。只有 OpenBot 授权结果明确列出的 bank 可被查询。来源与团队权限变动后重新计算可用 bank；结果必须按 OpenBot 当前已确认记录、有效时间及权限再次核对。缺少 OpenBot 记录、证据映射不完整或来源失权的结果均丢弃。tag 仅作检索分类，不承担公司、用户、团队或来源的安全隔离。

Hindsight API 和控制台不直接暴露给终端用户或公司管理员。自定义 TenantExtension 校验由 OpenBot 签发的服务端身份，OperationValidatorExtension 再限制该身份可访问的 bank；后台任务的身份与 bank 也由 OpenBot 签发，不信任请求体或可由客户端伪造的头。首选共享 Hindsight schema 与多个隔离 bank，以符合 OpenBot 共享数据库的已批准方向；若容量或隔离评估要求每公司独立 schema，再另立架构决策并验证 Hindsight 的跨 schema 维护成本。

每条 OpenBot 已确认记忆以稳定文档 ID 幂等同步到 Hindsight；仅从 Hindsight 取得命中和排序，再取回 OpenBot 已确认原文或已确认派生判断供 Bot 回答。Hindsight 新提取的事实、自动观察和 `reflect` 文本不直接进入 Bot 上下文。观察只能作为待审核判断，须能映射到完整、当前有权的原始依据；映射缺失时拒绝展示或使用。OpenBot 保存同步状态和重试任务，不能把同步失败表示为已索引。

## 生命周期与故障

- 已有 OpenBot 记录、已确认且公司归属可证的记忆迁入 Hindsight；未审核记录继续待审。只在 Intelligence 中存在而没有 OpenBot 记录的旧记忆不迁入也不导出；不能由全局用户 ID 猜测其公司归属。切换前核对实际迁移数量与隔离结果。
- Hindsight 暂时不可用时，只从 OpenBot SQL 中召回已确认且当前有权的记忆，提供较弱的本地检索；新确认内容留在 OpenBot，恢复后补同步。预算耗尽则暂停新的后台处理，保留待处理状态，不影响已确认内容的授权读取。
- 遗忘或来源撤销先在 OpenBot 阻断全部召回及相关派生判断，再重试删除 Hindsight 文档及关联观察。删除使用稳定 ID 和持久状态，恢复备份后必须先重放遗忘与撤权记录，才能重新开放召回。
- 分别报告“已停止使用”与“受控副本清除完成”。Hindsight 含内容的模型追踪关闭，已结束任务载荷配置 1 天保留窗口，受控备份配置至多 30 天保留窗口；只有活跃数据、任务记录与备份都有实际清理证据时才标记后者，不能只依赖保留期限配置。OpenBot 网关与外部模型供应商的日志保留应按已有批准策略单独核验，不能冒称由 Hindsight 删除接口覆盖。
- 由于 OpenBot 保留已确认原文，可考虑关闭 Hindsight 原始文档文本持久化；实施前须验证检索、来源关联和删除证据仍满足验收。正式配置必须固定版本并显式设置隐私相关默认值。

## 验收场景

1. 用户确认“周报用简短要点，例会周五”；两次不同会话中确认“周报风险优先”的依据，再确认“下周起例会改到周一”。同公司另一个获授权 Bot 备周报时用简短要点、风险优先、周一；问旧日期时答周五，并能展示依据。拒绝或删除任一依据后相关派生判断不再出现。
2. 同一个全局用户在甲、乙两家公司各有 Bot；甲公司的个人记忆、候选及派生判断不能在乙公司召回。甲公司团队 A 的业务事实不能由团队 B 的 Bot 使用；本人明确设为通用的个人偏好可在同公司获授权 Bot 间使用。公司管理员看不到员工记忆内容。
3. 自动产生的未审核候选在网页、频道、定时任务、Hindsight 可用及 SQL 降级情况下均不能被 Bot 跨会话使用。敏感候选需额外确认，密码和令牌不留存。
4. 断开来源或遗忘后立即不能召回原始内容及相关判断；Hindsight 故障、任务重试、备份恢复后仍不能复活。界面分别展示即时阻断与受控副本清理状态。
5. Hindsight 宕机、同步积压或平台预算耗尽时，已确认内容按权限降级可用；未索引内容和未经审核判断不会被宣称为已学习。旧 Intelligence 独有记忆不进入新系统。

## 实施前核验

本设计不是运行验证。实施前须固定 Hindsight 版本，用真实自托管部署验证自定义认证与操作校验、bank 隔离、观察依据映射、文档删除与派生观察失效、隐私配置、跨团队权限变化及恢复备份后的遗忘重放。还须先盘点当前 OpenBot 个人记忆缺少公司归属字段和本地召回会返回未审核记录这两处现状，按已批准多租户设计完成迁移与收紧；任何一项未通过均不能开放全员记忆功能。
