# Bifrost 直连请求以 OpenBot 积分预留作为准入条件

外部 Bot 直连 Bifrost，而个人积分台账由 OpenBot 管理；Bifrost 原生周期预算既不能表示一次性积分余额，也不能防止并发请求超支。因此扩展 Bifrost 请求准入，在供应商调用前向 OpenBot 同步申请跨 Bot 共享的原子预留，未成功预留则拒绝，调用后可靠提交实际费用用于幂等结算。一个 OpenBot 用户关联一个 Bifrost Customer，凭据及各供应商尝试始终追溯到该个人主体。

只有价格完整且可强制成本上限的调用能力可以启用；缺价格、经验估算或缩短预算同步间隔不能替代此条件。结果未知时保留预留，直到可靠结算或确认无费用后释放；Key 过期不免除既有消费责任。请求锁定兑换比例及价格依据，细小费用按用户累计尾差。

代价是新请求准入依赖 OpenBot 计费服务可用性，并需要 Bifrost 扩展及可靠结算恢复。严格积分路径与 ADR 0001 的经验计数及低估后人工兜底存在不同保证，不能直接沿用后者并宣称严格防超支；ADR 0001 对已有路径的适用性不由本决策自动改变。

依据：`docs/specs/2026-10-14-bifrost-integration-design.md` 中用户确认的 Q5、Q10–Q14。具体恢复协议、支持能力及验证证据仍待完整设计与实施，不代表当前代码已提供上述保证。
