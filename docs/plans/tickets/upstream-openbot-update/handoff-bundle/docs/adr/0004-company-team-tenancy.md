# 复用公司租户与团队工作空间，并分开公司及个人付款账户

以 Tenant 表示公司、Workspace 表示公司内平级团队，复用全局 User/Principal 与公司 Membership，补充多对多 Workspace Membership。员工可加入多个团队；团队之间默认不可见，明确发布为团队公共的 Bot 和知识库可由有效团队成员使用，个人资源及管理动作保留独立授权。

采用共享应用与 PostgreSQL，保留现有业务表和权威写入方，扩展现有事务及授权入口，逐业务闭环接入公司、团队、个人权限和数据库隔离。全部现有功能、客户端及后台入口完成隔离和验收后统一开放多租户。团队公共规则采用新的授权策略版本，不修改旧策略的隐式含义。

公司工作台使用公司统一余额，按团队及使用人记录用量。外部 Bot 个人授权直连 Bifrost 保留个人余额、个人治理主体与独立模型授权；ADR 0002/0003 的该路径决定继续有效。付款账户由服务端按业务归属或已签发授权固定，预扣、结算、对账及尾差跟随同一账户，余额不足不切换到另一账户。个人模型 Key 不授予公司内容权限。

这项选择复用已有实体、授权和积分机制，减少替换业务存储的范围；代价是所有旧入口仍需逐项接入隔离，以及公司与个人付款账户需要明确区分。复用通用授权入口不能替代全功能覆盖检查。

未选每公司独立部署：业务代码改动较少，但不满足本次共享平台目标。未选每公司独立数据库：当前没有独立数据库需求，会增加连接路由、迁移和运维复杂度。未选逐人复制全部团队资源 Grant：加入/退出团队需要批量修改授权且易残留。未选所有调用统一公司余额：用户明确要求保留 Bifrost 个人余额路径。
