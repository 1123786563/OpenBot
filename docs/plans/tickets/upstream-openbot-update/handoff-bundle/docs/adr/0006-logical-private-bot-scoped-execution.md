# 保留逻辑私有 Bot，并按业务范围隔离执行环境、工具和个人上下文

用户于 2026-10-16 在企业个人 Agent 规格审核后明确选择：“保留逻辑私有 Bot，并为实际执行环境、工具和个人上下文建立明确的范围隔离”。保留原 OpenMuse 每用户幂等预配的逻辑私有 Bot 身份与档案；公司和团队切换不要求为产品身份再创建另一套私有 Bot。实际业务通过公司、团队、本人和逻辑 Bot 共同确定的范围解析环境、工具及个人上下文，逻辑 Bot 标识不作为业务授权或物理 Computer 的唯一寻址依据。

这细化了 [OpenMuse 私有 Bot ADR](../../apps/openmuse/docs/adr/0004-private-openmuse-bot-per-user.md)在企业环境中的含义，并遵守 [ADR 0004](0004-company-team-tenancy.md)的公司/团队/个人隔离。不同范围的浏览器登录态、工作目录、工具授权、连接选择、会话历史和来源受限上下文不自动复用；共享无状态基础设施或中性展示标识不能扩大数据访问。已批准的同公司通用个人偏好及显式分享仍按各自授权规则处理，不被本决策扩大或取消。

未选按公司/团队分别创建新的产品私有 Bot：会增加身份、档案和用户选择的重复管理。代价是所有运行、工具、Computer、个人上下文及旧入口都必须明确解析范围，不能继续以全局 owner/Bot ID 对应一份可变业务状态；环境引用、控制凭据和缓存也须绑定范围并支持撤权。物理实例数量、容器池、数据库布局及迁移步骤由后续实现设计决定，不能把一个逻辑身份解释为只能有一个物理执行实例。

规范边界及验收见[企业个人 Agent 规格 §4.1、A36–A41](../specs/2026-10-16-enterprise-personal-agent-product-permissions-spec.md)。历史环境与数据仅在范围归属可证时绑定，未知归属受控隔离。此决策关闭该规格 C01 的方案选择；不等于批准整份产品草案、其他建议、实施或发布，也不表示隔离已通过运行验证。
