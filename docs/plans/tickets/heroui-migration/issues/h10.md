## 验收标准

- [ ] AC1: 中文 IME 组合期间 Enter 不误发，单次提交只生成一次发送；disabled/pending/停止/重试与原合同一致。
- [ ] AC2: 附件添加/粘贴/拖入/取消/上传失败/重试生命周期不变，非接收区 drop 不卸载页面。
- [ ] AC3: 流式追加、手动滚动、回底部和历史加载锚点正确，不因按钮换库重新挂载消息列表。
- [ ] AC4: 问卷/消息滚动的 render 动作与 HeroUI 按钮兼容；上下文菜单支持已验证的右键/键盘/触摸策略。
- [ ] AC5: 实时屏幕键盘接管、释放与快捷键优先级正确，菜单/弹窗焦点不吞掉屏幕控制。
- [ ] AC6: 跨公司/团队会话切换保留原归属，不把草稿、附件或异步响应显示到新范围。

## 实施任务草案

1. 按 H01 结论迁移通用动作和消息组合，保持编辑与滚动引擎。
2. 将旧 render 适配限制在动作入口，不重写整个问卷或 scroller。
3. 跑附件、IME、流式滚动和屏幕键盘真实浏览器场景。

## Handoff

Consumes：[H03 #446](https://github.com/1123786563/OpenBot/issues/446)、[H09 #452](https://github.com/1123786563/OpenBot/issues/452) 所交付并已审查集成的 Interface/检查点；根 CONTEXT、适用 Spec/ADR。

Produces：聊天与实时屏幕迁移检查点、专用引擎保留与兼容证据。

Verification：app/tests/composer-* / live-screen-keyboard / carousel-keyboard；tests/e2e/bot-chat.e2e.ts；真实 IME/滚动。

测试遵守 ADR 0008 的 native/driven/engine 分层；Focus、portal、IME、定位和滚动必须有真实浏览器证据。复用同版本有效证据，只补缺失验证。

Resume：读取 manifest、当前 Task Brief/Ledger 与 Git，核验上游检查点；不重新派发已 verified 工作。阻塞项保留具体证据；缺陷回到对应实现任务，不由验证者修改源码。

## 组内共同约束

本组为设计与排期拆分，尚未授权实施。默认采用主 Web 应用 app/、保留现有 WorkBuddy 视觉；不包含独立 desktop 引导程序、OpenMuse/Bifrost 子模块和 Craft 生成模板的迁移。用户如选择整体重设计或扩大范围，应先更新父方案。

保留 React/Vite/TanStack/CopilotKit 及业务 API；保留 PromptArea、Streamdown、Recharts、Embla、问卷/消息滚动的专用行为。不得改变权限、业务范围、付款账户、错误事实或数据协议。

正式实施按根 AGENTS：执行工作区与 BASE → writing-plans → SDD → 独立验证/Review → OCR → 必要修复与复审。没有提交授权时使用未提交增量检查点；不因缺少提交停滞。标签 ready-for-agent 不是实施授权；当前方案仍待评审，暂不添加此标签。

共享 UI、主题、布局、locale 和 lockfile 同一时刻只有一个写入者。默认串行执行；依赖已关闭仍须核验已审查代码集成与验收证据。涉及其他 Issue 所有权的修正，先记录共享 Interface 变更，不并行覆盖文件。
