## Parent

Spec: https://github.com/1123786563/OpenBot/issues/472 — 内置 Agent 执行迁移 Mastra。本 Issue 是其正式子 Issue。

## What to build

用户上传文件或图片并继续对话，刷新、翻页或重连后仍能看到完整消息及工具关联，Bot 读取同一份有权限的历史。

## Acceptance criteria

- [ ] 完整保存文本、文件/图片引用、工具调用与结果、必要 activity/state/审批 metadata；展示文本投影不替代模型历史。
- [ ] 同一输入幂等键只产生一个消息 intent，输出重试不会重复追加；序列与分页稳定，未 finalized 内容不进入模型上下文。
- [ ] ConversationService 是同一会话的唯一消息写入者，禁止 Mastra Memory 自动再次 append；snapshot 持久化与对话写入分别管理。
- [ ] 附件在所属 thread、公司/团队/本人权限验证后才读字节或签发下载；另一用户、团队或公司不能借已知 ID 取得内容。
- [ ] 刷新、重连、服务重启和 pending intent 修复保持完整 parts 与调用关系；损坏/缺失历史明确失败，不退回空历史继续。
- [ ] 保留既有历史清理规则，客户端伪造 system/tool 历史不成为服务端权威；原语音归档与聊天读取一致。

## Scope boundary

会话与附件完整性，不做旧平台全量历史导入、不新增自动长期记忆。

## Interfaces

- Consumes：前置票经审查的实际交付合同，以及父 Spec 的身份、预算、消息与恢复约束。
- Produces：授权完整历史读写、稳定消息身份与幂等/parts 转换合同。
- Responsibility：backend_implementer / frontend_implementer；相应只读验证者 + 独立 Spec/质量 reviewer。

## Verification

上传/回答/刷新/翻页的真实客户端流程；工具 pairs roundtrip、重复/中断写入与受限数据库跨范围测试。

## Failure handling

跨系统写入用 intent/reconcile，失败不能用双写或丢消息恢复服务。
