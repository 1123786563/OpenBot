## What to build

用户让 Bot 调用已连接应用，Bot 只使用被授权工具，正确处理结果/拒绝，并在多步执行中持续遵守预算。

## Acceptance criteria

- [ ] 工具发现与授权分离；只提供经过现有 grant 和工具筛选的工具，参数经原 schema 校验，实际调用仍过 policy、credential 和 audit。
- [ ] 执行时重新检查撤权与连接归属；同名工具、保留名冲突或非法工具名明确处理，不能覆盖系统工具。
- [ ] 供应商错误、平台拒绝和外部不可信内容保持原语义，不把供应商拒绝当普通成功数据。
- [ ] 模型每一步签发不同 capability，首步预算 100 消耗 70 后次步最多申请 30；预算拒绝不自动 retry 或换路由。
- [ ] 保留现有最多 8 步的工具循环；到上限给出真实结果/原因，不能伪造工具执行或完整成功。
- [ ] 工具提议、实际执行、receipt 与观测只关联同一操作一次；失去 owner 或用户撤权后阻断新的外部调用。
