## What to build

用户的定时任务到点后使用与网页相同的 Bot、工具、记忆和预算执行，结果出现在原会话且重复投递不重复推进。

## Acceptance criteria

- [ ] 从持久调度记录和可信目录重建当前 scope/受限身份；队列中的任意 tenant/owner 字符串不构成授权。
- [ ] 准入前确定明确预算和固定 payer；缺配置拒绝并显示原因，不猜默认公司或无限额度。
- [ ] 重复 firing/队列重投递只认领同一推进意图；执行 lease/heartbeat/stop 由 OpenBot 权威管理，不使用 Intelligence socket/私有 thread lock。
- [ ] 相同对话完整历史与当前授权上下文用于运行，工具参与需求按通用挂起合同处理，无浏览器不绕审批。
- [ ] 失败、暂停、取消与最终结果准确回写原会话，刷新后可见，原运行不会被队列重试重复收费。
- [ ] 员工撤权/删除、lease 丢失或预算耗尽后阻断新敏感调用，有真实错误与结算证据。

## Interfaces

- Consumes：前置票经审查的实际交付合同，以及父 Spec 的身份、预算、消息与恢复约束。
- Produces：可复用受控 headless turn 合同和后台准入/预算来源约束。
- Responsibility：backend_implementer；相应只读验证者 + 独立 Spec/质量 reviewer。
