## What to build

用户把工作交给另一 Bot 时，目标只得到允许分享的上下文，并准确回传一次结果，后台回收器不重复推进。

## Acceptance criteria

- [ ] 目标 Bot 通过发起人的授权 roster 解析，删除/失权目标明确拒绝，Mastra 默认子 Agent 规则不替代该授权。
- [ ] 原交接签名、最大深度、私有分享审批和目标 thread/channel 关系保持，子 Bot 不继承父 Bot 全部凭据、工具或个人记忆。
- [ ] 交接与返回结果采用稳定业务身份；delivery/reaper 重投递不会重复通知或重复创建对话。
- [ ] 执行通过同一 headless turn，每个子调用仍有明确预算/付款归属；不使用 Intelligence runner/socket。
- [ ] 目标失败/等待/已停止如实回传，不能在仅已接受任务时对用户称目标已完成。
- [ ] 测试跨团队/公司、私有分享拒绝、撤权、深度超限和结果读取权限，兼顾正常交接可用。

## Scope boundary

业务 handoff 装配，不引入新的 supervisor/network 产品或开放 remote Agent。

## Interfaces

- Consumes：前置票经审查的实际交付合同，以及父 Spec 的身份、预算、消息与恢复约束。
- Produces：受控交接输入/结果读取与 reaper 幂等合同。
- Responsibility：backend_implementer；相应只读验证者 + 独立 Spec/质量 reviewer。

## Verification

两 Bot 正常交接加一次私有分享等待恢复；另测 reaper 重试、越权和目标失败。

## Failure handling

无法共享就等待审批或拒绝，不能先发送私有内容再补授权。
