## 1. 核心设计决策（先例驱动，证据见 PLAN.md）

**发布 = 资源注册表上的显式受众事实，不写第二份权威。**

1. **发布状态落在 `enterprise_resources` 注册行**（kind='bot'，visibility='workspace'）。这与 MT036 把知识库注册为 kind='knowledge' 资源行完全同构：MT009 的团队公共动作规则（read 经 MT008 判定、run 带依赖校验、管理动作拒绝、非成员 canonical not-found）**原样**适用于已发布 Bot——验收 1 的「按 MT009 规则可 read/run」由复用逐字成立，本模块不复刻任何判定逻辑（Spec §4.2「不能通过新旧各写一份完成迁移」；MT010 先例：分享事实不改归属行）。
2. **不注册新迁移任务**：设计不新增任何表/列/策略/授权。资源行 operator INSERT（租户范围策略）与 visibility 列级 UPDATE（MT008 授权，行策略钉 app.tenant_id + app.resource_id）都是已验证交付。MT017 因此是**三新文件**（模块 + 测试 + 夹具），migrate-test.ts / migration-tool.test.ts / schema barrel / src/index.ts **全部零改动**——比 brief 预授权的「授权编辑点」更窄的改动面（票注「迁移动作复用 MT003 工具 manifest 机制」在无新 schema 对象前提下以零新迁移任务满足；provision 脚本仍经 MT003 工具按 brief 十四任务链逐任务 generate→apply 存档）。
3. **发布/取消发布是 owner 动作**（MT016 编辑门同源）：可见性门（归属行 active + 同团队 + 公司成员 active/epoch 匹配签发时版本 + 团队成员 active，MT016 readVisibleOwnership 同款事实切片本地镜像）→ owner 门（`PUBLISH_FORBIDDEN`，已过可见性门不新增信息）→ 受众策略。不可见者（非成员/跨公司/已删除）一律 canonical not-found。
4. **受众是显式输入，词表只含 "team"**：缺受众 throw `PUBLISH_AUDIENCE_REQUIRED`（票面「必须选择明确受众」，绝不隐式默认当前团队）；形状坏 throw `PUBLISH_AUDIENCE_INVALID`；type≠"team" deny `PUBLISH_AUDIENCE_UNSUPPORTED`（指定范围受众属后续票据）；受众 tenant≠归属 tenant deny `PUBLISH_AUDIENCE_CROSS_COMPANY`（验收 4）；受众 workspace≠归属 workspace（同公司跨团队）deny `PUBLISH_AUDIENCE_NOT_OWNING_TEAM`（Spec §5.1：跨团队共享是显式例外路径的业务，不在默认团队公共规则内偷放行）。判定顺序：受众纯校验（不触库、只关于请求自身）→ 可见性门 → owner 门——非成员对同一请求得到 canonical not-found，不泄露归属。
5. **注册行不变量守卫**：同 (tenant, id) 注册行若 kind≠'bot'、workspace≠归属团队，或发布路径上 status≠'active' → `BOT_PUBLISH_STATE_CONFLICT`（响亮，绝不静默改写他人种类的行）。已 'workspace' = 幂等 no-op（不推进版本号）；NULL/'private' → 'workspace'（owner 对自己 Bot 的显式选择——与 MT008 管理**批量**迁移「绝不翻转 private」语义不同：那是清单驱动的第三方动作，这是属主本人的发布动作，票面「显式发布」路径）；无行 → INSERT（display_name 取归属行服务端事实，kind='bot' 固定，客户端不能声明任何归属/种类属性——MT016 归属不可客户端声明同源）。
6. **取消发布 = visibility 回 NULL**：团队公共使用路径立即关闭（MT008/MT009 全部调用时判定、无缓存——**发布前签发的 scope 下一次判定即 canonical not-found**，scope 不携带任何内容权，验收 2「已运行会话不泄露」由调用时重验保证）；显式 grant 路径与团队公共路径独立不受影响（测试钉死：取消后持 grant 成员 read 仍 allow、run 仍不可见）；幂等：重复取消/未发布/注册行已软删一律 allow。
7. **事务纪律与 MT016/MT008/MT009 同族**：assertScopeContext → assertTrustedScope → operator 事务（read committed + lock/statement timeout → 事务本地 app.* → advisory 锁）。锁序 tenant → principal → membership → workspace-membership → bot（共享，MT016 键族）→ resource（**排他**，MT008 键族——与判定读共享锁、MT008 迁移写排他锁串行化；bot→resource 单向边无环）。UPDATE 前 set app.resource_id（行策略要求，resource-visibility.ts 同款）。全程受限 operator 角色；数据库层纵深防御：注册行 workspace 复合外键使跨租户行结构上不可能存在。

## 4. 披露 D1–D8

- **D1（无新迁移任务）**：发布模型复用 MT008 的 visibility 属性与资源注册表——无任何新 schema 对象，故 migrate-test.ts / migration-tool.test.ts 零改动（比授权编辑点更窄）。票注「迁移动作复用 MT003 工具的 manifest 机制」以两层方式满足：环境按 brief 十四任务链经 MT003 工具逐任务 generate→apply 存档；旧 public 显式迁移测试直接调用冻结的 MT008 manifest 入口（真实函数，非重写）。
- **D2（两表面语义披露）**：取消发布只关闭 MT008/MT009 资源使用路径（read/run 及一切经注册表的团队公共面）；MT016 归属可见性（同团队列表/详情）是其已验收的独立语义——取消发布后同团队成员经 MT016 面仍可见归属对象（归属未变），使用权立即关闭。测试双向钉死（验收 2 末例）；MT017 不改 MT016 文件、不重复其判定。已运行会话不泄露由调用时重验保证（stale scope 测试）。
- **D3（private→workspace 翻转语义）**：owner 发布动作对显式 'private' 注册行翻转为 'workspace'——属主本人的显式发布选择（票面「显式发布」路径），与 MT008 清单驱动**批量**迁移「绝不翻转 private」的第三方语义不同；两者不冲突（不同动作主体、不同入口）。本票测试未覆盖 private→workspace 用例（夹具只种 NULL 遗留行），该路径由 MUT5 覆盖的 INSERT 路径与 UPDATE 路径共同的结构保证 + 代码审查确认，属已知最小缺口。
- **D4（MUT5 中止签名）**：MUT5（注册行 INSERT 移除）的 throw 从 beforeAll 逃逸导致套件在 17/34 用例处中止（14 pass / 3 fail）——捕获有效（发布落库用例全灭），中止签名如实存档未粉饰。
- **D5（夹具 superuser stand-in）**：`setTenantPolicyRevision`（公司 A → workspace-v1）经 setup 通道执行——enterprise_tenants 无受限角色 UPDATE 策略，MT011/MT036 同款披露；判定侧从不使用该通道（MT008/MT009 判定全程受限 data 角色 + 真实 RLS）。公司 B 保持 tenancy-v1：跨公司不可见性与策略版本无关的对照。
- **D6（发布审计字段不在本票）**：published_by/published_at 未落（enterprise_resources 无此列，本票不加列）；发布事实 = visibility='workspace' 注册行本身。审计需求属后续票（诚实边界，模块头注释钉死）。
