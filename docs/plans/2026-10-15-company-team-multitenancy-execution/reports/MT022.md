## 1. 设计要点（新文件 `server/src/enterprise/tenancy/conversation-actions.ts`，纯新增）

- **每动作独立判定**（AC1/AC2/AC4）：send / read / replay / rename / archive 各自在**自己的**数据事务内完成 assertScopeContext → assertTrustedScope → read committed + lock/statement timeout → `set_config('app.*', true)` 事务本地 → advisory 共享锁（键序 tenant → principal → membership → workspace-membership，MT021 同款）→ 成员事实重验（公司 active 且 `epoch === scope.memberEpoch`；团队 active）→ 会话归属比对（RLS 租户臂先行 + workspace + principal）→ 执行或 canonical verdict。写动作（send/rename）在归属判定后再取 conversation 排他锁，键族与既有 conversations 服务一致（`["conversation", tenantId, threadId]`）。
- **replay 是独立授权面**（AC1 注记）：独立输入校验、独立事务、独立成员/归属重验，不委托 readMessages——否则它就是读的别名，构成 AC1 的绕过面。replay 返回全线程升序消息。
- **读分页语义**：`readMessages` 返回时间线**最新一页**（seq 降序读取、items 升序返回），`nextBeforeSeq` 钉在本页最早一条的 seq 上（严格小于续读，`limit` 1..100 缺省 50，`beforeSeq` ≥1）。
- **消息存储契约与既有 conversations 服务同源**：digest 复用 `conversations/store.messageDigest`（NFC + CRLF→LF + sha256）；`clientMessageKey` 幂等（同键同 digest 原样返回、不新占 seq），同键不同内容 = 响亮 `message_conflict`（409 形状，零写入）；发送走 `lastSeq+1` 预订 + INSERT + text part（与既有 platform append 同构）。
- **AC4 双臂防线**（MT016 D4 先例的分解钉死）：epoch 臂（MT006 撤权/MT007 恢复递增 epoch → 已签发 scope 失效，恢复后旧 scope 仍被拒）与 status 臂（suspended 即拒、与 epoch 无关——「无 epoch bump 依赖」）各自有独立可捕获的用例；全部在动作自身事务内重验，无任何跨调用缓存（MT014 验收 4 纪律）。
- **AC3 公共 Bot 会话**：按归属谓词（workspace + principal）判定，会话属使用者本人——团队他人与发布者五动作全部 canonical not-found；MT021 冻结面的 list/count/detail 在套件侧钉同一事实（消费不改）。
- **backend 门**：消息面三动作只对 `storage_backend='platform'` 生效（响亮 `CONVERSATION_BACKEND_UNSUPPORTED`）；管理动作（重命名/归档判定）是会话级元数据、不限 backend，且门在授权**之后**——非成员对 mastra 会话仍是 canonical not-found，不泄露存在性。
- **deny 零写入零副作用**：一切拒绝发生在任何 INSERT/UPDATE 之前；套件以 raw 计数不变量钉死。
- **不可见语义**：一切拒绝（不存在/跨公司/跨团队/同团队他人/被撤权）返回 MT011 冻结实例 `notFoundVerdict()`——单元素字节集断言钉死。
- **无迁移**：会话/消息归属列与 RLS（0057 基线 + `enterprise_*_data_scope`）已存在；本票交付服务面，migrate-test 链保持十六任务（裁定 Q2/方案B，见 D1）。
