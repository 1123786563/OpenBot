## 5. 诚实披露（D1–D8）

- **D1（库名口径）**：brief 写「端口 55565（库名 w14c）」。w14c 不满足仓库硬守卫（`enterprise-database.ts` 强制 `openbot_enterprise_*` 命名，非该命名 migrate/套件一律拒绝），按工具链强制约定取 `openbot_enterprise_mt031_test`（+ assigned/kb 两库），端口 55565 逐字采用。判定依据是仓库内不可绕过的守卫而非自行重设计；如 w14c 另有含义请协调方指正。
- **D2（目录策展通道）**：公共目录对受限业务角色零写授权、模块零目录写方法（AC1 断言钉死），因此测试种子经披露过的超户安排 stand-in 写入（fixture 注释如实标注）。生产侧目录策展属部署级行为（下游装配票接线），本票不定义目录写 API。
- **D3（连接 status 列重构）**：GREEN 后 REFACTOR 阶段移除了 enterprise_plugin_connections 的 status 列——它只会有默认值且无设置面，是不可钉死的死防线；解绑 = 删行（MT010 先例）。迁移 digest 相应变化（f73bb8ab…），专用库按 MT041-fix 先例重建该任务（drop 三表 + journal 行清除 + 三步配方重放，`08-mt031-migration-regen.txt`）。顺带移除 decideInstall 的 catalogExists 分支（FK 使其不可达）。
- **D4（migrate-test.ts 误删事故与恢复）**：REFACTOR 编辑中一次脚本化删行过宽，误删 5 个既有任务（MT004/009/016/026/027）的 status 列行。以 checkpoints 归档的 generated SQL + 16 任务 planDigest 对领取态逐一复算（oracle）恢复并逐字节验证：**16/16 前置任务 digest 与领取态一致**（MT027 ab50bf11…、MT070 430bd368… 等全部吻合）。事故、恢复与 oracle 验证如实存档（verification/ 证据 + 本节）。
- **D5（MT041 时钟抖动）**：全量回归曾出现 MT041 两个用例失败（`finishedAt <= Date.now()`），实测为 Docker Desktop VM 与宿主机时钟 ±10–120ms 漂移（漂移转正时该断言必败，与 MT031 零面接触、MT041 域文件 sha256 与领取态一致）。时钟对齐窗口内复跑 **1025/0**（11-final-green.txt）；漂移实测与零改动核验存档 `10-mt041-clock-skew-env.txt`。终态门槛以对齐窗口的 1025/0 为准。
- **D6（MUT-5 存活）**：uninstall 模块 WHERE 租户定界的单点变异被 FORCE RLS 租户臂 DELETE 策略掩蔽——经模块（必须走受限 operator 通道）观测时两层行为逐字节相同，第二层结构性不可从公共 seam 单独杀死。两层均保留（纵深防御，credential-ownership revoke 同款），各自存在分别由 AC3 行为用例与 FORCE RLS/授权矩阵用例独立钉死。属设计性相互掩蔽，非测试缺口（MANIFEST.md 如实披露）。
- **D7（node_modules）**：本工作树 node_modules 为本轮新装（bun install；eventsource 等依赖未随工作树转移——MT017 D7 同款先例），基线复现的前置条件之一。
- **D8（未变异项）**：advisory 锁序与事务隔离（并发不变量，单线程观测不到；MT008/MT026/MT027 同不变异）；jsonbDocument 驱动行为由红绿记录钉死而非独立变异；目录无 tenant 列为存储形状事实（columnsOf 探针钉死），非行为分支。
