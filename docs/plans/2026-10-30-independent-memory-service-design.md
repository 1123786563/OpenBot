# 通用个人长期记忆服务：设计访谈草案

状态：访谈决定记录。核心产品边界、技术栈、OpenBot 内嵌与独立身份中心方向已确认；完整合同及实现建议见[待评审 Spec](../specs/2026-10-30-independent-memory-service-design.md)。本文不是完整 Spec 的批准记录，不授权实施、迁移或发布。

## 已确认的目标与范围

- D01：记忆服务面向 OpenBot 之外的其他应用和 Bot，提供可复用的通用记忆能力。
- D02：首版聚焦个人长期记忆，包括候选、确认、更正、来源、召回和遗忘。聊天历史、当前会话上下文、团队共享知识留在各自系统。
- 确认来源：2026-10-30 当前设计访谈，用户原文：`Q1 成为 OpenBot 之外的其他应用、Bot 也能接入的通用记忆服务 Q2 是`。
- D03：独立服务拥有记忆原文、审核、更正、遗忘和历史的唯一写入权；各接入应用通过 API 操作。Hindsight 作为内部检索与推理实现。
- D04：跨应用记忆默认隔离，本人明确授权指定范围后才能读取；本人授权不扩大原公司和来源权限。
- D03、D04 确认来源：2026-10-30 当前设计访谈，用户原文：`Q3 是的 Q4 是`。职责与隔离决定记录于 [ADR 0012](../adr/0012-independent-personal-memory-authority.md)。
- D05：身份统一采用 Better Auth；外部应用账号须经本人验证关联，不凭邮箱或同名自动合并。身份关联本身不授予跨应用记忆读取权。
- D06：来源应用保留其业务来源权限的裁决权；记忆服务在返回来源受限内容前向来源应用核验当前权限。无法核验则暂不返回这类内容；无外部来源限制的个人记忆由记忆服务按自身授权规则判断。
- D05、D06 确认来源：2026-10-30 当前设计访谈，用户原文：`Q5 是 统一使用Better Auth 身份 Q6 是`。
- D07：OpenBot、记忆服务与自有应用共用同一套 Better Auth 身份中心，同一个人使用同一用户身份；外部应用保留其账号并经本人验证关联。共用身份不自动授予记忆访问权；具体登录、会话和跨域协议仍待设计。
- D08：首版跨应用共享由本人选择具体记忆，授权指定应用只读，可随时撤销。后续新增记忆不自动加入授权范围；接收应用不得凭共享授权修改或删除原记忆，可另经正常流程提交候选。分类持续共享与自动包含未来记忆不属首版范围。
- D07、D08 确认来源：2026-10-30 当前设计访谈，用户原文：`Q7 是 Q8 是`。
- D09：记忆服务提供统一管理界面，供本人审核候选、更正、遗忘及管理共享授权；各应用通过跳转或嵌入接入。具体集成方式尚待设计。
- D10：来源应用提交经授权的内容片段及来源信息；记忆服务统一负责提取候选、识别重复与冲突，并交本人审核。来源连接及原始内容获取由来源应用负责。
- D09、D10 确认来源：2026-10-30 当前设计访谈，用户原文：`Q9 是 Q10 是`。
- D11：共享授权绑定本人确认的具体内容版本。更正后立即停止向接收应用返回旧版本，新版本须再次授权；派生出的新记忆也须单独授权。
- D12：撤销后记忆服务阻止后续读取，并要求接入应用清理其控制的缓存及副本。已进入对方聊天记录、模型上下文或其他系统的内容分别记录处理范围和清理结果；界面区分“已停止共享”和“应用侧清理完成”。不将撤销解释为已收回所有外发内容。
- D11、D12 确认来源：2026-10-30 当前设计访谈，用户原文：`Q11 是 Q12 是`。
- D13：首版由服务运营方承担候选提取、索引和推理的模型费用，按应用和个人设置预算上限；记录分应用用量，暂不建设接入应用收费系统。额度不足时保留待处理状态，并展示未处理情况。
- D14：记忆服务不可用时，普通对话可继续并明确本次未使用个人记忆；必须依赖记忆的任务提示暂不可执行。故障时暂停记忆读写，不使用未经当前授权核验的旧副本；恢复后重试服务已可靠接收的待处理任务。
- D13、D14 确认来源：2026-10-30 当前设计访谈，用户原文：`Q13 是 Q14 是`。
- D15：应用须先登记，再由本人分别授权提交内容形成候选及读取本应用范围内已确认记忆；采集与读取可独立撤销。应用登记不等于本人委托，跨应用读取仍需逐条共享授权。
- D16：片段提交采用异步处理，先返回可查询的处理状态，后台提取候选后由本人审核。界面区分已接收、处理中、待审核、已确认；符合既有确认规则的内容方可召回。普通事实的主动“请记住”直接确认例外继续保留，须设计受信认证合同。
- D15、D16 确认来源：2026-10-30 当前设计访谈，用户原文：`Q15 是 Q16 是`。
- D17：提交的原始片段是临时处理材料：处理结束后一天内从活跃存储删除；排队最多保留 30 天，超时显示已过期。候选所需最小依据按记忆保留规则管理，备份清除遵守单独保留与验证要求。
- D18：新服务从一开始采用独立仓库、独立部署及独立业务数据库；OpenBot 通过客户端适配器接入，统一身份中心作为共同依赖。数据库可共用基础设施，但各自管理数据及迁移。
- D19：首版不迁移 OpenBot 现有个人记忆；此范围排除不授权删除旧数据。旧链路处置见 D20、D22。
- D17–D19 确认来源：2026-10-30 当前设计访谈，用户原文：`Q17 是 Q18 是 Q19 不用`。
- D20：删除 OpenBot 原有本地记忆实现、旧引擎记忆路径及回退逻辑，统一接入新服务；新服务按本轮确认的审核、授权、来源限制与遗忘规则运行。
- D21：记忆服务直接连接可配置的模型网关，以自身服务身份调用模型并执行预算控制，不经 OpenBot 业务 API；可共用网关基础设施，服务独立记录用量与处理任务。
- D20、D21 来源：2026-10-30 当前设计访谈，用户原文：`Q20 删除旧的记忆规则 Q21 是`。
- D22：用户对 Q22 的删除范围澄清回复“是的”，确认 D20；旧文档标记替代关系并保留决策历史。删除旧规则及实现不自动包含删除旧记忆数据。
- D23：技术栈采用 Bun/Hono、PostgreSQL、React，UI 使用 HeroUI；管理界面首版使用 Better Auth 统一登录跳转；开发完成后希望能挂载到现有 OpenBot 菜单。用户原文 `Better Auth ocid` 按后续 Q25 确认的 OIDC（OpenID Connect）方向表达；菜单展示见 D24。
- D23 来源：当前设计访谈，用户对 Q23 回复：`使用 Bun/Hono、PostgreSQL 和 React 管理界面首版采用统一登录跳转(Better Auth ocid) ui 使用 heroui，开发完成后最好是可以挂载到现有openbot 某个菜单中`。此回复确认技术与集成方向，不自动批准整份 Spec 或数据库任务实现建议。
- D24：点击 OpenBot 记忆菜单后保留 OpenBot 侧栏，在内容区展示记忆管理界面；同时保留独立站访问能力。登录通过统一身份中心跳转，登录后可内嵌，具体承载技术由实施设计选择。
- D25：统一 Better Auth 身份中心独立部署，作为 OIDC 提供方；OpenBot、记忆服务均作为客户端。新增提供方能力纳入建设范围，不假定当前 OpenBot 已装配该能力。
- D24、D25 来源：当前设计访谈，用户原文：`Q24 是 Q25 是`。
- 确认者：当前用户；确认范围为 D01–D25，不包含待评审 Spec 中其余实现建议和具体合同。

## 当前实现与已有约束

- [ADR 0005](../adr/0005-self-hosted-hindsight-for-personal-memory.md)原定由 OpenBot 管理记忆业务权威，Hindsight 承担检索与推理。[ADR 0012](../adr/0012-independent-personal-memory-authority.md)已局部替代目标架构的权威归属；现有实现尚未迁移。
- 当前业务门面位于 `server/src/memory/public.ts`；记忆原文、审核、来源等权威数据仍在 OpenBot 数据库。
- Hindsight 召回结果仍需回读权威数据并核对当前授权；同步、删除重试与降级召回由 `server/src/memory/integration.ts` 装配。
- 领域词义沿用根 `CONTEXT.md`。跨应用复用不自动意味着跨应用共享同一人的记忆，也不自动放开现有公司和来源隔离。
