# OpenShell 沙箱底座设计讨论

状态：设计共识已确认，访谈已结束，未授权实施。正式需求见 [Spec v1](../../specs/2026-10-30-openshell-sandbox.md)，架构决定见 [ADR 0013](../../adr/0013-openshell-sandbox-substrate.md)。本文保留决定来源和研究线索。

## 已确认的方向

来源：当前用户在 grill-with-docs 访谈中回复「Q1 是 Q2 全部迁移 Q3 先作为 Kubernetes 下的新增选择」。确认日期：2026-10-30。

- D1：首要目标为增强 Bot 执行环境的隔离及出站网络约束，减少自研维护为第二目标；可以接受有明确安全收益的额外运维成本。
- D2：迁移范围同时覆盖 agent-computer 与 agent-sandbox 的沙箱底座。后续 D6 明确不要求已有数据迁移，D20 明确部署统一选择底座；实现验证顺序由后续技术计划安排。
- D3：第一阶段作为 Kubernetes 下的新增部署选择；不据此移除现有部署实现。
- D4：隔离能力不可用、网络策略未就绪或确认失效时，拒绝新任务，并阻止受影响沙箱继续执行；不静默降级。来源：用户回复「Q4 是」。具体检测与终止机制待核实。
- D5：OpenBot 是 Bot 网络权限的权威来源与变更授权入口，OpenShell 执行下发的约束。来源：用户回复「Q5 是」。策略同步、撤销和运维变更处置细节待定。
- D6：项目处于开发期，本次不要求已有 Bot 数据迁移及旧环境回退方案。来源：用户回复「Q6 不需要 正在开发」。此决定不免除新环境运行期间的持久化要求；不授权删除现有数据。
- D7：每个 Bot 的 computer 与编码环境使用两个独立沙箱，可分别授权网络权限、停止和重置；编码进程不可直接读取浏览器登录资料。来源：用户回复「Q7 是」。沙箱身份须保留公司租户、团队工作空间和 Bot 的执行归属。
- D8：停止与闲置回收保留浏览器登录资料、编码工作文件及恢复会话所需磁盘数据；启动允许重新运行进程，不要求恢复进程内存和未保存编辑状态。两类环境分别重置，各自清除所属数据。来源：用户回复「Q8 是」。异常崩溃下的数据保证仍待定。
- D9：编码预览服务与编码环境同处运行；有效预览访问阻止闲置停止，无任务且无有效访问后才进入闲置停止，再次打开时按需启动。后台轮询不得无限续期；具体活动判据待定。来源：用户回复「Q9 是」。
- D10：两类沙箱无共享可读写目录，通过 OpenBot 授权的文件传递接口显式复制；检查两端执行归属及目标路径，浏览器登录资料不进入普通传递范围。来源：用户回复「Q10 是」。
- D11：未授权网络目的默认拒绝；管理员可预配置规则，Bot 仅可申请扩大权限，由有权的人通过 OpenBot 批准，区分 computer 与编码环境；临时申请须明确目的、范围与有效期。审批角色后由 D18 限定为部署管理员。来源：用户回复「Q11 是」。
- D12：网络权限撤销须终止已有连接；底层不能可靠即时撤销时，允许停止受影响沙箱，确认新策略生效后再启动；受影响任务应显示中断原因。撤销完成前不能报告已生效。来源：用户回复「Q12 是」。底层实现能力待核实。
- D13：沙箱进程不持有 OpenShell、Kubernetes 控制面管理凭据或其他 Bot 凭据，只获得任务所需权限；文件传递及网络申请经过 OpenBot 受限接口并校验执行归属。来源：用户回复「Q13 是」。
- D14：环境可自动恢复，但不自动重放有外部副作用且结果未知的操作；先核对外部状态或由用户处理，可证明幂等的操作允许重试。来源：用户回复「Q14 是」。
- D15：网络授权、撤销、重置、文件传递等关键操作先可靠记录意图，再执行并记录结果；审计不可用时拒绝普通破坏性操作。紧急停止及权限收紧仍执行，并通过可恢复记录保留证据，恢复后核对补齐结果。来源：用户回复「Q15 是」。可恢复审计机制与故障验收待设计。
- D16：临时网络授权限定沙箱和明确期限，在任务结束或到期时撤销（以先发生者为准）；延期需再次授权。长期规则由管理员单独配置。来源：用户回复「Q16 是」。
- D17：容量不足时排队，超过等待期限明确失败；不通过共享 Bot 沙箱或降级隔离缓解容量不足。两类环境分别计量并受部署总预算约束；任务开始前检查所需容量，运行中任务不因新任务到来被强制驱逐。来源：用户回复「Q17 是」。预算数值、硬限制及排队公平性待定。
- D18：第一版仅部署管理员可批准网络扩权，不增加公司或团队委托审批；普通任务审批权不包含网络扩权。来源：用户回复「Q18 是」。
- D19：新的默认拒绝、强撤销及授权流程先限定于 OpenShell 模式，现有部署模式保持各自行为，界面须明确当前模式与隔离能力。来源：用户回复「Q19 是」。
- D20：以部署配置统一选择沙箱底座，OpenShell 模式同时用于 computer 与编码环境；第一版不支持按公司、团队或 Bot 混选底座。来源：用户回复「Q20 是」。
- D21：computer、OpenCode、SSE、WebSocket及预览等入口统一经 OpenBot 校验用户和 Bot 归属，不提供可绕过校验的底层公开入口。来源：用户回复「Q21 是」。入站认证及头部传递须实测。
- D22：一个 OpenBot 团队工作空间对应一个 OpenShell 工作空间，内部按 Bot 与环境类型分配独立沙箱；团队内每 Bot 的权限仍由 OpenBot 检查。来源：用户回复「Q22 是」。底层 namespace 映射与选定发布版本支持待核实。
- D23：仅 OpenBot 集成服务按需持有 OpenShell 控制面权限；普通用户与 Bot 不直接成为 OpenShell 成员或取得控制面凭据。来源：用户回复「Q23 是」。集成服务凭据粒度和轮换机制待设计。
- D24：每个沙箱具有 CPU、内存、持久存储硬限制，两类沙箱分别设额度且受部署总预算约束；具体额度可配置，容量验证后确定默认值；存储超限不能自动删除登录资料或工作文件。来源：用户回复「Q24 是」。硬配额须在所选存储后端验证，PVC声明容量本身不能直接视为写入硬配额。
- D25：控制面失联后允许短暂恢复窗口，超过宽限期必须通过独立于失联控制链路的机制阻止受影响沙箱继续执行；恢复须重新核对归属、策略及授权。宽限期可配置，60秒仅为待验证候选值。来源：用户回复「Q25 是」。此机制为设计要求，不是已证明的OpenShell能力。

以上确认仅覆盖逐项记录的决定，不代表完整技术设计或实施批准。

## 设计树与待决问题

以下条目中的未定项属于技术设计或验证工作；当前用户已逐项确认 D1–D25 并整体确认共同理解，未批准实施。

- 安全目标（D1）
  - 隔离失败或策略未就绪时拒绝执行（D4）；检测与终止机制待核实。
  - 网络策略由 OpenBot 管理（D5），默认拒绝且人工授权扩大范围（D11）；审批者为部署管理员（D18），同步与生效确认机制待设计。
  - 撤销须切断已有连接，必要时停止沙箱（D12）；底层能力待核实。
  - OpenShell 控制面权限、故障与审计边界。
  - 沙箱无控制面管理凭据（D13）；控制面拓扑和角色映射待定。
  - 结果未知的副作用不自动重放（D14）。
  - 关键操作先记意图，紧急安全处置不被审计故障阻止（D15）；恢复机制待设计。
- 两类工作负载（D2）
  - 每 Bot 两个独立沙箱（D7）；通过受控接口显式传递文件（D10）。
  - 停止保磁盘数据、分别重置（D8）；异常崩溃保证待定。
  - 预览随编码环境运行并按有效访问保持活动（D9）；活动判据待定。
  - 不要求已有 Bot 数据迁移与旧环境回退（D6）；新环境普通停止保留数据（D8），崩溃场景保证待验证。
- Kubernetes 新增选择（D3）
  - 部署统一选择底座（D20），团队映射工作空间（D22），仅集成服务调用控制面（D23）；具体拓扑待设计。
  - 驱动、内核、存储与 Chromium 兼容性证据。
  - 容量管理、连接入口与验收标准。

## 目标结构

部署统一选择 OpenShell 后，由 OpenBot 集成服务在各团队对应的 OpenShell 工作空间中管理沙箱。每 Bot 按需拥有 computer 与编码两个独立沙箱，分别持久化、授权、计量、停止和重置。OpenCode 与预览进程位于编码沙箱内；跨沙箱文件通过受控接口复制。所有用户服务入口经 OpenBot 鉴权。

OpenBot 拥有业务归属、授权审批、网络规则意图、容量准入及关键操作审计。OpenShell 承接底层隔离、网络规则执行及沙箱生命周期。运行授权失效和控制链路失联需要独立执行约束；不能仅依赖 OpenBot 发出远程 stop。

## 技术验证门槛

选定不可变发布版本与镜像后，至少提供以下证据，才可将设计要求标记为能力成立：

1. 自定义 computer 镜像能启动 Chromium，编码镜像能运行 OpenCode 和预览；进程、文件、网络隔离实际生效，无静默降级。验证不能通过放宽已确认的安全边界来获得通过。
2. 跨 Bot、跨团队访问及管理操作被拒绝；所有 HTTP、SSE、WebSocket和预览路径鉴权成立，不能直连绕过。
3. stop/start、进程崩溃、Pod重建和控制服务重启分别验证持久化；普通停止后可恢复磁盘上的登录资料和编码会话数据。异常崩溃保证按实际持久化语义记录，不能承诺外部网站永不要求重新登录。
4. 默认拒绝、批准、到期撤销及人工撤销覆盖已有长连接、并发变更和附加 provider 规则；仅确认最终有效策略后报告生效。
5. 控制面失联、网络分区及执行约束组件故障下，独立机制能在约定期限阻止执行；不能用正常网络下远程 stop 的测试代替此证据。
6. CPU、内存和存储超限可强制约束；容量竞争、排队超时、预览活动及闲置停止符合 D9、D17、D24，不通过降低隔离或删除用户数据处置。
7. 审计故障时普通关键操作拒绝，紧急安全处置仍执行且证据可恢复；结果未知的外部副作用不会自动重放。

## 事实核实边界

当前代码：computer 的 Kubernetes provider 已按 Bot 创建 Sandbox，status 不唤醒，stop 保卷，reset 删除（server/src/computer/sandbox.ts）。编码环境目前为共享容器中的每 Bot OpenCode 子进程（agent-sandbox/src/bot-runtimes.ts），devserver 为独立子进程池（agent-sandbox/src/devserver.ts）；仅包裹整个共享容器不足以满足 D7。编码请求的执行归属约束见 agent-sandbox/src/proxy.ts，接入时须保留。

本轮代码核实：网络管理使用部署级 admin（server/src/auth/guards.ts:125），当前策略范围为 organization/group（server/src/admin/routes.ts:74）；无策略时 allow_all（server/src/computer/policy-network.ts:38），异步下发且无已有连接强撤销保证（server/src/admin/routes.ts:319）。D11 默认拒绝、D12 强撤销、D15 意图先记审计均为需要实施的行为变化，不是已有保证。普通动作审批权限不能直接用于扩大网络权限。

容量现状：computer 默认活动上限20、闲置15分钟，2GiB仅为API写入的内存计账而非底层硬配额（server/src/computer/capacity.ts:129、:350）；其闲置清扫由容量竞争触发。编码预览默认每实例8个，不等于OpenCode总并发上限（agent-sandbox/src/env.ts:116）。D17的排队及部署总预算属于新增设计。

历史会话的 OpenShell 能力结论仅为研究线索；驱动存储保证、Chromium 兼容性、内存挂起能力及自动闲置停止均须以选定版本的官方资料和适用实测核实。

统一领域词汇维护在根 CONTEXT.md。OpenShell workspace 指其授权分组，不是沙箱内工作目录，也不与 OpenBot Workspace（团队工作空间）混称；两种工作空间按 D22 映射。

### OpenShell 官方资料核实（文档基线 v0.1.6，未部署验收）

- Kubernetes 驱动依赖 Agent Sandbox controller/CRD，接入不等于移除该依赖；CNI 必须执行 NetworkPolicy。[setup](https://docs.nvidia.com/openshell/v0.1.6/kubernetes/setup)
- 自定义 OCI 镜像、工作区 PVC 可支持接入方向，但不证明 Chromium 兼容。[runtimes](https://docs.nvidia.com/openshell/v0.1.6/how-it-works/sandboxes/runtimes)
- stop/start 保持工作区与沙箱身份，但恢复是新进程代际。公开 service URL 需要应用自行鉴权，不自动继承控制面授权。[sandboxes](https://docs.nvidia.com/openshell/v0.1.6/how-it-works/sandboxes/overview)
- 已有 OpenShell workspace 和成员角色；同 workspace 成员能力不能直接等价每 Bot 归属校验。历史会话“无多租户授权”不能继续当作事实。[workspaces](https://docs.nvidia.com/openshell/v0.1.6/how-it-works/workspaces)
- 官方描述策略加载关闭旧连接；须核 Loaded 及最终有效策略，附加 provider 规则也可能继续授予访问。[policies](https://docs.nvidia.com/openshell/v0.1.6/how-it-works/policies/manage-policies)
- 已知 HTTP/WS 转发不等价 OpenCode SSE 已验收，长流、flush、头部和断线恢复仍须实测。
