# OpenShell 底座纵向 Ticket 草案

状态：待用户确认拆分；尚未发布子 Issue。父 Spec：[GitHub #734](https://github.com/1123786563/OpenBot/issues/734)，本地 [Spec](../../specs/2026-10-30-openshell-sandbox.md)，决定见 [ADR 0013](../../adr/0013-openshell-sandbox-substrate.md)。

目标：每张 Ticket 在其阻塞项完成后可由一个新 Agent 独立实现与验收。编号是本草案内部 ID；发布后替换为实际 Issue 编号，创建为 #734 的正式子 Issue，并在可用时建立原生 blocked-by 关系。`ready-for-agent` 不表示依赖已完成或技术门槛已通过。

## 拆分

### T01 — OpenShell Kubernetes 底座安全启动

**Blocked by:** 无。

**交付:** 部署管理员选择 OpenShell 模式后，集成服务能在一个测试团队工作空间启动受限的测试执行沙箱。旧模式仍可选择；模式与已验证能力可被管理员看到。该票固定版本、controller、CNI、存储与最小服务凭据组合，并证明默认拒绝与硬隔离；无法施加约束时拒绝启动。这里的测试工作负载是可运行的端到端探针，不宣称浏览器或编码能力已接通。

**验收:** OpenShell 模式能创建、访问并停止一个受限测试沙箱；跨工作空间和无授权网络访问被拒绝；NetworkPolicy 未生效或隔离能力失效时安全拒绝；底层凭据不进入工作负载；管理员看到真实模式，旧模式行为不变。关联 A01、A02、A06。

### T02 — 每 Bot 独立 computer 完成一次受控浏览器操作

**Blocked by:** T01。

**交付:** 对一个具有完整执行归属的 Bot，OpenBot 的 computer 服务通过独立 OpenShell 沙箱完成页面访问与受控动作，保持原有工具调用入口。另一个 Bot、团队或业务范围不能读其浏览器资料；Chromium 必须在实际加固配置下运行。

**验收:** 通过 OpenBot 入口完成浏览器操作；跨归属访问被拒绝；沙箱外壳不暴露控制面凭据；Chromium 与隔离规则兼容，不能为通过测试而放宽已批准边界。关联 A01、A02。

### T03 — 每 Bot 独立编码沙箱完成一次 OpenCode 会话

**Blocked by:** T01。

**交付:** 一个 Bot 在独立编码沙箱运行 OpenCode，创建会话并修改所属工作文件；另一个 Bot 无法访问其进程和文件。OpenBot 现有编码代理仍是用户入口，测试涵盖真实事件流连接。

**验收:** 创建会话、写文件与接收事件流成功；HTTP/SSE 长流、断线与头部行为可用；跨 Bot 与团队访问被拒绝；编码进程无法读取 computer 的登录资料。关联 A01、A02、A04。

### T04 — 所有运行服务只能经 OpenBot 鉴权访问

**Blocked by:** T02、T03。

**交付:** computer、OpenCode、事件流和编码预览的服务转发统一校验用户、Bot 及执行归属。底层暴露 URL 不形成旁路，未授权用户不能通过直连、重放或改写头部访问服务。

**验收:** 授权用户的 HTTP、SSE、WebSocket 与预览链路可用；同一 URL 对未授权用户、其他 Bot 与其他团队拒绝；测试确认无可直连的公开底层入口。关联 A02、A04。

### T05 — 关键沙箱操作具备意图审计与紧急处置

**Blocked by:** T02。

**交付:** 对 computer 沙箱停止、重置等关键操作，OpenBot 先可靠记录意图再执行，并记录结果；同一约束可供后续网络授权和文件传递复用。中央审计故障时普通重置拒绝，紧急停止仍可执行并留下可恢复证据。

**验收:** 正常、重复提交、结果未知与中央审计故障均可核对；审计故障不产生未记录的普通重置；紧急停止不被阻断且恢复后能对账。关联 A07。

### T06 — computer 停止保留登录资料，单独重置

**Blocked by:** T02、T05。

**交付:** computer 闲置停止或管理员停止后，后续动作唤醒同一执行归属的沙箱并复用磁盘上的浏览器资料；仅重置 computer 才清除其资料。只读状态查询不唤醒。

**验收:** 测试登录资料经 stop/start 可用，状态查询不唤醒；computer 重置不清除编码文件；Pod/控制服务重启的实测保证单独记录。关联 A03。

### T07 — 编码环境停止保留工作文件，单独重置

**Blocked by:** T03、T05。

**交付:** OpenCode 会话闲置后停止计算，重启保留工作文件与可恢复的会话磁盘数据；编码重置仅清除编码沙箱资料。状态查询不唤醒。

**验收:** 真实文件与会话跨 stop/start 保留；编码重置不清除浏览器资料；崩溃和 Pod 重建的实测范围如实记录。关联 A03。

### T08 — 预览活动维持编码沙箱，闲置后按需恢复

**Blocked by:** T04、T07。

**交付:** 用户查看预览时编码沙箱继续运行；用户离开且没有任务后停止。再次主动打开预览会唤醒，后台轮询不能无限续期。

**验收:** 有效用户访问保持预览；只剩心跳/轮询时按配置闲置停止；重新打开按需恢复，授权检查仍成立。关联 A04。

### T09 — computer 网络申请与管理员授权闭环

**Blocked by:** T02、T05。

**交付:** Bot 为 computer 申请指定目的地址；部署管理员可在 OpenBot 审批，批准后下发到对应执行沙箱。未批准、越权审批或策略未确认加载均不能产生访问权。

**验收:** 默认拒绝；部署管理员批准后仅目标 computer 获授权；普通动作审批者无权扩权；审计意图与生效回执可核对。关联 A06、A07。

### T10 — 编码沙箱独立网络授权闭环

**Blocked by:** T03、T05、T09。

**交付:** 同一 Bot 的编码沙箱可以独立申请和获批网络目的；computer 授权不自动复制到编码沙箱，反向亦然。

**验收:** 授权仅作用于指定环境和执行归属；未授权依赖下载失败并展示可申请路径；管理员批准与结果审计可核对。关联 A02、A06。

### T11 — 临时网络授权到期与强撤销

**Blocked by:** T09、T10。

**交付:** 临时授权在任务结束或到期时撤销；人工撤销切断 computer 与编码沙箱已有长连接。并发变更及附加规则不允许重新开放被撤销的目标；无法确认生效时停止受影响沙箱，不虚报成功。

**验收:** TCP keep-alive、WebSocket/流连接实际断开；到期和任务结束先到者生效；核最终有效策略与审计结果；旧连接无法在撤销完成后继续传输。关联 A06、A07。

### T12 — 两类环境之间受控传递文件

**Blocked by:** T04、T05、T06、T07。

**交付:** 用户可通过 OpenBot 将一个指定文件从编码环境复制到自己的 computer，或按允许方向复制回去。两端不共享可读写目录，登录资料不能经普通传递接口外发。

**验收:** 同归属文件成功传递；路径穿越、链接绕过、跨 Bot/团队/环境授权失败；重试幂等、审计结果与文件实际状态一致。关联 A05、A07。

### T13 — 每沙箱资源硬限制与容量排队

**Blocked by:** T02、T03。

**交付:** 两类沙箱分别施加 CPU、内存及持久存储硬限制，并共享部署总预算。容量不足时请求排队，超时明确失败；不驱逐在途任务、不降级隔离、不删除用户数据腾空间。

**验收:** 真实写盘、CPU/内存压力证明硬限制；并发请求不超总预算；队列等待与超时可见且公平性有明确规则；启动失败释放预留资源。关联 A08。

### T14 — 控制面失联后独立阻止执行并安全恢复

**Blocked by:** T02、T03。

**交付:** computer 和编码沙箱在控制面失联超过配置宽限期后，由独立于失联链路的执行约束阻止继续运行；恢复前重新核对业务归属、有效网络策略和授权。宽限期默认值须凭实测选择。

**验收:** 控制面停机、网络分区、执行约束组件故障均注入验证；期限内停止执行且不能由沙箱任务进程禁用；恢复后旧授权不能直接复活。关联 A02、A09。

### T15 — 中断任务的未知外部结果不自动重放

**Blocked by:** T06、T07。

**交付:** 沙箱停止、崩溃或恢复时，结果未知的有副作用操作进入待核对状态；可证明幂等的操作才自动重试。用户能看到需要核对的状态。

**验收:** 注入“外部系统已接收但回执丢失”后不重复提交；核对或人工处置后方可继续；已有幂等操作可安全恢复。关联 A07。

### T16 — OpenShell 模式整体验收与部署说明

**Blocked by:** T04、T08、T11、T12、T13、T14、T15。

**交付:** 一个 Kubernetes 部署中，两个环境都能完成完整用户旅程；管理员看到真实能力、配置限制和故障状态。整理可复现的隔离、撤权、持久化、容量、失联及审计证据，只有全部批准验收通过才声明可用。

**验收:** 父 Spec A01–A09 全部映射到最终代码和实测证据；失败/未测项保持未通过，不静默放宽要求；旧部署模式行为另作回归；所选版本、CNI、controller、存储和资源默认值有明确依据。
