# 通用个人长期记忆服务

状态：Issue 发布草稿。需求以已批准的 SPEC-INDEPENDENT-MEMORY-20261030 v3 及 ADR 0012 为准；此文按 to-spec 模板汇总，不取代原 Spec。

## Problem Statement

用户在不同应用和 Bot 中重复提供偏好与背景，现有记忆能力与 OpenBot 业务服务耦合，其他应用难以安全复用。用户需要知道保存了什么、来自哪里、谁可以使用，并能够更正、撤销或遗忘。

## Solution

提供独立的个人长期记忆服务，让多个应用通过统一身份和明确授权使用记忆。用户在统一管理界面审核候选、管理来源和逐条共享；OpenBot 中保留侧栏展示同一界面，同时支持独立访问。

## User Stories

1. 作为用户，我希望不同应用接入统一记忆服务，以便复用已授权的个人信息。
2. 作为用户，我希望应用默认无法读取其他应用的记忆，以便控制信息范围。
3. 作为用户，我希望选择具体记忆授权指定应用只读，以便清楚知道共享了什么。
4. 作为用户，我希望随时撤销共享，以便停止后续读取。
5. 作为用户，我希望更正后的内容重新授权，以便旧授权不自动覆盖新内容。
6. 作为用户，我希望派生出的新判断单独授权，以便控制额外披露。
7. 作为用户，我希望新增记忆不会自动加入共享，以便保持授权范围稳定。
8. 作为用户，我希望分别开启或撤销采集和读取，以便独立控制两个动作。
9. 作为用户，我希望在一个界面查看和审核候选，以便决定哪些信息成为记忆。
10. 作为用户，我希望编辑或拒绝候选，以便纠正错误。
11. 作为用户，我希望未审核候选不会被 Bot 召回，以便避免使用未经确认的信息。
12. 作为用户，我希望明确要求记住普通事实时能直接确认，以便减少重复操作。
13. 作为用户，我希望敏感信息受到额外审核，密码和令牌不被保存，以便控制风险。
14. 作为用户，我希望看到记忆的来源和依据，以便理解它为什么被使用。
15. 作为用户，我希望更正事实并保留有效时间，以便当前和历史问题使用适当信息。
16. 作为用户，我希望派生判断也经过本人确认，以便区分推断与事实。
17. 作为用户，我希望遗忘记忆立即阻断后续使用，以便控制个人信息。
18. 作为用户，我希望撤销来源后相关记忆和派生判断停止使用，以便撤权真正生效。
19. 作为用户，我希望看到停止使用和副本清理的不同状态，以便了解处理进度。
20. 作为用户，我希望暂时暂停学习或暂停使用记忆，以便分别控制采集和召回。
21. 作为用户，我希望来源权限失效时相关内容不可见，以便公司和团队范围继续生效。
22. 作为用户，我希望提交后看到处理和审核状态，以便知道内容是否真的被记住。
23. 作为用户，我希望预算不足或任务过期时看到状态，以便知道需要重新处理。
24. 作为用户，我希望普通对话在记忆服务故障时继续，以便完成不依赖记忆的工作。
25. 作为用户，我希望依赖记忆的任务在服务不可用时明确暂停，以便避免错误结果。
26. 作为用户，我希望从 OpenBot 菜单打开记忆界面并保留侧栏，以便在工作台内管理。
27. 作为用户，我希望独立访问同一管理界面，以便在其他应用使用记忆服务。
28. 作为用户，我希望用统一身份登录，以便避免建立重复账号。
29. 作为用户，我希望外部应用账号经本人验证关联，以便同名或同邮箱不会误合并。
30. 作为应用开发者，我希望使用稳定 API 提交候选和召回，以便集成自己的 Bot。
31. 作为来源应用，我希望继续裁决来源权限，以便记忆服务不会扩大原有访问权。
32. 作为接收应用，我希望接收清理通知并报告结果，以便落实撤销请求。
33. 作为服务运营者，我希望按应用和个人设置预算，以便控制后台模型费用。
34. 作为服务运营者，我希望查看健康和积压而不读取个人正文，以便维护服务。
35. 作为用户，我希望临时内容片段有明确保留期限，以便避免长期积累对话副本。
36. 作为用户，我希望备份恢复后先重放遗忘和撤销，以便旧数据不会复活。

## Implementation Decisions

- 独立服务拥有个人记忆、候选、审核、来源、版本、授权、任务和清理状态的唯一写入权；Hindsight 作为内部检索与推理适配。
- 独立 Better Auth OIDC 身份中心提供统一身份；OpenBot 和记忆服务分别作为客户端。身份关联不替代用户委托或来源授权，保留既有稳定主体和历史业务引用。
- 技术栈为 Bun/Hono、PostgreSQL、React 和 HeroUI；管理界面独立访问与 OpenBot 内容区内嵌均可用，登录采用顶层跳转。
- 来源应用提交授权片段并在线裁决当前来源权限；服务返回前回读权威内容并核验本人、应用、共享版本及来源。来源无法核验时不返回相关内容。
- 异步处理必须可靠接收、幂等、可查询并在处理前重验授权。候选审核、明确记住、派生、暂停、更正和遗忘沿用已批准规则。
- 服务运营方承担后台处理费用，按应用和个人设置预算；模型调用通过独立可配置网关受管执行。
- 原始片段处理结束后一天内清除，排队最多 30 天；未审核候选 30 天过期。受控备份不超过 30 天，恢复前重放撤销。
- 首版不迁移或删除 OpenBot 旧记忆数据；接入时删除旧记忆实现、旧引擎路径和回退逻辑，保留其他业务职责。

## Testing Decisions

- 以跨服务用户行为为主要测试边界：真实身份中心、记忆 API、来源核验、OpenBot 和浏览器组合验证；断言用户可观察结果与权限，而不是内部调用次数或代码结构。
- 分别测试身份连续性、记忆生命周期、版本共享与撤销、来源权限、异步幂等、预算并发、保留与恢复、独立及内嵌 UI；对外部服务不可用和在途撤权使用可控故障与并发场景。
- 沿用 OpenBot 的 tester-army e2e 统一入口、Better Auth 浏览器套件、隔离数据库辅助及现有记忆来源权限测试作为先例。具体验收以已批准 Spec 的 A01–A19 为准。

## Out of Scope

- 聊天历史、当前会话上下文和团队共享知识的存储。
- OpenMuse 精确 ID 私有记忆及 OpenBot 旧记忆数据迁移或删除。
- 分类持续共享、自动共享未来记忆、面向接入应用的收费系统。
- 生产身份迁移、发布和其他外部操作不由本 Issue 自动授权。
