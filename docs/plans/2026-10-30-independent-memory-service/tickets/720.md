# #720 来源权限受控的记忆召回 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans；仅在用户授权多 Agent 实施时使用 superpowers:subagent-driven-development。Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 来源权限受控的记忆召回，满足 Issue #720 的全部原始验收。

**Architecture:** MEMORY 按已批准的独立身份和记忆权威边界实现本票；跨票依赖通过已验证接口或明确标注的合同夹具接入。应用不能直接写记忆业务表。

**Tech Stack:** Bun/Hono、PostgreSQL、Better Auth；管理界面使用 React/HeroUI，测试统一使用 e2e。具体依赖版本在实施时核验并锁定。

**Spec:** [已批准 Spec v3](../../../specs/2026-10-30-independent-memory-service-design.md)、[ADR 0012](../../../adr/0012-independent-personal-memory-authority.md)、[跨仓库合同](../contracts.md)、[分册](../memory.md)；[Issue #720](https://github.com/1123786563/OpenBot/issues/720)。

## Global Constraints

- 本计划不授权实施、建仓、生产身份迁移、删除数据、提交、推送或部署；实施和切换需单独授权。
- IDENTITY 和 MEMORY 均为拟建仓库，下面路径仅为拟建相对路径；OpenBot 路径相对本仓库。
- 本人、登记应用、操作授权及来源资格必须分别验证；相同邮箱不合并，服务秘密不替代本人授权。
- 未审核候选不可召回；逐版本共享不自动继承；来源不可核验时拒绝相关内容。
- 完整片段处理后一天内清除，排队与候选最长 30 天，受控备份最多 30 天；本票不替其他票声称这些机制已完成。
- 测试使用独立数据库、唯一命名空间和可控服务，禁止生产数据；测试配置、命令为拟建，未实际运行。

- [ ] **写 RED 测试：** 在 `tests/recall-isolation.test.ts tests/revocation-race.test.ts` 覆盖以下具名场景及断言：

  - `source_context_and_sharing: 核验本人、origin/consumer、公司团队 Bot 范围、操作、版本和来源；跨应用无逐版本授权不可见`

## 原始验收逐条映射

1. 本人应用有效记忆和依据 → same_app_confirmed_only
2. 完整来源上下文及逐版本共享 → source_context_and_sharing
3. 来源失败隔离和无关内容 → partial_source_failure
4. 索引只提供 ID、回读权威 → index_ids_only
5. 并发撤权及无泄漏 → delivery_fence、index_ids_only
6. 空与不可核验可区分 → partial_source_failure
