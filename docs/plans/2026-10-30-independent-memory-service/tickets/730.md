# #730 OpenBot 来源授权与接入 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans；仅在明确授权并行实施时使用 superpowers:subagent-driven-development。步骤使用 checkbox；本文不授权实施、提交、推送、部署或外部写入。

**Goal:** 为所有 OpenBot 运行入口提供来源受控记忆接入。

**Architecture:** OpenBot 在线裁决来源；服务客户端从可信作用域绑定身份，浏览器和无人值守路径共用。

**Tech Stack:** Bun/Hono、PostgreSQL/Drizzle、React/HeroUI、Better Auth OIDC、Hindsight；测试采用 ADR 0008 的 e2e 入口。

**Spec:** [批准的 Spec v3](../../../specs/2026-10-30-independent-memory-service-design.md)、[ADR 0012](../../../adr/0012-independent-personal-memory-authority.md)；接口以[跨仓库合同](../contracts.md)为准。目标 MEMORY/IDENTITY 是拟建仓库，文件和新仓库命令均为计划，尚未验证。

## Global Constraints

- 默认应用隔离；登记、本人委托和逐版本共享分别检查；来源在线核验，候选不可召回。
- 原片段处理结束后一天内清除；排队和未审核候选最长 30 天；受控备份不超过 30 天，恢复先重放撤销。
- 身份中心为身份单一权威；不迁移或删除旧记忆数据。受信身份和来源不可由请求体自报。
- 仅用独立 fixture 用户、应用、来源和 TEST_DATABASE_URL；记录运行版本、非零收集数、失败/跳过和隔离清理证据。测试资源归属不明则阻塞，不碰生产数据。
- 完整档：冻结实现检查点后由未参与实现的会话独立行为验收和 Spec/质量审核，适用代码 OCR；失败修复后重验。执行前重新读取 Issue、评论、关系、Spec 与代码，依赖 verified 且检查点进入工作区后才开始。

## Review Focus

1. 伪造 userId 或跨公司引用拒绝；`forged_scope`。
2. 已登记但无委托拒绝；`delegation_required`。
3. 未知接收应用拒绝；`unknown_consumer`。
4. 无人值守入口不可放宽来源；`headless_same_policy`。
5. 来源失效或不可用不可泄漏；`source_outage`。

### Task 1：来源决策与运行客户端

**Files:** OPENBOT Create `server/src/memory-service/{client,context,source-check,routes}.ts`、`server/tests/memory-service-source-check.test.ts`、`server/tests/memory-service-runtime.test.ts`；Modify `server/src/assembly/{runtime,http}.ts`、`server/src/copilot.ts`、`server/src/agents/agent-resolver.ts`、`server/src/config.ts`、`.env.example`。执行时核实现有入口，不覆盖其他任务更改。
**Interfaces:** 消费合同 `SourceCheck`/`SourceDecision` 和 `MemoryClient`；产出 `checkOpenBotMemorySource(input: SourceCheck): Promise<SourceDecision>` 与 `createMemoryContextLoader(deps): (scope: PlatformScope, botId: string) => Promise<{ content: string; result: RecallResult }>`。来源引用须由 OpenBot 签发并恢复原始范围；HTTP 请求服务身份认证。用 `identity-subject-contract-fixture` 和 `memory-service-contract-fixture`，真实来源 Access 不 mock。

- [ ] 写 `forged_scope`、`unknown_consumer`：篡改本人、公司、团队、Bot、原始和接收应用、操作、版本或来源引用均拒绝，不返回正文；`delegation_required` 证明登记或身份本身不等于委托。
- [ ] 写 `headless_same_policy`：浏览器、频道、定时入口同一有效 fixture 可使用记忆，变更团队或撤权后全部拒绝；`source_outage` 在失权及无法核验时均不返回该来源，并保留其他授权内容。
- [ ] 用 ADR 0008 e2e 原生或 `E2E_BUN_ONLY=server/tests/memory-service-source-check.test.ts bun run test tests/bun-suites.test.ts` 和对应 runtime 单文件运行 RED；实现绑定及在线裁决后 GREEN，核实际收集。不得通过客户端传入的 userId 构造身份。
- [ ] 对实际频道、定时和浏览器调用链逐一记录调用证据；下游 #732 再核其他消费者与旧路径退出。

## Issue 验收逐条映射

1. 三个入口及委托来源 → `headless_same_policy`。
2. 可信上下文全字段 → `forged_scope`。
3. 两类入口一致 → `headless_same_policy`。
4. 跨边界、未知应用、失权和无委托 → 所有拒绝测试。
5. OpenBot 在线裁决、不扩大业务权限 → 实际 Access 集成测试。

## 验证与失败处理

每个 RED 必须因缺少目标行为失败而非环境/收集错误；GREEN 记录报告、用例数和退出码，必要时跑类型检查及构建。上述新仓库命令以拟建的 e2e 脚本为前提，实施时核实际 argv；OpenBot Bun 耦合套件经 ADR 0008 驱动，单独 `bun test` 仅诊断。独立 reviewer 在冻结版本上复现成功及拒绝场景、检查 Spec/质量并记录证据至 `.archive/runs/<run-key>/`；不可验证、清理失败或依赖缺失均标 blocked，不能以 fixture 通过冒充集成通过。需另行授权才提交、发布或操作真实数据。
