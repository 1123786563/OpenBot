# #719 明确记住与敏感内容保护 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans；仅在用户授权多 Agent 实施时使用 superpowers:subagent-driven-development。Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 明确记住与敏感内容保护，满足 Issue #719 的全部原始验收。

**Architecture:** MEMORY 按已批准的独立身份和记忆权威边界实现本票；跨票依赖通过已验证接口或明确标注的合同夹具接入。应用不能直接写记忆业务表。

**Tech Stack:** Bun/Hono、PostgreSQL、Better Auth；管理界面使用 React/HeroUI，测试统一使用 e2e。具体依赖版本在实施时核验并锁定。

**Spec:** [已批准 Spec v3](../../../specs/2026-10-30-independent-memory-service-design.md)、[ADR 0012](../../../adr/0012-independent-personal-memory-authority.md)、[跨仓库合同](../contracts.md)、[分册](../memory.md)；[Issue #719](https://github.com/1123786563/OpenBot/issues/719)。

## Global Constraints

- 本计划不授权实施、建仓、生产身份迁移、删除数据、提交、推送或部署；实施和切换需单独授权。
- IDENTITY 和 MEMORY 均为拟建仓库，下面路径仅为拟建相对路径；OpenBot 路径相对本仓库。
- 本人、登记应用、操作授权及来源资格必须分别验证；相同邮箱不合并，服务秘密不替代本人授权。
- 未审核候选不可召回；逐版本共享不自动继承；来源不可核验时拒绝相关内容。
- 完整片段处理后一天内清除，排队与候选最长 30 天，受控备份最多 30 天；本票不替其他票声称这些机制已完成。
- 测试使用独立数据库、唯一命名空间和可控服务，禁止生产数据；测试配置、命令为拟建，未实际运行。

### Task 1：实现并验证本票行为

**Files:** `src/memory/sensitivity.ts`, `tests/explicit-remember.test.ts`；修改 `src/memory/review.ts`, `src/memory/service.ts`, `src/http/routes.ts`。新文件相对拟建 MEMORY；实际存在的 OpenBot 文件以现有树为准。

**Interfaces:** 消费 #718 的确认版本和本人会话；`verifyRememberIntent(request: Request): Promise<VerifiedRememberIntent>` 私有品牌绑定本人、应用、内容摘要、来源及一次性 nonce；POST `/v1/remember`。应用声明和普通采集委托不能制造证明。

- [ ] **准备隔离 fixture：** 两个本人、两个应用、两个来源范围；固定时钟、受控 OIDC/来源/索引适配及唯一测试数据库。记录 fixture 的所有权与清理范围，禁止连接应用库。非本票前置行为由具名 contract fixture 提供，之后替换为经过验证的真实接口进行集成验收。
- [ ] **写 RED 测试：** 在 `tests/explicit-remember.test.ts` 覆盖以下具名场景及断言：
  - `verified_ordinary_direct: 有效本人证明和来源的普通事实直接形成一个确认版本`
  - `app_or_model_claim_denied: 仅应用/模型声明或篡改内容、应用、来源、本人、nonce 重放不能确认`
  - `secret_never_persisted: 密码和令牌在候选、任务、日志和持久层均不存在`
  - `sensitive_requires_review: 其他敏感内容遵守 ADR 0005 的额外本人审核，审核前不召回`
  - `authorization_and_source: 无授权或来源 denied/unavailable 不直接确认`
- [ ] **验证 RED：** 在相应拟建仓库执行 `e2e run --config e2e.unit.config.ts`，确认收集到上述测试且因缺少行为而失败；依赖缺失或环境错误不是有效 RED。
- [ ] **实现 GREEN：** 验证签名本人交互证明并原子消费 nonce；先执行秘密拒存和敏感分类，再按授权来源选择直接确认或额外审核；读取 ADR 0005 的敏感规则作为实施依据。
- [ ] **验证 GREEN：** 重跑 `e2e run --config e2e.unit.config.ts`，确认上述测试均被收集且通过、无意外跳过；运行拟建仓库 `bun run typecheck` 和 `bun run build`。浏览器场景使用隔离真实服务和浏览器，记录服务构建来源、版本及测试身份；无法启动真实依赖时标记集成阻塞，不以 fixture 冒充通过。
- [ ] **独立行为审核：** 由未实施该任务的审核者对照本票验收、Spec 和合同检查身份边界、失败路径与测试证据，记录 finding，修复并复验；按适用规则执行 OCR。清理仅本轮资源并确认释放。
