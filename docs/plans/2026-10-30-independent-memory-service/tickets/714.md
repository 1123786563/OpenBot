# #714 独立身份中心登录 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans；仅在用户授权多 Agent 实施时使用 superpowers:subagent-driven-development。Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 独立身份中心登录，满足 Issue #714 的全部原始验收。

**Architecture:** IDENTITY 按已批准的独立身份和记忆权威边界实现本票；跨票依赖通过已验证接口或明确标注的合同夹具接入。应用不能直接写记忆业务表。

**Tech Stack:** Bun/Hono、PostgreSQL、Better Auth；管理界面使用 React/HeroUI，测试统一使用 e2e。具体依赖版本在实施时核验并锁定。

**Spec:** [已批准 Spec v3](../../../specs/2026-10-30-independent-memory-service-design.md)、[ADR 0012](../../../adr/0012-independent-personal-memory-authority.md)、[跨仓库合同](../contracts.md)、[分册](../identity.md)；[Issue #714](https://github.com/1123786563/OpenBot/issues/714)。

## Global Constraints

- 本计划不授权实施、建仓、生产身份迁移、删除数据、提交、推送或部署；实施和切换需单独授权。
- IDENTITY 和 MEMORY 均为拟建仓库，下面路径仅为拟建相对路径；OpenBot 路径相对本仓库。
- 本人、登记应用、操作授权及来源资格必须分别验证；相同邮箱不合并，服务秘密不替代本人授权。
- 未审核候选不可召回；逐版本共享不自动继承；来源不可核验时拒绝相关内容。
- 完整片段处理后一天内清除，排队与候选最长 30 天，受控备份最多 30 天；本票不替其他票声称这些机制已完成。
- 测试使用独立数据库、唯一命名空间和可控服务，禁止生产数据；测试配置、命令为拟建，未实际运行。

### Task 1：实现并验证本票行为

**Files:** 拟建 IDENTITY：`package.json`, `src/index.ts`, `src/config.ts`, `src/auth/provider.ts`, `src/auth/clients.ts`, `src/db/schema.ts`, `app/src/routes/login.tsx`, `app/src/routes/consent.tsx`, `e2e.unit.config.ts`, `tests/support/provider.ts`, `tests/oidc-provider.test.ts`；OpenBot 修改 `server/src/auth/index.ts`、新建 `server/src/auth/identity-center-client.ts` 和 `server/tests/identity-center-provider.test.ts`；拟建 MEMORY 新建 `package.json`、`app/src/auth/oidc.ts` 和 `app/src/routes/login.tsx` 的可运行登录骨架。#715 在本票检查点上扩展现有客户端，不重复新建；#716 扩展 MEMORY 骨架。

**Interfaces:** `createIdentityProvider(config: IdentityConfig): { fetch: (request: Request) => Promise<Response>; close: () => Promise<void> }`；提供 discovery、JWKS、authorization code + PKCE、token 和退出。配置固定 issuer、密钥、独立数据库及两个客户端的精确回调和 audience；关闭公共动态注册。

- [ ] **准备隔离 fixture：** 两个本人、两个应用、两个来源范围；固定时钟、受控 OIDC/来源/索引适配及唯一测试数据库。记录 fixture 的所有权与清理范围，禁止连接应用库。非本票前置行为由具名 contract fixture 提供，之后替换为经过验证的真实接口进行集成验收。
- [ ] **写 RED 测试：** 在 `tests/oidc-provider.test.ts` 覆盖以下具名场景及断言：
  - `two_clients_pkce_sessions: 两客户端各自 code+PKCE 登录，验证 issuer、audience、签名及相同受信主体，各持独立会话`
  - `invalid_auth_response: 错误回调、verifier、issuer、audience、过期或重放 code 均拒绝且不建立会话`
  - `independent_provider: 两应用均在线时分别登录；停止 OpenBot 业务 fixture 后，记忆应用与第三个无关 fixture 客户端仍可登录；不复制跨站 cookie`
  - `config_fail_closed: 缺密钥或回调不在登记表则启动或授权失败`
- [ ] **验证 RED：** 在相应拟建仓库执行 `e2e run --config e2e.unit.config.ts`，确认收集到上述测试且因缺少行为而失败；依赖缺失或环境错误不是有效 RED。OpenBot 部分按现有 ADR 0008 的 e2e 驱动收集 `server/tests/identity-center-provider.test.ts`，核对实际报告。
- [ ] **实现 GREEN：** 以 Better Auth OAuth Provider 装配受控配置与登录/同意页面；锁定兼容版本并验证提供方而非假定现有 genericOAuth 已提供 OIDC。
- [ ] **验证 GREEN：** 重跑 `e2e run --config e2e.unit.config.ts`，确认上述测试均被收集且通过、无意外跳过；运行拟建仓库 `bun run typecheck` 和 `bun run build`。浏览器场景使用隔离真实服务和浏览器，记录服务构建来源、版本及测试身份；无法启动真实依赖时标记集成阻塞，不以 fixture 冒充通过。
- [ ] **独立行为审核：** 由未实施该任务的审核者对照本票验收、Spec 和合同检查身份边界、失败路径与测试证据，记录 finding，修复并复验；按适用规则执行 OCR。清理仅本轮资源并确认释放。

## 原始验收逐条映射

1. 两个客户端 PKCE 和独立会话 → two_clients_pkce_sessions
2. 错误回调、重放、错误 audience → invalid_auth_response
3. 相同受信主体且不复制 cookie → two_clients_pkce_sessions、independent_provider
4. OpenBot 停止后独立登录 → independent_provider
