**Goal:** 接入应用登记与本人委托，满足 Issue #716 的全部原始验收。

**Architecture:** MEMORY 按已批准的独立身份和记忆权威边界实现本票；跨票依赖通过已验证接口或明确标注的合同夹具接入。应用不能直接写记忆业务表。

**Tech Stack:** Bun/Hono、PostgreSQL、Better Auth；管理界面使用 React/HeroUI，测试统一使用 e2e。具体依赖版本在实施时核验并锁定。

**Spec:** [已批准 Spec v3](../../../specs/2026-10-30-independent-memory-service-design.md)、[ADR 0012](../../../adr/0012-independent-personal-memory-authority.md)、[跨仓库合同](../contracts.md)、[分册](../memory.md)；[Issue #716](https://github.com/1123786563/OpenBot/issues/716)。

## Global Constraints

- 本计划不授权实施、建仓、生产身份迁移、删除数据、提交、推送或部署；实施和切换需单独授权。
- IDENTITY 和 MEMORY 均为拟建仓库，下面路径仅为拟建相对路径；OpenBot 路径相对本仓库。
- 本人、登记应用、操作授权及来源资格必须分别验证；相同邮箱不合并，服务秘密不替代本人授权。
- 未审核候选不可召回；逐版本共享不自动继承；来源不可核验时拒绝相关内容。
- 完整片段处理后一天内清除，排队与候选最长 30 天，受控备份最多 30 天；本票不替其他票声称这些机制已完成。
- 测试使用独立数据库、唯一命名空间和可控服务，禁止生产数据；测试配置、命令为拟建，未实际运行。

### Task 1：实现并验证本票行为

**Files:** `package.json`, `src/index.ts`, `src/assembly/runtime.ts`, `src/db/schema.ts`, `src/auth/context.ts`, `src/apps/service.ts`, `src/delegations/service.ts`, `src/http/routes.ts`, `packages/client/src/contracts.ts`, `e2e.unit.config.ts`, `tests/support/server.ts`, `tests/access-context.test.ts`。新文件相对拟建 MEMORY；实际存在的 OpenBot 文件以现有树为准。

**Interfaces:** 消费 #714 OIDC 的签名、issuer、audience 和当前主体状态；`authorizeMemoryRequest(request: Request, action: "collect" | "recall" | "manage"): Promise<AccessContext>`。服务构造 AccessContext；运营登记包含 app 身份、回调、能力；本人会话单独管理 collect/recall。

- [ ] **准备隔离 fixture：** 两个本人、两个应用、两个来源范围；固定时钟、受控 OIDC/来源/索引适配及唯一测试数据库。记录 fixture 的所有权与清理范围，禁止连接应用库。非本票前置行为由具名 contract fixture 提供，之后替换为经过验证的真实接口进行集成验收。
- [ ] **写 RED 测试：** 在 `tests/access-context.test.ts` 覆盖以下具名场景及断言：
  - `registration_is_not_delegation: 登记和停用应用不创建本人授权，停用后拒绝`
  - `independent_delegations: 仅 recall 不能 collect，仅 collect 不能 recall；撤销 collect 后 recall 仍有效，反之亦然`
  - `forged_identity_denied: body userId、另一 app 身份、仅服务密钥或错误 audience 均不能取得本人授权`
  - `app_scope_and_operator: 关联账号不授予跨应用读取，运营身份不能读个人正文；未授权对象不泄露存在性`
- [ ] **验证 RED：** 在相应拟建仓库执行 `e2e run --config e2e.unit.config.ts`，确认收集到上述测试且因缺少行为而失败；依赖缺失或环境错误不是有效 RED。
- [ ] **实现 GREEN：** 在独立数据库持久化应用登记与本人、应用、操作范围委托；认证层校验本人和应用凭据，并从受信结果构造上下文；执行时重新查询撤销状态。
- [ ] **验证 GREEN：** 重跑 `e2e run --config e2e.unit.config.ts`，确认上述测试均被收集且通过、无意外跳过；运行拟建仓库 `bun run typecheck` 和 `bun run build`。浏览器场景使用隔离真实服务和浏览器，记录服务构建来源、版本及测试身份；无法启动真实依赖时标记集成阻塞，不以 fixture 冒充通过。

## 原始验收逐条映射

1. 登记/停用及能力不自动委托 → registration_is_not_delegation
2. 分别授权并限制操作 → independent_delegations
3. 分别撤销立即生效 → independent_delegations
4. 伪造身份和服务密钥拒绝 → forged_identity_denied
5. 本应用范围与关联不授权 → app_scope_and_operator
