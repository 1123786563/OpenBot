**Goal:** 从授权内容提交候选，满足 Issue #717 的全部原始验收。

**Architecture:** MEMORY 按已批准的独立身份和记忆权威边界实现本票；跨票依赖通过已验证接口或明确标注的合同夹具接入。应用不能直接写记忆业务表。

**Tech Stack:** Bun/Hono、PostgreSQL、Better Auth；管理界面使用 React/HeroUI，测试统一使用 e2e。具体依赖版本在实施时核验并锁定。

**Spec:** [已批准 Spec v3](../../../specs/2026-10-30-independent-memory-service-design.md)、[ADR 0012](../../../adr/0012-independent-personal-memory-authority.md)、[跨仓库合同](../contracts.md)、[分册](../memory.md)；[Issue #717](https://github.com/1123786563/OpenBot/issues/717)。

## Global Constraints

- 本计划不授权实施、建仓、生产身份迁移、删除数据、提交、推送或部署；实施和切换需单独授权。
- IDENTITY 和 MEMORY 均为拟建仓库，下面路径仅为拟建相对路径；OpenBot 路径相对本仓库。
- 本人、登记应用、操作授权及来源资格必须分别验证；相同邮箱不合并，服务秘密不替代本人授权。
- 未审核候选不可召回；逐版本共享不自动继承；来源不可核验时拒绝相关内容。
- 完整片段处理后一天内清除，排队与候选最长 30 天，受控备份最多 30 天；本票不替其他票声称这些机制已完成。
- 测试使用独立数据库、唯一命名空间和可控服务，禁止生产数据；测试配置、命令为拟建，未实际运行。

### Task 1：实现并验证本票行为

**Files:** `src/ingestion/submit.ts`, `src/ingestion/worker.ts`, `src/ingestion/schema.ts`, `src/ingestion/routes.ts`, `tests/ingestion-reliability.test.ts`；修改 `src/db/schema.ts`, `src/http/routes.ts`。新文件相对拟建 MEMORY；实际存在的 OpenBot 文件以现有树为准。

**Interfaces:** 消费 #716 `authorizeMemoryRequest`、`SourceCheck`/`SourceDecision`；产出 `submit(context: AccessContext, input: SubmitInput): Promise<JobView>` 与 `processIngestion(jobId: string): Promise<void>`，wire 为 POST `/v1/ingestions` 和 GET `/v1/jobs/:id`。尚未交付的提取器、暂停和来源撤销用具名 contract fixture，提取器缺失则 pending。

- [ ] **准备隔离 fixture：** 两个本人、两个应用、两个来源范围；固定时钟、受控 OIDC/来源/索引适配及唯一测试数据库。记录 fixture 的所有权与清理范围，禁止连接应用库。非本票前置行为由具名 contract fixture 提供，之后替换为经过验证的真实接口进行集成验收。
- [ ] **写 RED 测试：** 在 `tests/ingestion-reliability.test.ts` 覆盖以下具名场景及断言：
  - `authorization_and_source: 无 collect、来源 denied/unavailable 时拒绝且无任务`
  - `atomic_ack_and_failure: 事务写入片段及任务后才 202；故障回滚无 202，UI 不显示已记住`
  - `idempotent_restart: 同 app/subject/key 与内容返回同一 job；不同内容 409；重启与重复 worker 不重复候选`
  - `job_visibility: 本人及所属应用适当委托可读 accepted、processing、pending reason、review、failed、expired；其他应用 404`
  - `recheck_before_candidate: 领取及候选提交前撤销 collect/来源、暂停或过期均不形成候选`
- [ ] **验证 RED：** 在相应拟建仓库执行 `e2e run --config e2e.unit.config.ts`，确认收集到上述测试且因缺少行为而失败；依赖缺失或环境错误不是有效 RED。
- [ ] **实现 GREEN：** 事务持久化片段、固定归属、过期时间及任务；以租约和幂等约束恢复处理，在领取、调用前和候选提交前重新检查资格。
- [ ] **验证 GREEN：** 重跑 `e2e run --config e2e.unit.config.ts`，确认上述测试均被收集且通过、无意外跳过；运行拟建仓库 `bun run typecheck` 和 `bun run build`。浏览器场景使用隔离真实服务和浏览器，记录服务构建来源、版本及测试身份；无法启动真实依赖时标记集成阻塞，不以 fixture 冒充通过。
- [ ] **独立行为审核：** 由未实施该任务的审核者对照本票验收、Spec 和合同检查身份边界、失败路径与测试证据，记录 finding，修复并复验；按适用规则执行 OCR。清理仅本轮资源并确认释放。

## 原始验收逐条映射

1. 有效委托及来源 → authorization_and_source
2. 持久回执和失败显示 → atomic_ack_and_failure

4. 本人/所属应用状态隔离 → job_visibility
5. 各阶段重验和撤销阻断 → recheck_before_candidate
