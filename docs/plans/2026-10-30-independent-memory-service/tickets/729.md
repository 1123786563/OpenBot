# #729 服务故障与授权降级 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans；仅在明确授权并行实施时使用 superpowers:subagent-driven-development。步骤使用 checkbox；本文不授权实施、提交、推送、部署或外部写入。

**Goal:** 在故障中保持授权边界并向调用者明确降级。

**Architecture:** MEMORY 从自身权威记录降级并共用交付前核验；OpenBot 区分普通对话和依赖记忆的任务。

**Tech Stack:** Bun/Hono、PostgreSQL/Drizzle、React/HeroUI、Better Auth OIDC、Hindsight；测试采用 ADR 0008 的 e2e 入口。

**Spec:** [批准的 Spec v3](../../../specs/2026-10-30-independent-memory-service-design.md)、[ADR 0012](../../../adr/0012-independent-personal-memory-authority.md)；接口以[跨仓库合同](../contracts.md)为准。目标 MEMORY/IDENTITY 是拟建仓库，文件和新仓库命令均为计划，尚未验证。

## Global Constraints

- 默认应用隔离；登记、本人委托和逐版本共享分别检查；来源在线核验，候选不可召回。
- 原片段处理结束后一天内清除；排队和未审核候选最长 30 天；受控备份不超过 30 天，恢复先重放撤销。
- 身份中心为身份单一权威；不迁移或删除旧记忆数据。受信身份和来源不可由请求体自报。
- 仅用独立 fixture 用户、应用、来源和 TEST_DATABASE_URL；记录运行版本、非零收集数、失败/跳过和隔离清理证据。测试资源归属不明则阻塞，不碰生产数据。
- 完整档：冻结实现检查点后由未参与实现的会话独立行为验收和 Spec/质量审核，适用代码 OCR；失败修复后重验。执行前重新读取 Issue、评论、关系、Spec 与代码，依赖 verified 且检查点进入工作区后才开始。

## Review Focus

1. 检索不可用不得返回候选；`fallback_filters`。
2. 来源不可用不得伪装空结果；`partial_source`。
3. 无持久回执时重试不得换 key；`submit_retry`。
4. 服务故障不得使用旧缓存；`no_legacy`。
5. 确认与索引同步中断不得丢权威状态；`confirm_before_index`。

### Task 1：授权降级召回

**Files:** 拟建 MEMORY：Modify `src/recall/service.ts`、`src/recall/authorization.ts`、`src/hindsight/adapter.ts`、`src/memory/review.ts`；Create `tests/recall-fallback.test.ts`。
**Interfaces:** 消费合同 `MemoryService.recall`、`SourceDecision`、`RecallResult`；权威读取及相同权限检查来自 #720。用 `recall-authorization-contract-fixture` 提供确定的委托、共享和来源裁决；集成前不声称 #720 已实现。

- [ ] 写 `fallback_filters`：断开 Hindsight 后仅本人、应用、版本共享及来源均有效的已确认记录返回；候选、拒绝、过期、暂停和越权记录均不返回。
- [ ] 写 `partial_source`：一个来源 unavailable、另一个 allowed；返回 `partial` 与不可核验原因，允许无关内容且不泄露受限记录；空匹配返回 `available` 空列表。
- [ ] 写 `confirm_before_index`：确认事务成功后索引写失败，权威记录仍可通过相同授权降级读取，恢复后补索引。
- [ ] 拟建 MEMORY `bun run test tests/recall-fallback.test.ts` RED，修改权威回读及失败分支，同命令 GREEN。

### Task 2：调用方故障语义

**Files:** OPENBOT Modify `server/src/memory-service/client.ts`、`server/src/memory-service/context.ts`、`server/src/copilot.ts`；Create `server/tests/memory-service-degradation.test.ts`。界面提示依现有消息通道接入，具体显示文件在执行时按调用链核实。
**Interfaces:** 消费 `RecallResult` 和 #730 的 `createMemoryContextLoader`；服务故障不降级到本地存储。具名 `memory-http-fault-fixture` 返回超时/503/partial，实际集成使用 #730 检查点。

- [ ] 写 `plain_chat_and_required_task`：服务 503 时普通对话继续并明确提示未使用记忆，依赖记忆任务暂停；`submit_retry` 断言无可靠 202 回执不显示已接收，重试同一个幂等 key；`no_legacy` 在旧数据及缓存存在时断言均未读取。
- [ ] 按 ADR 0008 将具名 suite 原生收集或 Bun 驱动，运行 `E2E_BUN_ONLY=server/tests/memory-service-degradation.test.ts bun run test tests/bun-suites.test.ts`，核对报告确实收集该文件；RED 后实现并 GREEN。若实际分区为原生，以仓库 e2e 配置运行对应文件并核报告。

## Issue 验收逐条映射

1. 整体故障普通对话与暂停 → Task 2 `plain_chat_and_required_task`。
2. 无回执与幂等重试 → Task 2 `submit_retry`。
3. Hindsight 故障及先确认 → Task 1 `confirm_before_index`。
4. 降级同等授权过滤 → Task 1 `fallback_filters`。
5. 来源不可核验与无关内容 → Task 1 `partial_source`。
6. 禁止旧路径和缓存 → Task 2 `no_legacy`。

## 验证与失败处理

每个 RED 必须因缺少目标行为失败而非环境/收集错误；GREEN 记录报告、用例数和退出码，必要时跑类型检查及构建。上述新仓库命令以拟建的 e2e 脚本为前提，实施时核实际 argv；OpenBot Bun 耦合套件经 ADR 0008 驱动，单独 `bun test` 仅诊断。独立 reviewer 在冻结版本上复现成功及拒绝场景、检查 Spec/质量并记录证据至 `.archive/runs/<run-key>/`；不可验证、清理失败或依赖缺失均标 blocked，不能以 fixture 通过冒充集成通过。需另行授权才提交、发布或操作真实数据。
