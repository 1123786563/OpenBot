## Findings

1. **Medium — a valid projected empty string is collapsed into absent content.** In `app/src/components/ai-observability/run-steps.tsx:258-271`, `projectedValueText({ state: "projected", value: "" })` returns `""`, but the joined payload is rendered only when `payload.length > 0`. Thus an explicitly recorded empty output has no disclosure and is visually indistinguishable from null, missing, or omitted output. The R2 plan requires preserving projected content and the existing SafeValue distinctions; the shared step contract accepts this projected value. **Impact:** P17 loses a recorded fact, and the new null/omitted test does not catch it. **Smallest correction:** branch on whether at least one projected/truncated value is present rather than on formatted text length, and render an explicit empty-value marker for an empty projected string; add a case distinguishing it from omitted/null. Retain the existing redaction boundary and local scroller.

2. **Low — P19 absence assertions still target the dialog submit button, not the entry action.** `app/tests/ai-observability-experiments.test.tsx:465-485` queries `Submit experiment`, which is the button inside a normally closed dialog. The actionable row is labeled `Run an experiment` (`app/src/components/ai-observability/experiments-section.tsx:258-278`; English locale `submit.rowTitle`). The failure test would pass if that row regressed into the fault state. The empty-list test likewise does not establish its intended row behavior; source currently renders `SubmitExperimentRow` for a successful empty list. **Impact:** the R1 low finding and R2 plan's explicit action-absence/empty-list assertion remain unclosed. **Smallest correction:** assert the `Run an experiment` button is absent after a failed dataset read and present for a successful empty list, alongside the existing unavailable and empty-state assertions.

## Resolved R1 issues and limits

The R1 high null-payload crash is resolved: `step.input == null` and `step.output == null` bypass `projectedValueText`, and omitted SafeValues return null. A null/null or omitted/missing step has no empty disclosure. Existing truncated text and the named `overflow-x-auto` payload region remain. The new P17 test exercises null and omitted values through the rendered step tree.

The direct exports test imports the production file route and navigates a memory router to `/bots/bot-1/exports`; its allow path asserts the exports match and its denial path asserts no active match after the guard redirects. This closes the R1 direct-route coverage gap at the router harness level. The denied assertion is weaker than checking the redirect destination because that destination is absent from this minimal tree, but the paired allow/deny cases provide relevant source-level evidence.

The P17/P21/P23 disclosures remain native `<details>/<summary>`. R2 records that focused Enter did not toggle them in Happy DOM, and does not claim browser proof. The R2 implementation report records four focused Bun single-file suites passing and scoped Biome passing. These files are listed in the ADR 0008 driven manifest; the report does not provide an e2e-driven aggregate run for this checkpoint, so the stated counts are focused runner evidence rather than the full ADR gate. Browser keyboard, focus, geometry, themes and real permission behavior remain unverified here.

**Spec verdict: not yet accepted for T06-R2 source behavior** because the projected empty-string distinction is lost. **Quality verdict: not yet accepted** because the P19 regression assertion still misses the actual entry action; the reported focused checks do not establish the ADR 0008 aggregate gate. No new API, permission, concurrency, or redaction expansion is apparent in the five-path delta.
