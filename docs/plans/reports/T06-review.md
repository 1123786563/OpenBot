## Findings

1. **Medium — P23 direct route lacks the required observability guard.** `app/src/routes/_authed/_app/bots.$agentId.exports.tsx:10-14` installs only `component`, while P23's permission case requires the `canManage` and observability route guard for a direct URL. The sibling runs, datasets, and evaluations routes call `requireBotObservabilityAccess` in `beforeLoad`; exports does not. `ObservationExportsPage` and its API query can show a refusal, and the endpoint has its own permission gate, so this is a route-contract and defense-layer gap rather than evidence of server data disclosure. A read-only Bot visitor can enter the exports route and see its frame instead of being rejected by the route guard. **Smallest correction:** add the same `beforeLoad` guard to the exports route and a route-level direct-URL denial assertion for `canManage=false`.

2. **Medium — five data/observability pages still use the 672px prose width.** `app/src/components/bot-profile/bot-subpage.tsx:24-45` calls `PageShell` without `width`, whose default is `prose` (`app/src/components/layout/page-shell.tsx:32-34,44`). P16 runs, P17 run detail, P18 datasets, P19 evaluations, and P23 exports all use `BotSubpage` (`app/src/components/ai-observability/runs-list.tsx:408`, `run-detail.tsx:329`, `app/src/routes/_authed/_app/bots.$agentId.datasets.tsx:22`, `evaluations-page.tsx:17`, `exports-status.tsx:68`); the T06 delta sets `wide` only for P20–P22. Approved implementation Spec §7 says data/runs/comparison use 1024px, and Task 6 explicitly calls for that data width. This leaves the list and technical detail content constrained to 672px and undermines the intended hierarchy. **Smallest correction:** expose an optional `width` pass-through on `BotSubpage`, set `wide` on these five observability callers, and check the resulting class in each page's source-level/render test. Transfer shared-component ownership explicitly before editing it.

3. **Medium — P17 cannot expand a step to inspect its full recorded content.** P17 lists “expand steps” as an existing capability and requires long step content to collapse without losing access. `app/src/components/ai-observability/run-steps.tsx:231-272` renders every `StepNode` open and places its payload in a default-clamped `ItemDescription` at line 257; there is no disclosure button, full-content view, or local technical-detail scroller. A long projected payload is therefore shortened with no path to inspect it. **Smallest correction:** add a keyboard-operable per-step disclosure that preserves the summary and exposes full projected content inside a named `overflow-x-auto` region; assert collapsed/expanded text and keyboard operation in the step behavior tests.

4. **Medium — P21 and P23 lack their specified detail disclosures.** P21 requires a sample summary first with details expanded on demand. `app/src/components/ai-observability/experiment-results.tsx:315-397` renders reason, judge, and usage inline in every `SampleRow`, with no expandable boundary. P23 says error reasons can expand, but `app/src/components/ai-observability/exports-status.tsx:199-209` renders the failure reason inline and offers no disclosure. Long results defeat the compact narrow-screen scan; there is no user control to show or hide detail. **Smallest correction:** retain status/class/score in the summaries and put P21 reason/judge/usage and P23 error detail behind keyboard-operable disclosures. Add narrow-layout behavior assertions and preserve missing values as unavailable.

5. **Low — the changed P19 fault branch has no direct behavioral regression assertion.** The only behavior change is `ObservationExperimentsSection` at `app/src/components/ai-observability/experiments-section.tsx:109-123`, where a failed datasets read now produces a `StateNotice`. The scoped `ai-observability-experiments.test.tsx` exercises execution and result faults, but does not assert the submit section's dataset-read failure face or that its submit action is absent. This makes the new distinction between unavailable and empty easy to regress. **Smallest correction:** add one component/page test with a failed datasets query asserting the localized availability notice and no submit action, and one empty-list assertion preserving the empty state.

## Source coverage and verdict

P16–P23 were checked individually. The runs and evaluations parent routes retain `Outlet` and `beforeLoad` guard inheritance for P17/P20/P21/P22; datasets has its own guard. The detail Back links, result/comparison download paths, guarded export artifact fetch, explicit missing values, and comparison direction/unit rendering remain present in source. The four changed lines of width configuration and the new P19 fault notice introduce no apparent data or concurrency regression. Existing tests and the implementation report show a targeted driven run and scoped Biome pass; its app typecheck failed in an unrelated test file. I did not rerun tests under this read-only review.

**Spec verdict: fails T06 source acceptance** because P23 route denial, the five page widths, and P17/P21/P23 disclosure requirements remain unmet. **Quality verdict: changes are locally simple, but approval is withheld** pending correction and a direct regression assertion for the new P19 fault branch. Rendered, responsive, theme, permission-fixture and browser acceptance remain unverified by this review.
