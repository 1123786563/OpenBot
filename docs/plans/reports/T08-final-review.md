## Findings

### T08-S1 — Medium — Pending SMS confirmation can refer to a different conversation

- **Evidence and affected symbols:** `ReachingYou` stores `{challengeId, agentId, channelId}` when `/api/delivery/sms/start` succeeds, but derives the visible `challengeId` using only `pendingSms.agentId === fixedBot` (`app/src/components/delivery/reaching-you.tsx:157–159, 319–323`). `ConnectDialog` keeps a separately selectable `channelId` (`:367, 415–426`) and submits confirmation using only the visible challenge ID (`:517–525`). The new test covers Bot A→B→A and one conversation, but never changes conversation within Bot A (`app/tests/bot-reaching-you.test.tsx:227–295`). The stored channel field was added by the B1 T05 repair; this is within the delivery delta.
- **Impact:** After sending a code for one conversation, a user can select another conversation for the same Bot and still see and confirm the first conversation's challenge. The confirmation request targets the old challenge while the dialog displays the new conversation. This conflicts with P09's requirement to preserve the existing destination configuration and validation feedback without changing the business action's meaning. The server may correctly bind the old conversation; the UI gives the user no reliable indication of that mismatch.
- **Smallest defensible correction:** Scope the visible/resumable challenge to both Bot and conversation, and preselect the stored conversation when resuming a pending challenge. Add a behavior test that starts SMS for conversation A, switches to B, and verifies A's challenge cannot be confirmed as B, then reopens A and confirms the resumable challenge.

### T08-Q1 — Low — R2 lacks its dedicated checkpoint package

- **Evidence and affected artifact:** The repair plan requires `checkpoints/t08-r2/PRE/`, but that directory is absent. `T08-R2-review.md` independently recovered the two exact PRE bytes from HEAD and the T03-R3 POST snapshot and hash-matched them to the implementation report; the live POST hashes also match. The bounded two-test delta is reviewable, yet the prescribed reusable R2 PRE/POST package was not retained.
- **Impact:** A later reviewer must repeat the reconstruction to audit baseline exclusion or recover the exact R2 increment.
- **Smallest defensible correction:** Retain the recovered PRE and current POST bytes, hashes, and their two-file delta in the planned T08-R2 checkpoint directory; cite the reconstruction sources. No source or test behavior change is needed.
