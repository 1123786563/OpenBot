## Findings

1. **High — an accepted null step payload crashes the P17 step tree.** `shared/ai-observability-runs.ts:125-128` explicitly allows `input` and `output` to be `null`, and `app/src/lib/ai-observability/runs.ts:484-497` accepts those values from the server. The new disclosure in `app/src/components/ai-observability/run-steps.tsx:265-275` checks only `=== undefined` before calling `projectedValueText`; that function reads `value.state` at line 59. React evaluates closed `<details>` children while rendering, so any step with a null input or output throws before the user can expand it, losing the entire step section (and possibly the route). This also means valid omitted projections can show an empty disclosure. **Smallest correction:** treat `null`, `undefined`, and projected `omitted` as absent before formatting, render the disclosure only when at least one safe projected value is present, and add a behavior case with a null field and an omitted projection.

2. **Low — the new P19 regression tests do not assert the action is absent.** `app/tests/ai-observability-experiments.test.tsx:462-479` checks `queryByRole("dialog")` after failed and empty dataset reads. The dialog is normally closed before the user clicks the submit row (`app/src/components/ai-observability/experiments-section.tsx:258-286`), so this assertion also passes if a regression renders an actionable submit row for a failed read. **Smallest correction:** assert absence of the submit row/button on failure, and assert the intended row behavior for an empty list separately.

3. **Low — direct-route and keyboard coverage is weaker than the repair plan requires.** The exports route now has the guard (`app/src/routes/_authed/_app/bots.$agentId.exports.tsx:11-14`), but `app/tests/observability-route-guards.test.tsx:20-38` calls the helper directly and never loads the exports route. The P17/P23 disclosure tests use `fireEvent.click` (`ai-observability-run-steps.test.tsx:548-551`, `ai-observability-exports.test.tsx:451-455`), and the P21 test uses a pointer click (`ai-observability-experiments.test.tsx:782-789`); none proves keyboard activation promised in the repair plan. Native `<details>/<summary>` provides the expected browser semantics, so this is a coverage finding, not evidence of broken keyboard behavior. **Smallest correction:** add a direct exports route denial/allow test and a keyboard activation assertion for each disclosure kind in an appropriate DOM/browser harness.

## Resolved findings and verdicts

The prior T06 route, width, and disclosure source gaps are addressed: exports uses `requireBotObservabilityAccess`; `BotSubpage` defaults to `prose` and forwards explicit `wide` for P16/P17/P18/P19/P23 while P20–P22 retain their wide configuration; P21 sample reason/judge/usage and P23 failure reason are behind native disclosures. P19 now distinguishes failed dataset reads from empty lists in source. The P17 formatter regression above prevents acceptance despite those corrections. Redaction remains bounded to the existing `SafeValue` projection; the new code does not fetch raw payloads or add an API. The new P17 `<pre>` has an internal `overflow-x-auto` region; its actual 390px/zoom behavior requires the deferred browser pass.

**Spec verdict: fail for T06-R1 source acceptance** because a valid null projected step can crash P17. **Quality verdict: fail pending the high finding and targeted behavioral assertions.** The other four prior medium findings have source-level corrections. Rendered and real permission acceptance remain deferred; this review does not count them as passed.
