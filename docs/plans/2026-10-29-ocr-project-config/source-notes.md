## scan、Git 与子模块

`ocr scan` 审查完整工作树文件，不要求 diff，也可对非 Git 目录运行。有关文件范围的 flags 是 `--repo`、`--path`、`--rule`、`--exclude`、`--preview`；另有输出、并发、模型、token 预算、resume，以及 `--no-plan`、`--no-dedup`、`--no-summary`、`--batch`。**没有 `--include`、独立 allowlist 开关或 `--max-file-size` flag。** `--path` 是逗号分隔的精确文件/目录选择器，不是 glob；目录会包含其后代，`.` 会放宽至整个扫描根。review 没有 `--path` flag。[flags 完整定义 L203–249](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/cmd/opencodereview/shared_flags.go#L203-L249)、[scan provider L55–89](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/scan/provider.go#L55-L89)、[L300–350](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/scan/provider.go#L300-L350)、[L427–430](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/scan/provider.go#L427-L430)。

scan 的 Git 枚举为 tracked `git ls-files -z` 加 untracked `--others --exclude-standard`，无递归子模块选项；随后还读取扫描根 `.gitignore` 并做 provider 过滤。`--exclude-standard` 的完整 nested/global ignore 语义针对 untracked，不能据源码注释推断 tracked 也遵守所有 nested/global ignore。非 Git 目录用 WalkDir，仅处理根 `.gitignore` 与内部排除目录；符号链接、非普通文件跳过，默认单文件读取上限 2 MiB，另有 per-file token gate。[scan provider L100–157](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/scan/provider.go#L100-L157)、[L172–265](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/scan/provider.go#L172-L265)、[L32–37](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/scan/provider.go#L32-L37)、[scan agent L438–455](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/scan/agent.go#L438-L455)。

review 的 Git diff 取得后也经 provider 层过滤根 `.gitignore` 与硬编码根目录前缀。这个 `.gitignore` 处理器支持前导 `!`，按最后匹配决定，和项目 exclude 是两套不同实现。provider 在 FileFilter 前工作，project include 无法重新引入已经移除的内容。根目录硬编码包括 `.git/`、`.idea/`、`.vscode/`、`vendor/`、`node_modules/`、`target/` 等。[diff git.go L27–40](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/diff/git.go#L27-L40)、[L281–331](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/diff/git.go#L281-L331)、[L432–450](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/diff/git.go#L432-L450)。

review 从子目录启动会将 RepoDir 提升到 Git 根，加载根项目规则；scan 保持给定目录/CWD，因此从 `app/` 运行 scan 不会自动读取 OpenBot 根配置。项目例行命令应显式 `--repo /Users/wuyongjun/trea/OpenBot`。[shared.go L173–192](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/cmd/opencodereview/shared.go#L173-L192)。

父仓库 scan 不递归子模块：Git 枚举返回 gitlink 路径，随后因其不是普通文件而跳过。父仓库 review 的 diff 命令也没有递归子模块参数，只能看到父层 gitlink 差异，不能把它算成子模块源码审查。OpenBot 的 `apps/openmuse`、`bifrost` 必须在各自仓库另行选择范围并核对各自规则；父层路径排除不能替代子仓库配置。这是从枚举、普通文件门禁和 diff 调用方式得出的推论。[scan provider L190–212](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/scan/provider.go#L190-L212)、[L129–137](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/scan/provider.go#L129-L137)、[diff git.go L220–263](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/diff/git.go#L220-L263)。

## Secret 与后续工具读取边界

built-in secret gate 比用户 include/exclude 更早，无法由 include 覆盖。它纯按路径检查，不扫描内容：`.env` 与 `.env.*` 被排除，只有名称精确为 `.env.example`、`.env.sample`、`.env.template` 的模板例外；例外仅表示不因 secret gate 被拒绝，仍须通过后续扩展/路径规则。另保护 `.ssh/**`、常见私钥名称、`.netrc`、`.npmrc` 等，不等于拦住任何叫 `credentials.json` 或 `secrets.ts` 的内容。review 同时检查 rename 前后路径。[secret_path.go L40–72](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/config/allowlist/secret_path.go#L40-L72)、[default_secret_patterns.json L1–12](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/config/allowlist/default_secret_patterns.json#L1-L12)、[selection.go L78–89](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/agent/selection.go#L78-L89)。

**rule.json 的文件过滤不是工具访问控制。** `FileReader` 仅持有 RepoDir、mode/ref、runner，工作树读取约束在仓库内并防止符号链接逃逸，但没有 FileFilter 或 secret gate。`code_search` 使用模型给出的 pathspec 组装 Git grep，也不加载项目 exclude。故排除 `docs/**` 能阻止它成为待审输入，不能硬性禁止模型后续 `file_read` / `code_search` 读取文档。规则文本可以要求不读文档，但这只是模型指令；若需求是“文档内容绝不外发”，仅改 rule.json 无法提供该保证，需要隔离输入工作区或修改工具访问控制，均不是本次只读研究的实施范围。[filereader.go L57–115](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/tool/filereader.go#L57-L115)、[L193–208](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/tool/filereader.go#L193-L208)、[code_search.go L22–103](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/tool/code_search.go#L22-L103)、[review_cmd.go L613–620](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/cmd/opencodereview/review_cmd.go#L613-L620)。

## 最小配置建议

在 v1.13.3 的受支持字段中，没有直接表达“只有这些语言或这些 include 路径可以入选”的白名单开关。可用显式 exclude 排除当前仓库的文档/产物，结合 preview 清单对账达到本轮范围；不能将其描述成对任意未来文件都闭合的代码白名单。[字段定义 L205–224](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/config/rules/system_rules.go#L205-L224)、[选择实现 L70–101](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/agent/selection.go#L70-L101)。

本项目的实际配置见 [`.opencodereview/rule.json`](../../../.opencodereview/rule.json)，以该文件为唯一配置事实源，不再提供可被误复制的部分示例。当前配置使用一个 `path: "**/*"` 的 catch-all 条目，审查指令直接内联于 `rule`，并明确设置 `merge_system_rule: false`。因此项目指令整体替换内置语言规则，也没有外部 Markdown 引用的路径基准问题。

选择替换是为了把审查重点收敛到可证明的行为、安全、隔离与可靠性缺陷。实际 `rules check` 核对发现，TypeScript 内置规则包含拼写、`var`、`any`、注释与 inline style 等要求；启用 merge 会把这些内容放进标为 Mandatory 的 system 段，与本项目减少风格误报的目标冲突。`merge_system_rule: true` 仍是工具提供的可选能力，不是本项目采用的配置。[TypeScript 内置规则 L1–26](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/config/rules/rule_docs/ts_js_tsx_jsx.md#L1-L26)、[合并包装 L489–503](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/config/rules/system_rules.go#L489-L503)。

文件范围采用显式 exclude：排除文档/执行证据目录、配置与数据后缀、锁文件、常见无扩展名说明文件、环境/私钥文件、依赖和构建产物、已知生成代码及两个子模块。include 用于恢复目标测试与 Dockerfile/Makefile；它不代表白名单。新目录、新后缀及其他无扩展名文件仍须通过 preview 清单对账，不能假定都已排除。若 scan 必须具有精确入选集合，应生成代码文件清单传入 `--path`；review 没有同等 `--path`，需要核对当前 diff 的预期集合与过滤后结果，或使用经授权的隔离审查镜像。[flags L203–249](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/cmd/opencodereview/shared_flags.go#L203-L249)、[scan provider L300–350](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/internal/scan/provider.go#L300-L350)。

配置验证应分开检查“规则文本是否命中”和“文件是否入选”：对 `server`、`app`、测试、脚本各挑一条运行 `ocr rules check`，再查看 `ocr scan --repo <根目录> --preview --format json` 与真实 review 范围的 `--preview`。核对文档、产物、默认跳过测试、无扩展名、JSON/YAML 和子模块边界；这些命令可在不调用 LLM 的情况下完成配置验收。[rules_cmd.go L45–79](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/cmd/opencodereview/rules_cmd.go#L45-L79)、[scan_cmd.go L156–177](https://github.com/alibaba/open-code-review/blob/375f64cd6f67a48a135da83cfcf59c52669a09cb/cmd/opencodereview/scan_cmd.go#L156-L177)。
