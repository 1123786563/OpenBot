# 模块架构迁移与验收方案

继承[架构主文档](../../specs/2026-10-23-modular-architecture-design.md)的设计稿状态。本分册定义可独立验收的迁移工作包、接口前置和放行条件；不是已批准的逐文件执行计划，也不将整个重构作为一个巨型实现任务。

实际启动某个工作包前，核验其批准依据、Git 与全部消费者，再使用 writing-plans 输出该工作包的精确文件/签名/测试计划。实现 Issue 时再递归摄取正式树与依赖，按现有 SDD/验证/Review/OCR 流程执行。设计稿中的工作包依赖不能替代 GitHub 原生 blocked_by。

用户已于 2026-10-23 授权建单，根 [#620](https://github.com/1123786563/OpenBot/issues/620) 与 25 张子票见[正式 Issue 索引](github-issues.md)。它们将工作包细分为可逐步选择的改造切片；建单不表示已启动实施。

## 1. 全局约束与审查重点

- 保留当前宿主、稳定业务 ID、现有公开协议和数据归属；本次架构整理不授权删除表/数据、改付款账户或生产切换。
- 业务状态只有一个写入所有者，跨 Module 原子写保留同连接事务；所有远端副作用有具名未知状态与恢复入口。
- 每步迁移真实消费者后才能收窄旧出口；兼容 Adapter 有具体调用者和退出条件，不增加第二个状态写入权威。
- 目标图不代表当前代码已满足；候选 BA/Personal Space 不能作为已批准实施来源。旧 #6 不进入执行队列。
- 提交策略按当时授权决定；无授权使用完整未提交检查点，保存到 `.archive/`，不以空提交范围代替 Review。

Review 重点：撤权与在途动作的交错；同键不同输入；旧 generation/旧安装版本的恢复；输出完成但费用未知；开启/关闭可选能力时的实际启动与回退路径。每一类都在下表分配验收，禁止只测正常成功路径。

## 3. 每个工作包的标准迁移步骤

1. 冻结入口、消费者、表写入者与行为基线，记录原始 HEAD/未提交检查点。完成标准：所有实际消费者和兼容臂可逐项对账。
2. 在所属目录定义公开业务 Interface 与必要内部合同，复用已有类型；标记当前 legacy 深层引用为具体例外。完成标准：输入、输出、错误、幂等、事务和撤权语义可测试。
3. 按一条纵向链路接入真实 Adapter，迁移其所有实际消费者。完成标准：同一事实只有一个写入路径，新旧 Adapter 不同时执行业务副作用。
4. 对 Interface 验证成功、拒绝、重放、交错失败与恢复。完成标准：下节所属 AC 有当前版本证据，适用真实环境证据齐全。
5. 收窄旧出口、删除无真实消费者的兼容逻辑，更新目标依赖与文档。完成标准：该范围没有未登记深层引用或实现泄漏。
6. 完成独立验证、Review 与该范围 OCR，保存后再放行下游。完成标准：前置检查点已集成，结论绑定相同内容/哈希；覆盖不完整时不放行。

这些步骤定义迁移策略，不替代单任务的精确 RED/GREEN、文件所有权和执行命令。

## 5. 验证资源与依赖检查设计

实施时先读[测试资源规范](../../../.agents/rules/testing.md)与指定 ADR。根 e2e 清单、Bun/原生/外部 suite 分类和数据库/端口隔离按当前项目配置决定，不在本架构稿复制一份会漂移的全局测试命令。

公开 Interface 行为测试替代对内部文件结构的镜像测试；数据库事务/锁必须用项目认可环境验证；供应商 Adapter 的 mock 不能代替要求的真实集成证据。修改跨宿主 wire、配置或错误语义时补对应消费者测试。

目标依赖检查器在有首个迁移工作包时一起交付，而非本轮空建：解析源码相对/alias/workspace import 和 type import，按本目录表及实际归属清单分类；集成层与测试内部 Seam 单独处理。存量例外逐条记录来源文件、目标文件、具体理由、所属迁移任务和退出条件。新违规失败，既有例外数量/范围增加也失败，不能用目录级无限豁免。

运行输出、覆盖矩阵、检查点、Review/OCR 与裁决按 [产物归处](../../../.agents/rules/artifacts.md)写 `.archive/runs/<run-key>/`。架构主文档与合同变更保留在版本控制路径，不能只在本地归档留唯一批准事实。

## 7. 回退与完成条件

优先无数据形状变化的 Interface/装配迁移；新旧实现只能经受控选择装配一个写入者。代码回退复用原持久 ID 与事实，不清空新写出的动作/费用记录。

涉及 schema 时按独立已批准迁移采用 expand→验证→切读写→收窄；切换前定义备份、恢复点和不可逆写入门槛。BA M0–M4 按自身合同执行，本架构稿不另定一套权威开关。切换后如旧版本无法理解已写事实，只能恢复兼容版本或停写处置，不能盲退旧双写路径。

单工作包完成需满足：所有者与消费者对账完整、目标 Interface 行为可验、直接依赖无新增循环、适用检查通过、独立 Review/OCR 覆盖完整、现有用户改动保留、交付差异符合授权。目录存在、public.ts 能编译或测试部分通过均不单独构成完成。

本轮文档交付的完成标准仅为：主文档与分册齐全、Agent 阅读入口可达、合同/依赖/验收映射一致、链接和差异检查通过。实现状态不随文档完成而改变。
