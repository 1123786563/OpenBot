## F1 注册 / 登录 / 登出

### TC-E2E-AUTH-001: 有效账号密码登录成功

**优先级**: P0　**类型**: E2E　**预估时间**: 3 分钟　**自动化**: ✅

**前置条件**:
- QA 环境健康（`GET https://qa-api.example.com/health` 返回 200）
- debug 包已安装，首启权限弹窗已处理
- 种子账号存在：`e2e.p0.login@test.com` / `Passw0rd!123`，昵称「E2E测试用户01」

**测试步骤**:
1. `driver.activateApp(<bundleId>)` 冷启动应用
2. 若已登录则先执行登出
3. 邮箱输入框输入 `e2e.p0.login@test.com`
4. 密码输入框输入 `Passw0rd!123`
5. 点击「登录」按钮
6. 等待首页头像元素（超时 10s）

**预期结果**:
- ✅ 进入首页，底部 Tab「我的」标签正常显示
- ✅ 「我的」页昵称为「E2E测试用户01」
- ✅ 全程无错误 Toast

**通过/失败标准**: 3 项断言全部满足为 PASS；任一失败或 10s 超时为 FAIL。

**潜在缺陷**: iOS 键盘遮挡输入框；Android 密码管理器弹窗劫持焦点。

---

### TC-E2E-AUTH-002: 错误密码登录被拒且提示安全

**优先级**: P0　**类型**: E2E　**预估时间**: 2 分钟　**自动化**: ✅

**前置条件**: 同 AUTH-001，账号处于未锁定状态

**测试步骤**:
1. 打开登录页
2. 输入正确邮箱 `e2e.p0.login@test.com`
3. 输入错误密码 `WrongPass!000`
4. 点击「登录」

**预期结果**:
- ✅ 登录失败，Toast 显示「账号或密码错误」（**不得**提示「密码错误」，防止账号枚举）
- ✅ 停留在登录页，密码框被清空
- ✅ 连续触发时无接口报错堆栈泄露

**潜在缺陷**: 错误提示区分「用户不存在」与「密码错误」（信息泄露）；明文回显密码。

---

### TC-E2E-AUTH-003: 验证码错误 5 次触发限流锁定

**优先级**: P0　**类型**: E2E + 安全　**预估时间**: 6 分钟　**自动化**: ✅

**前置条件**:
- 手机号 `13800001111` 已注册
- QA 环境限流阈值配置为 5 次/10 分钟

**测试步骤**:
1. 选择「验证码登录」，输入手机号 `13800001111`
2. 输入错误验证码 `111111`，提交
3. 重复步骤 2 共 5 次
4. 第 6 次尝试（无论对错）
5. 等待 10 分钟后再次尝试正确验证码

**预期结果**:
- ✅ 第 5 次失败后提示「尝试次数过多，请稍后再试」
- ✅ 第 6 次请求被服务端拒绝（HTTP 429），而非继续校验
- ✅ 锁定期满后使用正确万能码 `000000` 可正常登录

**潜在缺陷**: 限流仅前端禁用按钮（绕过）；锁定无上限（DoS 他人账号）。

---

### TC-E2E-AUTH-005: 登出后返回键不能回到已登录页面

**优先级**: P0　**类型**: E2E　**预估时间**: 2 分钟　**自动化**: ✅

**前置条件**: 账号已登录并停留在首页

**测试步骤**:
1. 「我的」页点击「退出登录」，确认
2. 出现登录页后，按 Android 返回键 / iOS 返回手势

**预期结果**:

- ✅ 冷启动后停留在登录页，本地 token 已清除（TC-SEC-MOB-003 联动）

## F2 首页浏览与搜索

### TC-E2E-HOME-001: 冷启动首页加载（骨架屏→内容）

**优先级**: P0　**类型**: E2E　**预估时间**: 3 分钟　**自动化**: ✅

**前置条件**: 未登录状态，QA 环境种子里首页推荐位有 ≥ 10 条内容

**测试步骤**:
1. `terminateApp` 后 `activateApp` 冷启动
2. 计时观察首屏
3. 等待内容卡片元素出现（超时 8s）

**预期结果**:
- ✅ 骨架屏在 1s 内出现（无白屏）
- ✅ 8s 内真实内容渲染完成
- ✅ 冷启动到可交互 < 3s（冒烟级性能断言，超时记 P2）

**潜在缺陷**: 首屏接口串行调用导致白屏；图片未压缩首帧慢。

## F3 核心交易流

### TC-E2E-ORDER-001: 完整下单→支付（沙箱）→查单

**优先级**: P0　**类型**: E2E　**预估时间**: 8 分钟　**自动化**: ✅

**前置条件**:
- `e2e.order+<runid>@test.com` 已登录（每套件新建）
- 种子商品「E2E-测试商品A」库存 ≥ 10，价格 ¥9.90
- 支付沙箱通道开启

**测试步骤**:
1. 搜索「E2E-测试商品A」进入详情
2. 点击「立即购买」
3. 确认订单页核对金额为 `¥9.90`
4. 点击「去支付」→ 选择「沙箱测试支付」
5. 沙箱收银台点击「支付成功」
6. 返回 App 进入「我的→我的订单」

**预期结果**:
- ✅ 首条订单状态「已支付」，金额 ¥9.90
- ✅ 支付成功页 3s 内出现
- ✅ **状态断言**：调 QA API `GET /orders?user=<uid>` 确认后端状态同为 paid（防 UI 假成功）

**潜在缺陷**: 支付回调丢失卡「待支付」；Android 跳转支付页 Activity 重建丢上下文。

---

### TC-E2E-ORDER-002: 库存不足下单被阻断

**优先级**: P0　**类型**: E2E　**预估时间**: 5 分钟　**自动化**: ✅

**前置条件**: 种子商品「E2E-库存1商品」库存设为 1

**测试步骤**:
1. 用账号 A 购买该商品全部库存（1 件）并支付成功
2. 用账号 B 购买同一商品，数量 1，提交订单

**预期结果**:
- ✅ 账号 B 提交时提示「库存不足」，订单未创建
- ✅ API 断言：账号 B 订单列表为空（无脏数据）
- ✅ 商品详情页库存显示为 0

**潜在缺陷**: 并发超卖；下单不校验库存产生僵死单。

---

### TC-E2E-ORDER-003: 支付中途取消，订单停留待支付

- ✅ 再次支付可成功，状态流转正确

## F4 个人资料

### TC-E2E-PROF-001: 修改昵称保存成功

**优先级**: P1　**类型**: E2E　**自动化**: ✅　**预估时间**: 3 分钟

**步骤**: 「我的」→「编辑资料」→ 昵称改为 `E2E用户-<timestamp>` → 保存 → 杀进程重启验证持久化。
**断言**: 保存后即时显示新昵称；重启后仍是新昵称；超长昵称（>20 字符）被截断或提示。

### TC-E2E-PROF-002: 头像上传（相册选图）

**步骤**: 编辑资料 → 头像 → 系统相册选择预置图片 `fixture-avatar.png` → 裁剪确认 → 保存。
**断言**: 上传中 loading；成功后「我的」页头像更新；重启后不回退。

**前置条件**: Android 模拟器网络限速 400ms 延迟 / 64kbps（或 Charles throttle 3G profile）

**步骤**:
1. 开启弱网
2. 搜索并进入商品详情
3. 点击「立即购买」提交订单

**断言**:
- ✅ 提交后 500ms 内出现 loading 指示
- ✅ 超时（15s）后提示「网络不给力，请重试」，可重试成功
- ✅ 无 ANR（Android）无卡死

---

### TC-E2E-OFFL-002: 断网操作入队，恢复后自动同步

**优先级**: P1　**类型**: E2E　**自动化**: ✅　**预估时间**: 6 分钟

**步骤**:
1. 开启飞行模式（adb: `adb shell svc data disable && svc wifi disable`）
2. 修改昵称为 `offline-<ts>`，保存
3. 观察 UI 提示
4. 关闭飞行模式恢复网络
5. 观察同步行为；杀进程重启再次验证

**断言**:
- ✅ 断网保存时提示「已保存，联网后同步」（本地写入成功）
- ✅ 网络恢复 30s 内自动同步，无用户操作
- ✅ 重启后昵称为新值，云端 API 同步一致

## 中断与异常专项（INT）

### TC-E2E-INTR-001: 支付页来电中断返回状态一致

**优先级**: P0　**自动化**: Android adb / iOS 真机手动　**预估时间**: 5 分钟

**步骤**:
1. 进入收银台页面
2. 模拟来电：`adb shell am start -a android.intent.action.CALL -d tel:10086`（iOS 用真机呼叫测试机）
3. 挂断返回应用

**断言**: 返回后仍停留收银台或正确回到待支付订单页；金额订单号不变；不重复创建订单。

---

### TC-E2E-INTR-002: 杀进程重启登录态与购物车保持

**优先级**: P0　**自动化**: ✅　**预估时间**: 3 分钟

**步骤**: 登录 → 加购 1 件 → `terminateApp` → `activateApp`。
**断言**: 无需重登直接进首页；购物车角标为 1；商品详情可正常继续结算。

---

### TC-E2E-INTR-003: 权限全拒绝核心流程可用

**优先级**: P1　**自动化**: ✅　**预估时间**: 5 分钟

**前置条件**: `autoGrantPermissions: false`，全新安装

**步骤**: 首启逐项拒绝所有权限弹窗（通知/定位/相机/相册）→ 浏览→搜索→下单。
**断言**: 核心浏览交易流不依赖权限可完成；头像上传时二次引导去开启权限；无崩溃。

---

### TC-E2E-INTR-004: 后台 5 分钟回前台数据刷新

**优先级**: P2　**自动化**: ✅（`backgroundApp(300)`，CI 加速可降 60s）　**预估时间**: 6 分钟

**断言**: 回前台后首页数据自动刷新或提供下拉刷新；登录态不过期误踢（token 续期正确）。
