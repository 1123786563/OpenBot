## 登录后跳转失效修复（commit e101922）

- **根因（两类）**：①gate.tsx 的 load() 把 fetchMe/fetchWorkspace 的**任何非鉴权错误**都 setPhase('signin') 弹回登录表单——server 重启窗口/网络抖动时用户看到"登录成功却不跳转"（本环境 server 频繁重启，正是高发场景）；②登录成功后 currentSession() 本地查询可能因 Better Auth 客户端缓存未更新返回 null，被误判为未登录。
- **修复**：load(justSignedIn) 表单登录后跳过本地查询直接 /api/me 裁决；错误分流——仅 isAuthFailure 回登录页（附明确原因），其余停留加载态显示"你的登录仍然有效"+重试/返回登录页双选。
- **排查路径记录**：先真实浏览器复现（正常场景通过）→ 代码审查跳转链找到结构性缺陷 → 场景化验证（停 server 刷新=用户场景，必现弹回）→ 修复后三场景回归。
- **环境事故链**（跳转问题排查中发现）：OpenBot server 频繁死→根因 OrbStack 挂了（pg 5432 ECONNREFUSED，server 连不上库崩）→ `open -a OrbStack` + 等 docker compose 容器组自愈 → postgres healthy 后拉起 server。server 启动配方：`env -u HTTP/HTTPS_PROXY NO_PROXY=localhost OTEL_SDK_DISABLED=true bun --env-file=../.env src/index.ts`。

## 用户真实支付"未到账"排查（14:50）——支付闭环首次真实验证 + 轮询补丁

- **现象**：用户扫码支付两笔（standard ¥49 + advanced ¥140）但页面一直「订单待支付」。
- **真相三层**：支付宝沙箱侧两单都 `TRADE_SUCCESS`（钱已收，支付宝流水号 2026101122001429920511908076/077）；本地订单 pending；**根因 = 升级弹窗没有轮询**——settle 靠 `readOrder` 的渠道查账副作用（或回调，沙箱回调不可达），弹窗下单后从不 re-read，用户付完钱永远显示待支付。
- **立即修复（到账）**：浏览器触发 `GET /purchases/:id` → standard 单 `paid→applied`（Lago active standard 订阅创建，页面显示「标准版」）；advanced 单 `paid→failed`——**一部署一订阅**的正确业务拒绝（standard 已生效，第二笔无法激活；钱已收，需人工/退款流程处理——**遗留问题：paid-but-failed 的订单无自动退款路径**）。
- **根治（轮询补丁）**：UpgradeDialog 加 settlement poll——pending 订单每 5s `queryClient.fetchQuery(purchaseOrderQueryOptions)` re-read（服务端查渠道对账），状态变化即更新 UI；对齐 subscribe 页 PurchaseFlow 的既有模式。测试需 QueryClientProvider 包裹（withProvider helper）。回归 6/6+3/3+6/6、typecheck/biome 过、浏览器验证弹窗+防呆+禁用全正常。
- **方法论**：支付"未到账"排查三板斧——①支付宝侧 query-order.ts 直查 trade_status（钱到没到）②本地 payment_orders 状态 ③触发 readOrder 看能否 settle。settle 失败≠支付失败，两回事。
