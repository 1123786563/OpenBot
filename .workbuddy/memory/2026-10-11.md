## 启动 OpenBot 本地全栈（排障记录，可复用）

- 结论：全栈已跑起来。app :3010、server :3001、agent-computer :4100、agent-bot :4200、agent-langgraph :4201、supervisor :4500 全部 HTTP 200，licenseStatus=valid，注册 Bot 4 个（general-assistant / knowledge / risk-analyst / UI 设计师）。
- 踩坑 1（构建期）：`bun install` 在 Docker 内大面积 `ConnectionRefused / FailedToOpenSocket / 404`。根因是 bun.lock 里硬编码 1538 个 `registry.npmmirror.com`（宿主机 ~/.npmrc 是 npmmirror），加上 bun 默认并发 48 被限流。处理：把 lockfile 域名换成 `registry.npmjs.org`（原始文件备份在 /tmp/bun.lock.npmmirror.orig），并给 5 个 Dockerfile 的 `bun install --frozen-lockfile` 加 `--network-concurrency=8`（server / agent-computer / agent-bot / agent-langgraph / supervisor）。换源后构建稳定成功。
- 踩坑 2（代理）：BuildKit 会把宿主机的 `HTTP_PROXY=127.0.0.1:56949` 透传进构建容器，而容器 bridge 网络访问不到宿主机 127.0.0.1，且该变量参与缓存键；**构建时必须 `env -u HTTP_PROXY -u HTTPS_PROXY ...` 清除**，否则每次都重建并失败。
- 踩坑 3（运行期）：反过来，**server 进程必须带代理**才能校验 Intelligence licence，否则 `/api/copilotkit/info` 返回 `licenseStatus: unknown`，start.sh 会在 3/4 卡住退出。即"构建清代理、运行带代理"。
- 踩坑 4：start.sh 用 `( ... &)` 起的后台进程会随脚本退出被回收（server/worker 随即消失）。持久化要用 Bash 工具的后台任务直接前台跑 server、app、worker 三个进程，别依赖 start.sh 的后台派生。
- 因此最终是绕过 `scripts/start.sh` 手工拉起：先 `docker compose build`（清代理）→ 迁移成功 → 再分别前台常驻 server / app / worker。日志在 .logs/server.manual.log、app.manual.log、worker.manual.log。
