## 修复：账单/消耗明细「查询条件不生效」＝ queryKey 时钟漂移引发的无限重取风暴

- 用户报「账单管理查询条件不生效」。实测证据链：server.manual.log 里 `/api/billing/invoices` 稳定 **~150 req/s** 持续重取（awk 按秒分桶 77-167 req/s）；库里 12 条 payment_orders 全部创建于 2026-10-10，SQL 窗口过滤（gte/lte created_at）直接验证语义正确。根因不在后端。
- 根因：`invoices.tsx`/`usage.tsx` 在 render 内直接调 `windowFor(range)`（内部 `new Date().toISOString()`），毫秒时间戳进 queryKey → 每次渲染都是新 key → React Query 新查询 → fetch → setData → re-render → 循环。UI 表现即「筛选切换无效果」（列表一直在闪、永远在 pending/refreshing）。
- 修复：`useMemo(() => windowFor(range), [range])`——时钟每次 range 变化只读一次；两页同步修（`app/src/routes/_authed/settings/invoices.tsx`、`usage.tsx`，usage 的 consumption 同病同治）。typecheck exit 0、biome 两文件通过。
- 运行时验证：修复（HMR 生效）后 tail -100 仅剩 7 条残留请求、随后归零，风暴停止。
- 通用教训（React Query 纪律）：**任何进入 queryKey 的值必须在 render 间稳定**。凡是「从时钟/随机数现算」的 queryKey 成员（时间窗口、随机 id），必须 useMemo 固定，或把语义粒度降级（窗口用 range 枚举做 key、from/to 只进 queryFn）。诊断此类问题的最快路径：看 server log 按 path 分桶的每秒请求数。
