# 退役 OpenBot 旧收款通道

[#221](https://github.com/1123786563/OpenBot/issues/221) 的生产切换在支付宝 [#219](https://github.com/1123786563/OpenBot/issues/219) 和微信 [#220](https://github.com/1123786563/OpenBot/issues/220) 均通过真实商户验收后执行。

## 停接新单

1. 记录旧收款商户、旧适配器覆盖的账号和切换时间。确认两个 Flexprice 渠道仍能按各自的授权名单下单、查单和原路退款。
2. 在 OpenBot API 的 Infisical 目录清空 `OPENBOT_CREDIT_PACK_LIVE_ACCOUNT_IDS` 和 `OPENBOT_CREDIT_PACK_ALIPAY_LIVE_ACCOUNT_IDS`。保留旧适配器的 `ORIGIN`、`TOKEN`、商户和其他配置，继续处理已发出的付款和退款。保留旧通道回调入口及后台对账任务。
3. 验证旧通道拒绝新下单。用已有旧订单确认查单、付款回调和退款核验仍可工作。关闭已有待付订单前，先查单确认未付款。渠道结果未知时保留跟踪，等待明确结果。

## 处理在途订单并移除适配器

1. 按旧商户和订单渠道对照 OpenBot 订单、退款记录与商户后台。核对待付款、待确认、待退款和人工处理记录，包含已签发但仍可支付的二维码，以及待处理的迟到、多收款。核实每笔实收都有对应的订单或退款记录。
2. 完成在途处理后记录对账范围、时点及未结数量。只有旧商户和 OpenBot 都确认未结为零，才移除旧适配器、对应回调配置和专用凭据。保留 OpenBot 账本、历史订单及消费预占、结算和退款冻结能力。
3. 用两个新渠道分别复验下单、查单、到账发点及退款。若退役前发现遗漏的在途订单，暂停移除，保持旧适配器能继续对账。

保存脱敏的旧通道拒绝新购证据、双方零未结对账和新渠道复验结果，再关闭 #221。
