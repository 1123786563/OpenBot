# Flexprice 能力接管调研

核对范围为部署文档记录的 Flexprice 后端 `d7d5c1120`、国内支付集成分支 `3e31fed88` 及当前 OpenBot 计费代码。结论来自静态源码核对，生产验收需使用目标镜像和真实商户。

| 能力 | 接管结论 |
| --- | --- |
| 客户、商品目录、价格、计量、账单、订阅、账单调整、账务门户 | 可交给 Flexprice。OpenBot 仍要将登录账号映射到计费客户、生成原始模型用量并记录调度结果。现有部署使用一个零价对账订阅，按客户实际计费需要迁移客户映射和事件归属，并确保同一笔用量只扣一次。 |
| 钱包、点数余额、充值、流水、赠送、过期、余额提醒 | Flexprice 有相关能力。可以作为唯一余额来源，但同一份点数不能同时发到两个账本。购买档位的金额、点数、兑换率和精度需要按订单固化。 |
| 国内收款、查单、换码、到账认定、多收款处理 | 国内支付分支已经通过 GoPay 实现支付宝与微信扫码和多收款记录。须把支付分支与部署分支合并，确认保留关闭注册配置。 |
| 付清自动充钱包 | Flexprice 已有充值账单完成待入账钱包流水的钩子。到账成功但钱包入账失败时存在仅记录错误的路径，需要验证国内扫码充值的完整链路、漏通知恢复和重放只入账一次。 |
| 套餐权益和用量配额 | Flexprice 可管理产品侧权益和配额。OpenBot 仍执行身份验证、资源授权及实际请求的拦截。 |
| 模型调用前预占、实际用量结算、释放余额 | 钱包有余额查询和立即扣减，未在核对的接口中找到按调用预占、按实际用量结算和释放的一套操作。普通余额查询与后续上报之间存在竞争。手工扣减 API 允许负余额，不能用于严格预占。 |
| 常规原路退款及对应点数撤销 | 国内支付分支能记录多收款的退款。普通已付账单通过支付宝或微信原路退款，并与指定批次点数冻结、撤销、失败解冻联动，仍需接入和验收。 |

## 判断是否可以删除 OpenBot 点数账本

如果接受先执行后计量，以及并发请求可能透支的语义，可另立方案评估 Flexprice 钱包和用量计费。若继续保持 OpenBot 的严格预付语义，可以在 Flexprice 扩展预占、结算、释放及批次冻结，再迁移账本归属。将预占留在 OpenBot、钱包放在 Flexprice 也需要明确并发控制，避免余额读写分属两个系统后绕过预占。

迁移前至少验证以下业务结果。

- 钱包剩 10 点时并发提交两笔各需预占 8 点的模型调用，最多一笔能执行。取消、超时和重试可释放或补结算，最终只扣实际消费。
- 两个渠道的实付账单各只充一次钱包。支付成功时钱包暂不可用，恢复后自动补账。对账可定位原付款和钱包流水。
- 退款冻结与消费预占竞争时，同一批点数只能被一方占用。退款状态未知时保持冻结，成功时撤销，明确失败时解冻。
- 同一调用经过计量重投、账单重试及进程重启后，始终只扣一次。核对目标镜像功能与 Flexprice 企业版生产授权，保留真实渠道分别验收的条件。

## 本地接管验证

| 验证 | 结果 |
| --- | --- |
| 严格预付 | 在 Flexprice 钱包服务夹具中交错执行两次余额读取，再依次手工扣款。两笔各需 8 点的请求都读到 10 点并获准，扣款后实际余额为 −6 点。普通扣款的余额不足检查通过。 |
| 钱包补账和扣款去重 | Flexprice 充值完成测试通过，覆盖普通充值、赠送点数、重复完成和部分失败。扣款幂等测试因已知问题跳过。没有端到端证明国内扫码账单已付、钱包暂时不可用时可自动补账。 |
| 国内扫码支付 | 国内支付分支的隔离 PostgreSQL 测试通过，覆盖双渠道切换、支付重试、账单结算和迟到多收款的退款记录。渠道使用夹具。 |
| 退款和预占竞争 | OpenBot 点数包及用量集成测试 22 项通过，包含退款与预占争用、退款状态未知时保持冻结、漏回调恢复和用量重投。Flexprice 钱包尚未通过等价的批次冻结验证。 |

本轮结果支持继续由 OpenBot 执行严格预付。钱包切换仍需验证原子预占和释放、扣款重试去重、扫码充值故障补账，以及普通退款与批次冻结。未使用真实商户或修改生产配置。
