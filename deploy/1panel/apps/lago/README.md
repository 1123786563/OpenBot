## 产品介绍

模型用量与对账。安装参数与依赖见 OpenBot 的 1Panel 部署说明。

部署配置基于[上游 Compose](https://github.com/getlago/lago/blob/v1.57.0/docker-compose.yml)修改。许可证见[上游许可证](LICENSE-upstream)。

## 数据库

安装时在「已有 PostgreSQL 实例」下拉框中选择 1Panel 管理的实例。表单会随机填充库名、用户名和密码，1Panel 在启动 Lago 前自动建库和建用户。1Panel 2.5.1 会给密码添加 6 位随机字符。需要更强密码时，可用 `openssl rand -hex 32` 生成后覆盖表单值。

复用 1Panel 中已登记的数据库时，将随机库名、用户名和密码替换为原凭据。旧版实例更新配置时也使用原凭据。数据库会关联到 Lago 安装实例，卸载前备份并检查面板的数据库删除选项。

使用已安装 pg_partman 的 PostgreSQL 15 或更新版本。1Panel 2.5.1 自动创建的 PostgreSQL 角色带有 `SUPERUSER` 权限，供 Lago 1.57.0 空库迁移使用。迁移完成或安装中止后，将该角色改回普通权限。

## Redis

安装时在「已有 Redis 实例」下拉框中选择 1Panel 管理的 Redis，「Redis 密码」随所选实例自动带入，未设密码时留空。Lago 用它保存缓存、后台任务队列和实时推送。

从自带 Redis 的旧版本升级时，旧 Redis 中的待处理后台任务不会迁移，请在后台任务跑完后再重建。

## 应用密钥

新安装时，可留空 Rails 签名密钥、RSA 私钥和 3 项加密参数。首次启动会生成并保存这些值到 `lago_secrets` 命名卷，迁移、API、Worker 和 Clock 共用。容器重建时沿用该卷。恢复旧数据库时，填入原密钥或使用原密钥卷，并将密钥卷与数据库一同备份。

## 管理员账号

安装表单填写初始组织名称、管理员邮箱和密码。迁移任务在空库上创建组织、管理员和组织的 API 密钥，安装完成后用该邮箱和密码登录界面。OpenBot 用量导出使用的 `LAGO_API_KEY` 在 **Settings → Developers** 中复制。

注册入口已关闭，其他账号由管理员在 **Settings → Members** 中添加。找回密码依赖已配置的邮件发送。

已有实例更新到本版本时，填入当前管理员的邮箱、当前组织名称和任意密码。迁移只补建缺失的记录，不修改已有用户的密码；三项留空时跳过初始化。
